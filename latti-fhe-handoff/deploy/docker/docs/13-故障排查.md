## Nginx 日志文件 Permission denied

典型错误：

```text
open() "/tmp/latti-client-error.log" failed (13: Permission denied)
```

修复统一日志文件权限：

```bash
sudo touch /tmp/latti-client-error.log /tmp/latti-nginx-access.log
sudo chown root:adm /tmp/latti-client-error.log /tmp/latti-nginx-access.log
sudo chmod 664 /tmp/latti-client-error.log /tmp/latti-nginx-access.log
```

如果仍失败，确认不需要保留旧日志后重建：

```bash
sudo rm -f /tmp/latti-client-error.log /tmp/latti-nginx-access.log
sudo install -o root -g adm -m 664 /dev/null /tmp/latti-client-error.log
sudo install -o root -g adm -m 664 /dev/null /tmp/latti-nginx-access.log
```

## Nginx 8995 端口占用

典型错误：

```text
bind() to 0.0.0.0:8995 failed (98: Address already in use)
```

先确认占用者：

```bash
sudo ss -lntp | grep ':8995'
sudo ps -eo pid,ppid,args | grep '[n]ginx'
```

如果已经有项目 Nginx 在运行，不要重复执行 `nginx -c`，改用 reload：

```bash
NGINX_CONF=/home/jiangsy/prod-project/latti-client/nginx-8.62.conf
sudo nginx -t -c "$NGINX_CONF"
sudo nginx -s reload -c "$NGINX_CONF"
```

如果需要停止旧项目 Nginx，只停止对应配置的 master，不要停止系统默认 Nginx：

```bash
NGINX_CONF=/home/jiangsy/prod-project/latti-client/nginx.conf

NGINX_PID="$(
  sudo ps -eo pid,ppid,args |
    awk -v conf="$NGINX_CONF" '$0 ~ /nginx: master process/ && index($0, conf) {print $1; exit}'
)"

echo "$NGINX_PID"
sudo kill -QUIT "$NGINX_PID"
```

系统默认 Nginx 通常类似：

```text
nginx: master process /usr/sbin/nginx -g daemon on; master_process on;
```

不要误停该进程。

## Nginx pid 文件丢失或为空

典型错误：

```text
open() "/tmp/latti-nginx.pid" failed (2: No such file or directory)
invalid PID number "" in "/tmp/latti-nginx.pid"
```

先确认项目 Nginx 是否仍在监听 `8995`：

```bash
sudo ss -lntp | grep ':8995'
sudo ps -eo pid,ppid,args | grep '[n]ginx'
```

如果项目 Nginx 正在运行，把对应 master pid 写回 pid 文件：

```bash
NGINX_CONF=/home/jiangsy/prod-project/latti-client/nginx-8.62.conf

NGINX_PID="$(
  sudo ps -eo pid,ppid,args |
    awk -v conf="$NGINX_CONF" '$0 ~ /nginx: master process/ && index($0, conf) {print $1; exit}'
)"

echo "$NGINX_PID" | sudo tee /tmp/latti-nginx.pid >/dev/null
sudo chown root:root /tmp/latti-nginx.pid
sudo chmod 644 /tmp/latti-nginx.pid
sudo cat /tmp/latti-nginx.pid
```

再 reload：

```bash
sudo nginx -t -c "$NGINX_CONF"
sudo nginx -s reload -c "$NGINX_CONF"
```

如果 `8995` 没有监听，说明项目 Nginx 未运行，按 [06-Nginx配置与启动](06-Nginx配置与启动.md) 首次启动。

## Redis 异常

```bash
./scripts/run-node.sh ps

```

确认 `LOCAL_REDIS_PASSWORD`、端口和数据目录配置一致。

## GPU unavailable

宿主机检查：

```bash
nvidia-smi
```

容器检查：

```bash
docker exec fhe-worker-a130-58996 nvidia-smi
```

如果宿主机正常但容器异常，重建 Worker：

```bash
./scripts/run-node.sh up -d --force-recreate fhe-worker
```

## 端口占用

```bash
ss -lntp | grep -E ':8995|:58996|:58998'
```

确认没有旧服务占用端口。

## orphan container 提示

如果看到历史容器，例如 `fhe-gateway`、`fhe-route-redis`，说明旧架构容器仍存在。确认不再使用后可手动删除：

```bash
docker rm -f fhe-gateway fhe-route-redis
```

## health degraded

查看健康接口和 API 日志：

```bash
curl -i http://127.0.0.1:58996/api/v1/health
./scripts/run-node.sh logs -f fhe-api
```

常见原因：GPU 不可见、Redis 异常。
