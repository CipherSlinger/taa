# 12-多服务器节点接入

本文用于把新的 GPU 服务器作为计算 Node 加入入口 Nginx 一致性哈希。

## 新节点准备

1. 拉取代码，见 [01-拉取代码与安装依赖](01-拉取代码与安装依赖.md)。
2. 配置 env，见 [02-环境变量配置](02-环境变量配置.md)。
3. 准备 runtime 和模型目录，见 [03-运行时与模型目录准备](03-运行时与模型目录准备.md)。
4. 导入镜像或本机构建。

## 新节点 env 要点

每个 Node 必须有唯一身份：

```env
NODE_ID_OVERRIDE=<node-id>
NODE_IP_OVERRIDE=<node-ip>
API_HOST_PORT=58996
LOCAL_REDIS_BIND_HOST=127.0.0.1
LOCAL_REDIS_HOST_PORT=58998
```

## 启动新 Node

```bash
cd /path/to/latti-client/deploy/docker

./scripts/run-node.sh up -d
./scripts/run-node.sh ps
curl -i http://127.0.0.1:58996/api/v1/health
```

## 入口 Nginx 加节点

在入口服务器 `nginx.conf` 的 `upstream latti_nodes_by_user` 中加入：

```nginx
server <node-ip>:58996 max_fails=0;
```

检查并重载：

```bash
sudo nginx -t -c /home/wuwm/prod-project/latti-client/nginx.conf
sudo nginx -s reload -c /home/wuwm/prod-project/latti-client/nginx.conf
```

## 验证路由

访问业务接口：

```bash
curl -fsS -i http://<nginx-ip>:8995/api/v1/models \
  -H "X-User-Id: <user-id>"
```

响应头应包含：

```text
X-Nginx-Route-Key
X-Upstream-Addr
```

## 注意事项

1. 新增或删除 upstream 节点会导致部分用户哈希漂移。
2. 用户的 eval context、任务输入和结果保存在原 Node 本地，不会自动迁移。
3. 生产环境扩缩节点前需要确认用户数据归属和迁移策略。
