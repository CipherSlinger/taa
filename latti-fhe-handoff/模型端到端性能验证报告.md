# 模型端到端性能验证报告（cifar-10 / 平台化 FHE）

> 本报告对**交付包内实际使用的镜像 + 运行时**做端到端验证，记录关键阶段的
> 运行时间、CPU 内存与 GPU 显存占用。测试日期 2026-10-15。

---

## 1. 结论摘要

| 指标 | 数值 |
|---|---|
| 单任务（冷启动，10 个 case）端到端 | **108.9 s**，completed 10/10 |
| 单任务（同用户第 2 次，常驻复用） | **78.6 s**，completed 10/10 |
| 单 case GPU 推理 | **7.2 – 7.8 s**（20 case 平均 7.51 s） |
| 用户公钥解析（`import_eval_context`，3.18 GiB） | **28.4 s**，**0 显存**，进程 RSS ≈ 14.5 GiB |
| `load_model`（冷首次） | **1.68 s** → 显存 43.9 GiB |
| `load_model`（常驻复用） | **1.05 s** |
| `release_device()` | **≈ 0.12 s** → 显存回落到 **0.5 GiB** |
| worker 进程 RSS 峰值 | **29.2 GiB**（解析结果常驻 + 单 case 计算峰值） |
| GPU 显存峰值 | **43,875 MiB / 49,140 MiB**（池预占，非真实用量） |

**要点**：解析一次公钥后常驻，任务之间只做「重新上卡 → 推理 → 释放」，
空闲时整个容器只占 **≈0.5 GiB** 显存；`import_eval_context` 是纯 host 操作，不占卡。

## 3. 端到端链路与阶段耗时

```
客户端(keygen/加密) ─► eval_context.bin ─► 服务端 import(0 显存) ─► load_model(上卡)
        └──────────────────────────► input.zip ──► evaluate(每 case) ──► output.zip ──► 客户端解密
```

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 客户端 keygen（浏览器 WASM，单线程） | **466 s** | 产出 `eval_context.bin` 3,329,929,205 B + `full_context.bin` 25,494,056 B |
| 客户端 keygen（原生 liblattisense，本机对照） | **108.5 s** | 峰值 RSS ≈ 1.21 GiB；写 3.10 GiB |
| 客户端加密（`encrypt`） | **1.4 s** | 输入密文 3,653,705 B / case |
| 服务端 import_eval_context | **28.4 s** | 3.18 GiB；**显存 0**；进程 RSS +≈14.5 GiB |
| 服务端 load_model（冷） | **1.68 s** | 触发显存池首次分配 → 43.9 GiB |
| 服务端 evaluate（每 case） | **7.2 – 7.8 s** | 35,580 steps；20 次采样平均 7.51 s |
| 服务端 release_device | **≈0.12 s** | 显存 43.9 GiB → 0.5 GiB |
| 客户端解密（`decrypt`） | **0.19 s** | 与明文基准 `max|Δ| ≈ 5e-4`（阈值 0.1） |

## 4. 资源占用

### 4.1 GPU 显存（nvidia-smi 采样，1 s 间隔）

| 时刻 | 显存 |
|---|---|
| 空闲 | 1 MiB |
| `import_eval_context` 期间 | 1 MiB（不占卡） |
| `load_model` 之后 | 43,873 MiB |
| 推理期间峰值 | 43,875 MiB |
| `release_device()` 之后 | **515 MiB** |

> 43.9 GiB 是 HEonGPU 内存池在首次上卡时按 `0.9 × 空闲显存` 的**预留**
> （`defines.h` 的 `initial_device_memorypool_size`），单用户上下文的真实设备
> 需求约 15.5 GiB。多容器共卡时用 `HEONGPU_DEVICE_POOL_MAX_BYTES`
> 给每个容器设预算即可（例如 16 GiB，48 GB 卡可并放 3 个容器）。

### 4.2 进程内存（worker RSS）

| 时刻 | RSS |
|---|---|
| 启动空闲 | 0.05 GiB |
| import_eval_context 之后（解析结果常驻） | ≈ 14.5 GiB |
| 单 case 推理峰值 | 28 – 29 GiB |
| release_device 之后 | ≈ 26 GiB（glibc 不把解析结果还给 OS） |

## 5. 常驻复用对比（同用户、同模型连续两任务）

| | 任务 A（冷启动） | 任务 B（常驻复用） |
|---|---|---|
| 公钥 import | 28.4 s | **0 s（复用常驻解析结果）** |
| load_model | 1.68 s | 1.05 s |
| 10 个 case | ≈75 s | ≈75 s |
| 端到端 | **108.9 s** | **78.6 s** |
| 任务结束显存 | 515 MiB | 517 MiB |
| 输出 | completed 10/10 | completed 10/10，逐 case 结果与 A 一致 |

**结论**：解析一次 + 常驻后，每个后续任务省掉 28.4 s 的 import；
任务之间显存从 43.9 GiB 回落到 0.5 GiB，卡可被其它容器的任务使用。
