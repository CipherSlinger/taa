# 模型端到端性能验证报告（resnet20 / CIFAR-10）

> 对交付镜像 + 运行时做的端到端验证：关键阶段耗时、进程内存、GPU 显存。

---

## 1. 结论摘要

| 指标 | 数值 |
|---|---|
| 单任务（冷启动，10 个 case） | **108.9 s**，completed 10/10 |
| 单任务（同用户第 2 次，常驻复用） | **78.6 s**，completed 10/10 |
| 单 case GPU 推理 | **7.2 – 7.8 s**（20 次采样平均 7.51 s） |
| 用户公钥解析（`import_eval_context`，3.18 GiB） | **28.4 s**，**0 显存**，RSS ≈ 14.5 GiB |
| `load_model`（冷 / 复用） | **1.68 s** / **1.05 s** |
| `release_device()` | **≈ 0.12 s** → 显存回落到 **0.5 GiB** |
| worker RSS 峰值 | **29.2 GiB** |
| GPU 显存峰值（交付默认 20 GiB 池） | **20,993 MiB** |

**要点**：公钥解析一次后常驻内存，之后每个任务只做「上卡 → 推理 → 释放」，
空闲时容器只占 ≈0.5 GiB 显存；`import_eval_context` 是纯 host 操作，完全不占卡。

## 3. 阶段耗时

```
客户端(keygen/加密) ─► eval_context.bin ─► 服务端 import(0 显存) ─► load_model(上卡)
        └──────────────────────────► input.zip ──► evaluate(每 case) ──► output.zip ──► 客户端解密
```

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 客户端 keygen（浏览器 WASM，单线程） | **466 s** | 产出 `eval_context.bin` 3,329,929,205 B + `full_context.bin` 25,494,056 B |
| 客户端 keygen（原生 liblattisense 对照） | **108.5 s** | 峰值 RSS ≈ 1.21 GiB |
| 客户端加密（`encrypt`） | **1.4 s** | 密文 3,653,705 B / case |
| 服务端 `import_eval_context` | **28.4 s** | 3.18 GiB；**显存 0**；RSS +≈14.5 GiB |
| 服务端 `load_model`（冷） | **1.68 s** | 触发显存池首次分配 |
| 服务端 `evaluate`（每 case） | **7.2 – 7.8 s** | 35,580 steps |
| 服务端 `release_device` | **≈ 0.12 s** | 整池归还 |
| 客户端解密（`decrypt`） | **0.19 s** | 与明文基准 `max|Δ| ≈ 5e-4`（阈值 0.1） |

## 4. 资源占用

### 4.1 GPU 显存（nvidia-smi 采样，1 s 间隔）

| 时刻 | 显存（交付默认 20 GiB 池） |
|---|---|
| 空闲 | 1 MiB |
| `import_eval_context` 期间 | 1 MiB（不占卡） |
| 首次上卡后 | 20,993 MiB |
| `release_device()` 之后 | **513 MiB** |

- 显存池默认 `INITIAL=20 GiB`、`MAX` 不设（上限 = 启动时空闲显存的 95%，随卡自适应），
  按需增长；resnet20（CIFAR-10）单用户的真实设备需求约 **15.2–15.6 GiB**。
- 早期版本沿用「首次上卡按空闲显存 90% 预占」（本机 43.9 GiB），交付版已改掉；
  同一单 case 任务现在峰值 20,993 MiB、耗时 79.6 s。
- 预算设得过小（实测 12 GiB）时任务会**明确失败**并回传
  `Maximum pool size exceeded …`，而不是卡死。

### 4.2 进程内存（worker RSS）

| 时刻 | RSS |
|---|---|
| 启动空闲 | 0.05 GiB |
| `import_eval_context` 之后（解析结果常驻） | ≈ 14.5 GiB |
| 单 case 推理峰值 | 28 – 29 GiB |
| `release_device` 之后 | ≈ 26 GiB（glibc 不把解析结果还给 OS） |

## 5. 常驻复用对比（同用户、同模型连续两任务）

| | 任务 A（冷启动） | 任务 B（常驻复用） |
|---|---|---|
| 公钥 import | 28.4 s | **0 s（复用常驻解析结果）** |
| load_model | 1.68 s | 1.05 s |
| 10 个 case | ≈ 75 s | ≈ 75 s |
| 端到端 | **108.9 s** | **78.6 s** |
| 任务结束显存 | 515 MiB | 517 MiB |
| 输出 | completed 10/10 | completed 10/10，逐 case 与 A 一致 |

**结论**：解析一次并常驻后，每个后续任务省掉 28.4 s；任务之间显存回落到 0.5 GiB，
卡可被其它容器使用。

---

## 6. 容量规划提示

- **内存**：每个常驻用户 ≈ 14.5 GiB（解析结果），单 case 计算峰值再叠加到 ≈ 29 GiB。
  `RESIDENT_MAX_SERVERS`（默认 4）决定单容器最多常驻几个用户的解析结果。
- **显存**：单个推理任务峰值 ≈ 20 GiB（默认预算），空闲 ≈ 0.5 GiB。
- **一个用户固定一个节点**能最大化复用（省掉每次 28.4 s 的 import）；跨节点会把
  公钥重新解析一遍并多吃 14.5 GiB。
