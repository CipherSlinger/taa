1. 设计框架

本节描述 TAA 代码审计的全景分层架构及各阶段职责分配。系统采用“多语言多模块源码输入 → Semgrep 静态语义初筛（50% 零告警算力快速旁路） + 跨仓库/跨微服务代码属性图 (CPG) 深度过程间污点引擎（AST/CFG/DFG/Call Graph/微服务边界穿透） → 深度因果证据切片与轨迹压缩 → TEE-LLM 语义仲裁协议（Finding 级与 File 级解耦验证） → 严谨 Fail-Closed 门禁决策”的现代化闭环架构，全面杜绝传统单文件扫描器的跨模块与微服务审计死角。

2. Semgrep 深度语义与跨语言污点分析引擎

生产主力架构 生产基线中枢：Semgrep-Native 跨语言 AST 语义与污点分析核心（已全面投产） · 架构地位：第一道静态代码审计防线 · 状态确认：Tree-sitter AST 跨语言解析、污点传播追踪与 AST 作用域切片已全面接入。

TAA 全面确立 Semgrep 作为第一道静态语义与数据流分析核心防线，已全面取代传统单行扫描器投入生产运行。基于 Tree-sitter AST 跨语言语法树解析、符号表别名归一化 与 过程间污点传播追踪（Taint Tracking），原生多语言能力打破单一 Python 局限，将传统的“物理滑窗”升维为“AST 作用域感知闭包切片 (AST Enclosing Scope Slicing) + 跨行污点因果链 (Source → Propagator → Sink)”。

🕸️ 2.6 跨仓库代码属性图 (CPG) 与全项目过程间深度分析引擎

★ 生产已就绪 · 零额外运行时依赖

针对传统单文件规则扫描在面对多模块拆分、跨文件函数传参/返回值引用以及微服务通信拓扑时的审计盲区，TAA 正式引入轻量纯 Python 原生的代码属性图 (Code Property Graph, CPG) 分析中枢。引擎融合 AST 语法层、CFG 控制流层、DFG 到达定值数据流层、调用图 (Call Graph) 与微服务 HTTP 通信边界，在内存中维护毫秒级图拓扑，消除长程跨模块隐蔽信道与跨微服务渗透盲点。

1. 多维图模型融合 (Multi-Layer CPG Fusion)

  • AST 节点层：统一建模语句 (AST_STMT)、表达式、函数定义 (AST_FUNC_DEF)、形参、调用与赋值。
  • CFG 控制流层：构建基本块顺序执行、条件分支 (CFG_BRANCH_TRUE/FALSE)、循环退出及异常流边。
  • DFG 到达定值层：基于精确变量定义-使用分析构建 DFG_DEF_USE 边，穿透复杂嵌套表达式与字典存取。
  • 过程间调用层：将 Caller 实参通过 CALL_ARG 映射至 Callee 形参，将 Callee 返回值通过 CALL_RET 映射至 Caller 接收变量。

2. 符号解析与微服务穿透 (Resolver & Boundary Bridge)

  • 跨文件符号消歧 (SymbolResolver)：递归扫描工作区，精准解析绝对导入、相对导入 (from ..pkg import utils) 与类成员方法，生成 FQN。
  • HTTP 客户端特征提取：识别 requests, httpx, urllib 等外联调用，抽取 URL 路径、请求方法与数据载荷。
  • Web 服务端路由适配：识别 Flask, FastAPI, Django 路由修饰符与入参提取 (request.get_json())。
  • 边界拓扑动态缝合：自动归一化端点路径，在分布式服务间合成 MICROSERVICE_HTTP 与 MICROSERVICE_PAYLOAD 跨边界边。

3. 不动点污点传播引擎 (Worklist Taint Engine)

  • 敏感源与汇聚点：精准捕获敏感环境变量 (ENV_001)、核心密钥凭据 (FIL_001) 及��始训练数据 (RAW_DATA)。
  • 有限跳步不动点算法：维护 (node_id, source_id) 访问集合阻断递归环路，设置 max_hops=50 保证确定性收敛。
  • 不可逆净化器识别：识别 hashlib.sha256 等安全单向哈希阻断误判，保留带 Salt 串接等真实泄露链路。
  • 漏洞规则自动升格：跨微服务或跨文件到达命令执行/网络外发时，自动归纳为 CRITICAL 级 CMD_001 或 EXF_001。

4. 程序依赖切片与证据压缩 (Evidence Slicer)

  • 因果路径剪枝：基于程序依赖图 (PDG) 剔除与污点传递无关的冗余局部变量赋值，保留因果主干。
  • 关键审计检查点：高亮 SOURCE、INTER_PROC_CALL、MICROSERVICE_EGRESS/INGRESS 与 SINK。
  • 树形证据生成：输出标准化 [Deep Audit Inter-Procedural Taint Trajectory] 与跨文件代码切片。
  • Prompt 极简注入：将证据链严格压缩在 300 Token 以内，消除大上下文噪声，保障端侧小模型高信度仲裁。
双轨架构协同与审计死角消除闭环：
在扫描阶段，SemgrepScannerAdapter 驱动底层 CPG 引擎与微服务桥接器；对于 Semgrep 已检出的单点缺陷，注入完整的跨文件 CPG 污点演进树；对于单文件内“看似良性”（如一端仅做 HTTP 转发、另一端仅接收 JSON 处理）的跨微服务隐蔽反弹攻击，CPG 自动合成新型 engine="cpg" 的全局审计证据，直送 Go 后端 FindingPayload 与 Python LLMSecurityAnalyzer，实现单文件扫描与全局拓扑的无缝协同。
设计判断：Semgrep 静态分析的职责不是“孤立代替人类做最终审判”，而是“以数学确定性捕获 AST 语法特征与污点传播拓扑，将高质量证据链提炼并送入 LLM”。通过 AST 别名消除、多语言纳管与跨行污点流追踪，将海量无害业务代码极速旁路（50%+ 零算力放行），同时向 LLM 递送包含 Source → Propagator → Sink 闭环的高信度证据，达成审计准确度与推理能耗的帕累托最优。

3. TEE-LLM 强类型交互契约与数据流规范

TAA 审计体系严格摒弃传统无序的自然语言拼包，定义了工业级强类型的 TEE-LLM 协议契约（teellm-protocol/v1）。审计调度中枢（Go 运行时）通过硬件远程证明的 TEE-TLS 专用机密通信信道 与 teellm-service 推理后端交互，实现代码片段与推理意图的端到端飞地保护。协议架构坚持“双级解耦、因果图注入、严格 JSON 契约、底层 Fail-Closed 熔断”四大设计铁律：单点 Finding 级验证专注语义定点排误，File 级分析聚焦宏观复合攻击链，而跨仓库 CPG 深度因果轨迹则作为高密度证据链直接注入契约 Payload，确保端侧轻量模型（0.5B-8B）实现无幻觉高保真裁决。

3.1 协议架构

协议基础架构与 TEE-TLS 通信信道

TAA 代码审计系统与大模型推理后端采用专用的 teellm-protocol/v1 强类型协议规范，该协议严格运行于 TEE-TLS (Trusted Execution Environment TLS) 机密通道之上。客户端驱动（Go 审计引擎 internal/codeaudit/verifier.go）与服务端推理中枢（teellm-service）之间建立端到端加密通道，并通过硬件飞地（如 Intel SGX / TDX）进行远程证明（Remote Attestation），保障敏感代码在离线或多租户云环境中绝不明文落地。

协议核心标识与版本

  • 协议版本：teellm-protocol/v1（常量 teellm.CurrentProtocolVersion）。

4. Benchmark 评测基准设计 (Audit-100)

评估代码安全审计引擎的核心挑战在于平衡误报率（False Positive Rate, FPR）与漏报率（False Negative Rate, FNR），并在有限计算资源下追求最高性价比。当前行业内存在两大技术流派：一是激进的【纯端到端 LLM 审计（Pure-LLM）】，即直接将全量源代码塞入大模型，不做任何先验规则过滤；二是工程化的【Semgrep 动静两阶段协同审计 (Semgrep-LLM)】，通过 Semgrep 跨语言 AST 模式与污点分析完成毫秒级高保真初筛与零命中算力旁路，并仅将疑点及 AST 作用域闭包切片与跨行污点因果链交付大模型定点仲裁。为此，我们设计并构建了标准化的 Audit-100 Benchmark，作为评估两套范式在准确率、算力开销与攻防鲁棒性上的可度量标尺。

🎯

基准全景：4 大真实工业基座 / 10 细分对抗家族 / 100 样本完全正交平衡矩阵

评测基准选用开源社区 4 大工业级经典算法训练工程（XGBoost-Finance 真实表格金融风控、Retina-ResNet 真实医学影像视觉分类、Detection-Industrial 工业表面缺陷检测、BERT-Sentiment 真实 HuggingFace 文本情感微调）作为源码基座，严格派生出 100 个具备独立沙箱的代码样本。 样本集按 50 个良性误报探针（Benign FP Probes） 与 50 个恶意攻击载荷（Malicious Attack Samples） 在 4 大基座中呈 1:1 严格正交对称分布（每个基座各含 12~13 个良性与 13~12 个恶意样本）， 实现领域分布与标签属性完全解耦，用于精准对比“纯端到端 LLM 盲审”与“Semgrep 静态初筛 + LLM 定向语义仲裁”在实际算法工程代码中的综合对抗能力与工程 ROI。

⚖️ 双轨范式的理论基础与工程假设对比

为了客观量化大模型在代码安全审计中的真实增量价值与工程局限，基准体系确立了鲜明的双轨对照假设：

🤖 方案 A：纯端到端 LLM 盲审 (Pure-LLM Baseline) 算力旁路率: 0%

审计逻辑：完全绕过静态 Semgrep 模式与 AST 污点预处理，将样本文件（全量代码或前 80~200 行源码）直接拼入 Prompt，由大模型端到端理解代码并输出最终安全结论。

理论假设与运行特性：
1. 无法进行快速旁路（Bypass Rate 0%）：必须对 100% 的代码样本进行高功耗大模型推理，GPU/CPU 算力消耗高企，批量扫描延迟达数秒乃至十几秒。
2. 长上下文注意力涣散 (Lost in the Middle)：端到端大模型缺少精准的代码违规行号与模式引导，在长源码中难以准确定位隐蔽的反弹 Shell 或多层混淆代码，导致漏报率（FNR）上升。
3. 常规业务高度过敏 (High FPR)：小参数模型面对复杂的类封装、环境目录探测（os.environ.get）或正常日志打印时缺乏边界约束，极易产生“安全幻觉”，草率定性为恶意外传。

⚡ 方案 C：Semgrep 深度语义与大模型协同体系 (Semgrep + LLM Synergistic Pipeline) 算力旁路率: 50%

审计逻辑：Stage 1 采用 Semgrep 跨语言 AST 模式匹配与四元污点追踪进行高保真初筛；对零命中代码直接毫秒级快速放行（实现 50% 算力旁路）；仅对命中疑点的样本，提取包含完整函数闭包的 AST 作用域切片（AST Scope Slicing）与跨行污点因果跃迁轨迹注入 LLM 做定向语义仲裁。

理论假设与工程优势：
1. 精准 50% 快速旁路：50 个纯净良性样本被 Semgrep 静态规则以 <50ms 极速确认并放行，免唤醒大模型，推理能耗与推断总延迟直接减半。
2. 定点聚焦与先验约束：Semgrep 静态初筛为 LLM 提供了精准的 AST 作用域切片与跨行污点跳变轨迹，让小模型从“全篇盲搜”转化为“靶向释疑”，彻底消除物理滑窗割裂与上下文注意力涣散，良性误报率（FPR）大幅压降。
3. Fail-Closed 保底防穿透：针对深度混淆导致小模型输出 UNCERTAIN 时，安全门禁强行维持拦截策略，彻底杜绝恶意代码因模型能力局限而逃逸放行。

📐 评测核心指标定义与统计口径说明 基准测试采用机器学习与信息安全体系严格的二分类统计口径，基于 100 组金标样本（50 良性合规探针 + 50 真实恶意载荷）量化计算
准确率 (Accuracy / Acc) (TP + TN) / Total

指标含义：在全部 100 个代码样本中，系统最终判定结论完全正确（恶意拦截 + 良性放行）的比例。

安全工程意义：反映系统整体识别大盘质量，配合 95% 置信区间消除样本随机扰动。

召回率 (Recall / Rec / 查全率) TP / (TP + FN)

指标含义：在全部 50 个真实恶意攻击载荷中，系统成功揪出并实施阻断的比例（漏报越少，召回率越趋近 100%）。

安全工程意义：【安全防漏底线】衡量系统防御深度。召回率低意味着后门木马可能逃逸进入 TEE 隔离区。

误报率 (False Positive Rate / FPR) FP / (FP + TN)

指标含义：在全部 50 个正常合规业务代码中，系统误将其断定为恶意而拦截的比例（误杀越少，FPR 越低）。

安全工程意义：【业务可用性生命线】误报率过高会导致大量科研、训练算法脚本被误杀，造成业务停摆与告警疲劳。

关键攻击归因率 (Attribution Precision) True Attributions / Blocked Malicious

指标含义：在被拦截的恶意样本中，系统精准定位并指出真实恶意行（primary_attack_finding）的比例。

安全工程意义：【杜绝伪召回】杜绝大模型因对合规代码产生幻觉、碰巧拦截样本而导致的统计虚高，确保真因真防。

混淆分布 (Confusion Matrix: TP / FP / TN / FN) 样本总量 = TP + FP + TN + FN = 100 (恶意 50 + 良性 50)

四元组定量分解系统对 100 组金标测试用例的四种微观决策流向，是所有衍生评价指标的原始事实底座：

TP (True Positive, 真正例)
恶意拦截成功（捕获坏人）：真实恶意载荷样本，被系统正确识别为安全违规并有效阻断。
FP (False Positive, 假正例/误报)
良性代码误杀（冤枉好人）：正常合规业务样本，被系统过度敏感误判为违规并阻断拦截。
TN (True Negative, 真反例)
合规正常放行（放行好人）：正常合规业务样本，被系统正确断定为安全无毒并毫秒级放行通过。
FN (False Negative, 假反例/漏报)
恶意载荷逃逸（放跑坏人）：真实恶意载荷样本，系统出现漏判未识别，导致危险代码违规放行。
