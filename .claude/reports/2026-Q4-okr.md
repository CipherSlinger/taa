- **KR3** 15 份历史 spec/plan 迁入 `.claude/`，`docs/superpowers/` 清空，README 中 2 个失效链接修复、仓库结构与实际目录 100% 对齐。

**验收**：路线图 1.2 六项通用门禁全绿；隔离环境全量测试结果与基线一致。

## O4 审计链路先测量后优化，无等价证明不改

- **KR1** 5 个 benchmark（报告生成、校验、摘录渲染、scope 上下文、二进制证据采集）落地，`-benchmem` 三次取中位数且数字稳定。
- **KR2** 生产路径分段测量出基线：静态扫描、二进制通道、LLM finding 仲裁、文件级分析、报告组装的耗时与峰值内存，附 pprof 热点。
- **KR3** 固定输入下 `audit_report.json` 除易变字段逐字节一致；如无安全收益，明确关闭本批并交付测量结论。
- **KR4** 已证实的非确定性（同输入不同判定）与无效配置项清单文档化，且不把「temperature 0 已配置」当作已修复。

**验收**：不改提示词、并发度、超时与降级语义；新增代码仅测试 / 基准。

## O5 补齐真实环境暴露的四个缺口（行为变更，独立 spec）

- **KR1 存活判定**：以进展为证据，把总时长 deadline 换成 idle deadline。固定负载下「慢但持续输出」的请求 0 误杀，真失联可及时判定；`/healthz` 能区分模型未驻留 / 无响应 / 进程已退出三态。
- **KR2 macOS 包兼容**：`__MACOSX/`、`._*`、`.DS_Store` 在解包阶段过滤，按包内真实源码根计算扫描路径。实测 macOS 产物跑通导入→审计，扫描目标集合无元数据文件，Linux/Windows 包回归不变。
- **KR3 失败原因回传**：结构化输出失败阶段、退出码与信号、stdout/stderr 尾部（有界）、日志路径。缺文件 / 字段非法 / OOM / 非 0 退出四类典型失败均能给出可直接修正的原因，且无宿主路径、密钥或环境变量泄漏。
- **KR4 接口鉴权**：控制面接口具备可验证调用方身份（候选 mTLS / 请求签名 + 防重放 / 短期 token，由 spec 定）。密钥不落镜像与仓库，401/403 不泄露内部细节，`/healthz` 免鉴权且只返回存活；按观察模式 → 灰度 → 默认强制迁移，旧客户端有明确窗口。

**验收**：每项独立 spec，实施前留现状证据（超时误判率、mac zip 失败复现、失败原因缺失样例）；成功路径与现有测试保持通过。
