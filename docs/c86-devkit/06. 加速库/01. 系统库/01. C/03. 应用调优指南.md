# 海光平台动态库使用指南

## 1. 海光平台与动态库对应关系

不同海光平台需使用对应的动态库文件，核心库文件存在软链接关联，具体对应关系如下：

| 海光平台 | 推荐使用的软链接库 | 对应的实际库文件     |
|----------|--------------------|----------------------|
| C86-3G | lib3c.so           | libh3c.so.2.0.0      |
| C86-4G | libh4c.so           | libh4c.so.2.0.0       |
| C86-4G/H | libh4c\_avx512.so           | libh4c\_avx512.so.2.0.0       |

> 注：libh4c\_avx512.so 是 libh4c\_avx512.so.2.0.0 的软链接，libh4c.so 是 libh4c.so.2.0.0 的软链接，lib3c.so 是 libh3c.so.2.0.0 的软链接。

## 2. 动态库使用方法

### 方法 1：编译时指定动态库路径链接

编译阶段直接指定动态库路径和库文件，确保程序编译时关联目标库。

#### 命令格式

```bash
# C86-3G平台
gcc -o 输出程序名 -L$HC_LIB64_PATH -llibh3c.so 源文件.c

# C86-4G平台
gcc -o 输出程序名 -L$HC_LIB64_PATH -llibh4c.so 源文件.c

# C86-4G/H平台
gcc -o 输出程序名 -L$HC_LIB64_PATH -llibh4c_avx512.so 源文件.c
```

#### 参数说明

- `-o 输出程序名`：指定编译后的可执行程序名称；
- `-L$HC_LIB64_PATH`：指定动态库所在路径（`$HC_LIB64_PATH` 替换为实际路径，如 `/opt/hygon/lib64`）；
- `-llibh3c.so/-llibh4c.so/-llibh4c_avx512.so`：指定要链接的动态库文件。

### 方法 2：运行时通过环境变量强制加载

通过 `LD_PRELOAD` 环境变量，强制程序运行时优先加载指定动态库，无需重新编译程序。

#### 操作步骤

1. 设置环境变量（当前 Shell 会话有效）, 请LD\_PRELOAD 设置为实际的安装libhc库路径：

```bash
# C86-3G平台
export LD_PRELOAD=/opt/hygon/lib64/libh3c.so

# C86-4G平台
export LD_PRELOAD=/opt/hygon/lib64/libh4c.so

# C86-4G/H平台
export LD_PRELOAD=/opt/hygon/lib64/libh4c_avx512.so
```

2. 在当前 Shell 环境启动业务应用 / 测试程序：

```bash
# 启动目标程序
./目标程序名
```

## 3. 验证动态库是否被调用

设置 / 编译完成后，通过以下命令验证动态库是否成功加载：

### 方式 1：lsof 命令

C86-3G平台查看程序进程加载的库文件 (若为其它平台，替换libh3c.so为其对应名称) ：

```bash
lsof -p 程序进程ID | grep 库文件名
# 示例：lsof -p 12345 | grep libh3c.so
```

### 方式 2：pmap 命令

查看进程的内存映射，确认库文件路径：

```bash
pmap 程序进程ID | grep 库文件名
# 示例：pmap 12345 | grep libh
```

> 验证结果：若命令输出中显示目标库文件的路径（如 `/opt/hygon/lib64/libhxx.so`），则说明库已成功被调用。
