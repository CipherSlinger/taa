# htcmalloc 调优指南

## 1 使用方式

htcmalloc 支持两种集成方式，可根据业务部署场景选择：

### 1.1 编译时链接动态库

编译阶段直接指定动态库路径并链接 htcmalloc，生成的可执行文件会默认依赖该库运行。

```bash
# 编译命令
gcc -o 可执行文件名称 -L${HTCMALLOC_LIB64_PATH} -lhtcmalloc 源码文件.c
```

**说明**：`${HTCMALLOC_LIB64_PATH}` 需替换为 htcmalloc 动态库实际存放的 64 位路径，可设置为 `/opt/hygon/lib64/libhtcmalloc.so`。

### 1.2 运行时预加载动态库

通过设置环境变量 `LD_PRELOAD`，在执行程序前提前加载 htcmalloc，无需重新编译源码。

```bash
# 临时设置环境变量（当前终端有效）
export LD_PRELOAD=/opt/hygon/lib64/libhtcmalloc.so
# 执行目标程序
./目标程序名称
```

**说明**：`/path/libhtcmalloc.so` 需替换为 htcmalloc 动态库的绝对路径。

### 1.3 验证库文件是否被调用

通过以下命令确认内存库已成功加载：

```bash
# 方式1：lsof查看进程加载的库文件（替换为实际进程ID）
lsof -p 程序进程ID | grep libhtcmalloc.so

# 方式2：pmap查看进程内存映射（替换为实际进程ID）
pmap 程序进程ID | grep libhtcmalloc.so
```

## 2 环境要求

### 2.1 操作系统内核

- 最低版本：Linux Kernel ≥ 4.19
- 核心原因：需支持 rseq（Restartable Sequences，可重启序列）技术，该技术用于提升多核系统中并发操作的性能。

### 2.2 基础库版本

| 基础库    | 最低版本要求 | 补充说明                     |
|-----------|--------------|------------------------------|
| Glibc     | ≥ 2.27       | -                            |
| libstdc++ | ≥ 6.0.24     | 随 GCC 7.3.0 及以上版本发布 |

### 2.3 特殊配置（Glibc 2.35+）

Glibc 2.35 及更高版本内置了 rseq 机制（主要用于提升 `sched_getcpu()` 函数的执行速度，该函数用于获取当前进程运行的 CPU 编号），可能与 htcmalloc 产生冲突，需在运行程序前设置以下环境变量禁用内置 rseq：

```bash
export GLIBC_TUNABLES=glibc.pthread.rseq=0
```

**性能影响**：若业务场景频繁调用 `sched_getcpu()`，禁用该机制可能导致该函数性能下降。

## 3 平台支持

仅支持 Linux/x86\_64 架构平台，暂不支持其他架构（如 ARM）或操作系统。

## 4 版本说明

htcmalloc 基于 tcmalloc 扩展实现，不同版本特性如下：

| 版本号             | 核心特性                                                                 |
|--------------------|--------------------------------------------------------------------------|
| htcmalloc.so.1.0.0 | 基础版本，在 tcmalloc 基础上实现 NUMA aware（NUMA 感知）的通用内存管理能力 |
| htcmalloc.so.1.0.1 | 基于 1.0.0 增强，新增自适应硬件 NODE 节点特性，适配海光（hygon）2/4 路等平台 |
| htcmalloc.so.1.0.2 | 基于 1.0.1 优化，解决内存库兼容性问题，在多类不同平台均有性能优化效果     |

## 5 风险提示

### 5.1 内存消耗风险

htcmalloc 的内存分配和布局策略与系统默认 malloc 不同，可能导致内存消耗量增加；若业务为大内存用量场景（接近物理内存总量），可能触发 OOM（内存溢出）风险。

### 5.2 环境兼容性风险

- 若未满足内核、基础库版本要求，或未配置 Glibc 2.35+ 的特殊参数，可能导致程序运行异常（如崩溃、性能骤降、功能异常等）。
- htcmalloc的内部NUMA内存绑定策略可能和客户程序的numactl、OMP场景的绑定策略冲突，导致不可用、NUAM管理失效等问题，使用时需要注意。

## 6 调优场景

htcmalloc作为一个感知hygon NUMA架构的内存库，保证程序在内存分配/使用/释放的亲和性，减少远端访问时延，主要是针对高并发、大内存、受远端访问时延影响的客户应用程序，其应用程序场景特征如下：

 - 高并发：应用程序需要跨多个 NUMA 节点的 CPU 资源，并发线程数量越多，性能优化效果越显著，不适用于仅运行在1个NUMA节点的程序。
 - 大内存：程序运行时占用大量内存资源，内存使用量越大，内存NUMA亲和性管理带来的性能提升越明显，一般这类程序的物理内存占用需要在1GB以上，避免访存太少导致无法覆盖NUMA内存的元数据管理开销成本。
 - 远端访问：程序存在大量远端内存访问行为（远端占比至少大于5%），远端访问比例越高，通过NUMA内存亲和性优化获得的性能提升越显著。

### 6.1 多线程场景分析

以一个典型的多线程benchmark负载模型为案例，该程序根据整机core数创建高并发的业务线程，每个业务线程在内部随机创建内存块，然后进行读写业务数据，代码参考：

```
rootcy@neptune:~/code/htcmalloc_test$ cat numa_ideal_benchmark.cc
// g++ -O3 numa_ideal_benchmark.cc -lpthread -o numa_ideal_benchmark
#include <iostream>
#include <vector>
#include <thread>
#include <random>

using namespace std;

void thread_function(int id) {
  random_device rd;
  mt19937 gen(rd());
  uniform_int_distribution<int> dist(64, 64 * 1024 * 1024);

  for (int i = 0; i < 50; i++) {
    int size = dist(gen);
    char *ptr = (char *)malloc(size);

    for (int k = 0; k < 10; k++) {
        for (int j = 0; j < size; j += 64) {
            *(char *)(ptr + j) = 0x05;
        }
    }

    free(ptr);
  }
}

int main() {
  vector<thread> threads;
  for (int i = 0; i < 128; i++) {
    threads.push_back(thread(thread_function, i));
  }

  for (auto &thread : threads) {
    thread.join();
  }

  return 0;
}

```
