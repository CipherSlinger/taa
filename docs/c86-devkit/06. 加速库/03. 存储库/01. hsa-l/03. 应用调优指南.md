# 性能测试方式

可以使用ISA-L自带性能测试用例，进行性能测试。

## 完整测试

```bash
make perf
```

执行后，会运行所有性能测试用例，并展示带宽性能。

## EC特定配比、数据长度性能测试

测试用例 `erasure_code_perf.c` 支持使用输入参数控制配比和数据长度：

- \-k 数据块数量
- \-p 校验快数量
- \-e 恢复块数量（decode）
- \-s 数据块长度

例如：

| 测试场景 | 评估项配置 | 正确命令 | 关注指标 |
|---------|-----------|----------|---------|
| EC 编码 (4+2) | 4+2 | `./erasure_code_perf -k 4 -p 2 -s 64M` | 编码吞吐量 |
| EC 编码 (8+3) | 8+3 | `./erasure_code_perf -k 8 -p 3 -s 64M` | 编码吞吐量 |
| EC 解码 (4+2) | 4+2 | `./erasure_code_perf -k 4 -p 2 -s 64M -e 2` | 解码吞吐量 |
| EC 解码 (8+3) | 8+3 | `./erasure_code_perf -k 8 -p 3 -s 64M -e 3` | 解码吞吐量 |

## crc32c 特定数据长度测试

需通过修改测试用例源码进行调整。以数据长度为64KB为例：

```bash
vim crc32_iscsi_perf.c
```

找到文件中 TEST\_LEN 宏定义，修改为：

```c
#define TEST_LEN      64 * 1024  // 测试数据长度设置为64KB
```

```bash
# 重新编译
make perfs
# 运行测试
./crc32_iscsi_perf
```

# 动态库使能方式

## 设置环境变量以加载优化库

- **方式一：通过 `LD_LIBRARY_PATH` 指定库路径**
  
   ```bash
   export LD_LIBRARY_PATH="/usr/lib:$LD_LIBRARY_PATH"
   ```

> 默认库安装路径为 `/usr/lib`。若自定义安装，请替换为实际安装路径。

- **方式二：直接预加载指定的 `libisal.so`（优先级更高）**
  
   ```bash
   export LD_PRELOAD="/usr/lib/libisal.so"
   ```

> 若自定义安装，请将 `/usr/lib/libisal.so` 替换为 `libisal.so` 所在的实际路径。

## 运行您的应用程序

在修改了环境变量后，程序将优先调用新的ISA-L动态库，无需修改源码（前提是使用标准 ISA-L API）。
