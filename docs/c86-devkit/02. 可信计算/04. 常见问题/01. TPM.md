# TPM FAQ

#### Q: BIOS编译时修改默认PCR bank设置后系统不断重启

A: 在BIOS使能默认配置的PCR bank，系统不断重启，当fTPM支持的pcr bank和BIOS不一致时，会调用PCR allocation重新分配PCR，PCR allocation需要保存到flash中，如果fTPM不使能ALLOCATE\_PCR\_AFTER\_SMM\_INIT，pcr allocation时flash还不可写，在SMM\_INIT后再调用PCR Alloction才能成功保存到flash中，再重启时BIOS PCR bank和fTPM PCR bank才能保存一致

#### Q: BIOS使能TPM后系统启动会出现Could not map UEFI TPM log table payload

A: 在5.6.5内核patch中解决此问题efi/x86: Add TPM related EFI tables to unencrypted mapping checks  commit f10e80a19b07b58fc2adad7945f8313b01503bae upstream. 下载grub2.04源码编译，默认使用linux启动命令，而不是linuxefi启动命令，在内核启动时不会初始化eventlog相关内容，这种方式可以绕过此问题

#### Q: 在OS下使用工具升级BIOS，可能会出现系统无法启动

A: 原因：使用工具在OS升级BIOS后会运行reboot命令，这时OS会发送TPM shutdown命令，fTPM会写flash，如果写的数据区的地址不一致，会导致NV一致性校验不通过，导致无法启动。解决：在OS下升级BIOS，要在BIOS中关闭fTPM或者在OS下卸载hygon\_tpm驱动模块。在firmware也做了workaround方案：如果firmware获取的psp data的offset不一致，则处理OS发送的tpm shutdown命令时，不操作flash
