# 海光C86平台 TPM + 国密SM4/SM3可信磁盘加密实施手册（基于 hygon\_luks\_toolkit 工具集）

工具集下载地址：[hygon\_luks\_toolkit](https://gitee.com/anolis/hygon-devkit/tree/master/tpm/hygon_luks_toolkit)
下载后进入“hygon\_luks\_toolkit”目录，参照本文内容执行。

> **本手册定位**：面向海光 C86 平台的运维 / 安全工程师，演示一条端到端可落地的 TPM + 国密
> SM4/SM3 + LUKS2 可信磁盘加密路径。从内核度量、BIOS 引导链到 systemd 自动解封，所有步骤
> 在 C86 主机 + cryptsetup 2.8.6 上实机验证，产出物（`/etc/crypttab`、`/etc/fstab`、
> `systemd` unit、TPM 对象）可直接进入生产评审。
> 
> **配套文档**：
> 
> - \[TPM应用——磁盘加密部署指南\](./02. TPM应用——磁盘加密部署指南.md) — 讲清楚为什么这样设计、每一步的安全含义；
> - [hygon\_luks\_toolkit/README-toolkit.md](https://gitee.com/anolis/hygon-devkit/blob/master/tpm/hygon_luks_toolkit/README-toolkit.md) — 工具集所有子命令的参考手册；

本手册以一条**完整部署路径**为例演示说明：

- 算法：`capi:gbt17964(xts(sm4))-plain64` ← 国内合规首选，内核内置 GB/T 17964 包装
- KDF / 哈希：`argon2id` + `sm3` ← LUKS2 默认 + 国密
- TPM seal scheme：`nv` ← NV index，TPM 自带空间，无需外部 handle 配额
- PCR 策略：`sm3_256:0,2,4,7` ← 覆盖固件 → bootloader → Secure Boot，任何引导链篡改
  阻断开机自动解封
- 目标盘：`/dev/sdb1`
- mapper / 挂载点：默认值

不同算法的命令差异仅体现在 deploy 的 step 2 菜单；其余步骤对算法不敏感，可直接复用。

> 路径虽以 `capi:gbt17964(...)` 为例，改用 `sm4-xts-plain64` 或 `aes-xts-plain64` 时，
> 只需在 step 2 选不同项，后续 9 步命令完全一致。

## 1. 前置准备

### 1.1 安装工具集

工具集附带 `install.sh`，执行该安装脚本将工具部署至 `/usr/local`（默认）后，`hygon_luks_toolkit` 即位于 `$PATH` 中，**在任意目录下均可直接执行 `sudo hygon_luks_toolkit ...`**，无需 `cd` 进入工具目录。
若不执行安装，亦可在工具集根目录下直接调用 `./hygon_luks_toolkit`。
下文以安装方式为例展开说明。

```bash
# 首先获取工具集源码，随后进入工具目录
cd /your/path/to/hygon_luks_toolkit/

# 安装到默认 /usr/local；想装到别处加 --prefix <dir>
sudo ./install.sh

# 验证：任意目录下
hygon_luks_toolkit version
# 期望输出：hygon_luks_toolkit 1.2.0

# 卸载
sudo ./install.sh --uninstall
```

> **bash 补全要"新 shell"才生效**：上面 `install.sh` 会把补全脚本写到 `/usr/local/share/bash-completion/completions/hygon_luks_toolkit`，**加载时机为新建 shell 启动时**。当前 shell 中 `hygon_luks_toolkit <TAB>` 仍不可用，需重启终端或执行 `exec bash` 后生效。
> 
> 如果新 shell 仍然没有补全：
> 
> 1. 检查包是否装了：`dpkg -l | grep bash-completion`（Debian/Ubuntu）或 `rpm -q bash-completion`（RHEL/C86）。没装则 `sudo apt install bash-completion` / `sudo dnf install bash-completion`。
> 2. 确认 `~/.bashrc` 里 `source` 了 `/usr/share/bash-completion/bash_completion`（部分发行版默认将其注释）。

`install.sh` 实际产物：

- `/usr/local/bin/hygon_luks_toolkit` —— **launcher**（系统PATH上命令实际入口点）。内容只有一行 `exec /usr/local/lib/hygon_luks_toolkit/hygon_luks_toolkit "$@"`，其作用是将 `hygon_luks_toolkit ...` 调用转发至真实 dispatcher。
- `/usr/local/lib/hygon_luks_toolkit/hygon_luks_toolkit` —— **真实 dispatcher**（实际执行入口脚本）。包含全局 flag 解析、子命令分发及 `source lib/*.sh`。
- `/usr/local/lib/hygon_luks_toolkit/lib/` —— 模块（common.sh / deploy.sh / manage.sh 等）。
- `/usr/local/share/bash-completion/completions/hygon_luks_toolkit` —— bash 补全。

### 1.2 准备 cryptsetup 工具

cryptsetup是贯穿本工具集的一个重要命令，必须提前安装。虽然linux发行版基本都自带cryptsetup工具，但大多版本低于2.7.3(通过命令：`cryptsetup --version`可以看到系统自带的版本号)，不支持"capi:"参数，也就**不支持更高性能且合规的“gbt17964(xts(sm4))”算法**（原因见工具集README），所以：
**建议使用版本高于2.7.3的cryptsetup**，可以自行从[https://gitlab.com/cryptsetup/cryptsetup](https://gitlab.com/cryptsetup/cryptsetup)下载最新源码编译，编译方式很简单：

```bash
/autogen.sh
/configure
make
#或者
/configure
make
#完成编译后执行验证构建是否成功：
sudo make check
#验证完成后可选择安装或不安装，若要安装，则建议先卸载系统自带的cryptsetup，然后执行：
sudo make install
```

本手册示例采用自编译 cryptsetup 2.8.6，本手册为了演示通过`--cryptsetup-path` 参数定位新版cryptsetup所在路径，没有执行install安装。
使用者若编译新版本cryptsetup并install到系统路径，则可以不带`--cryptsetup-path`参数执行。

### TIPS：如果使用`--cryptsetup-path` 参数，则deploy、perf、manage子函数都要带`--cryptsetup-path`，以保证cryptsetup工具在整个部署/维护周期内的统一。

### 1.3 工具最低版本（手册示例路径要求）

| 工具 | 最低版本 | 说明 |
|------|---------|------|
| tpm2-tools | 5.x | `tpm2_getcap`、`tpm2_pcrread`、`tpm2_nvdefine` 等 |
| cryptsetup | 2.7.3 | 用 CAPI 必须 ≥ 2.7.3 |
| 内核 | Hygon C86 配套 | 已编译 `CONFIG_CRYPTO_SM4_CIS_X86_64=[ym]`，否则 `gbt17964(xts(sm4))` 将无法注册至 `/proc/crypto` |
| 权限 | root | 所有子命令都要求 root |

### 1.4 检查sudo 可用性

因为本工具集需要sudo权限，若非root用户，需检查sudo可用：

```bash
sudo -n true && echo "sudo OK"
```

## 2. 部署前体检：precheck

**适用时机**：首次部署前；或部署环境（内核、cryptsetup、TPM）发生变更后。

```bash
sudo hygon_luks_toolkit precheck --verbose
```

实际输出（节选自 C86 主机 + cryptsetup 2.8.6 自编译路径下的典型执行结果）：

  cryptsetup              PASS    cryptsetup present (resolved: /usr/sbin/cryptsetup)
  tpm_dev                 PASS    TPM device nodes /dev/tpm0 and /dev/tpmrm0
  kconfig_core            PASS    Kernel config: TCG_TPM, DM_CRYPT, CRYPTO_XTS, CRYPTO_AES
  kconfig_phys            PASS    Kernel config: TCG_TIS or TCG_CRB present
  kconfig_hygon           PASS    Kernel config: TCG_HYGON (Hygon TPM driver)
  kconfig_user_api        PASS    Kernel config: CRYPTO_USER_API_SKCIPHER present
  pcr_bank_sm3            PASS    TPM sm3_256 PCR bank present
  pcr_read                PASS    tpm2_pcrread sm3_256:0,2 returns values

CAPABILITIES (informational)
  CAPABILITY              AVAIL   NOTE
  ----------------------  ------  ------------------------------------------------------------
  cipher_aes_xts          yes     xts(aes) registered -- aes-xts-plain64 LUKS volume works
  kernel_sm4_xts          yes     sm4 cipher source available in kernel -- xts(sm4) will be
                                 auto-instantiated on first request via xts/ecb template
                                 composition (no manual modprobe needed).
  kernel_gbt17964_sm4_xts yes     sm4-cis-x86_64 available -- gbt17964(xts(sm4)) is
                                 registered directly.
  hash_sm3                yes     sm3 registered -- usable as LUKS hash and PCR digest
  fio                     yes     fio present -- the 'perf' subcommand is usable
  capi_cipher_syntax      yes     cryptsetup >= 2.7.3 -- capi: cipher family recognised by
                                 cryptsetup

[INFO/precheck] Versions: tpm2-tools=5.6  cryptsetup=2.8.6  OS=centos-stream  initramfs=dracut
```

### 怎么读这张表

- **`REQUIRED CHECKS` 全部 PASS 后方可继续执行 deploy**。若出现 `WARN` 或 `FAIL`，脚本将以退出码 20 退出并打印一行 `[ERROR/precheck] One or more required checks failed. Refusing to proceed.`
- **`CAPABILITIES (informational)` 段不影响 deploy**，但用于指示**下一步 deploy 菜单中将出现的可用选项**：
  - 若 `capi_cipher_syntax=yes` 且 `kernel_gbt17964_sm4_xts=yes`，step 2 菜单将**包含**第 3 项 `capi:gbt17964(xts(sm4))-plain64`。
  - 任一项为 `no` 时，菜单仅包含 AES 与 SM4-xts 两项。
- 本手册示例路径要求 `kernel_gbt17964_sm4_xts=yes` 且 `capi_cipher_syntax=yes`。若不满足，请**改选 step 2 的第 2 项 `sm4-xts-plain64`**（同样满足合规要求，性能略低）。

> 若需查看脚本实际调用的命令，可追加 `--dry-run`：
> 
> ```bash
> sudo hygon_luks_toolkit precheck --dry-run
> ```
> 
> `STATUS` 列将变为 `DRY`，其后跟随一行 `        would run: <cmd>`。

## 3. 部署：deploy子命令 —— 11 个步骤 step by step

本节命令（全程需以 root 权限运行）：

```bash
sudo hygon_luks_toolkit deploy \
     --cryptsetup-path /home/lipu/workspace/cryptsetup-2.8.6 \
     --allow-luks-reformat
```

进入 wizard 后的首屏（banner + 内部 precheck）：

```
================================================================
   hygon_luks_toolkit toolkit  -  TPM+LUKS deploy / manage / perf
   version 1.2.0
================================================================

  >>> Subcommand: deploy

TPM+LUKS deploy wizard
[INFO/deploy] Re-running precheck (this is fast and may abort the deploy on critical failures)...
```

如果内部 precheck 不过，会打印 `[ERROR/deploy] Precheck did not pass; refusing to deploy. Run 'hygon_luks_toolkit precheck' first to see the failing checks.` 并退出码 20。

下文每一步均按"屏幕输出 → 用户输入 → 本步骤操作说明"三段呈现。

### 3.1 Step 1/11 — 选目标分区

### 3.5 Step 4b/11 — 选 PCR 策略

紧接 step 4，**不会**推进 step 计数器（4b 与 4 共用同一 `STEP_4_STATUS` 状态）。屏幕输出：

```
Step 4b/11: Choose PCR policy set

  The PCR set binds the sealed key to specific boot-measurement
  registers. A narrower set (e.g. {0,2}) is more forgiving after
  BIOS / firmware updates; a wider set (e.g. {0,2,4,7}) also covers
  the bootloader (PCR4) and Secure Boot (PCR7) so any change there
  also blocks auto-unseal. The bank is always sm3_256 (C86 TPM).

  PCR policy:
    1) sm3_256:0,2  -- firmware + BIOS/option ROM (standard)
    2) sm3_256:0,2,4,7 -- + bootloader + Secure Boot (high security)
    3) custom            -- pick individual PCRs (checkbox: space to tick)
  Choice [1-3] (default 1):
```

三个选项含义：

- `1` 标准：`sm3_256:0,2`，只绑定固件 + BIOS/option ROM，升级 BIOS/固件后最不易失效，是默认项。
- `2` 高安全：`sm3_256:0,2,4,7`，额外绑定 bootloader（PCR4）与 Secure Boot（PCR7），任何一处变动都会阻断开机自动解封。
- `3` custom：进入复选框界面自由勾选任意 PCR 组合，绑定范围完全自定义（详见下方 3.5.1）。

选 `1` / `2` 都是固定预设，选中即写入对应集合、无需额外操作。本手册为演示自由组合，选 `custom`（第 3 项），输入 `3` 进入复选框界面：

```
3
```

#### 3.5.1 选 `3) custom` —— 复选框自由组合 PCR

选 `3` 后进入复选框界面。候选 PCR 为 0–9，默认按标准集预勾 `{0,2}`。操作键：`空格`勾选/取消当前项、`↑`/`↓`（或 `k`/`j`）移动光标、`回车`确认。**至少勾一个**，否则回车无效；全程无需手输数字。初始界面（光标 `>` 停在 PCR 0）：

```
  Select PCRs (sm3_256) -- space=tick  up/down=move  enter=confirm:
  > [x] 0 firmware / platform firmware code (SRTM)
    [ ] 1 firmware configuration / data
    [x] 2 option ROM code (pluggable)
    [ ] 3 option ROM configuration / data
    [ ] 4 boot loader / MBR / IPL code
    [ ] 5 boot loader configuration / GPT
    [ ] 6 platform / resume / state transitions
    [ ] 7 Secure Boot policy
    [ ] 8 boot loader command line (GRUB)
    [ ] 9 kernel / initrd files (GRUB)
  Checked: 0,2
```

本手册在默认预勾 `{0,2}` 的基础上，再把 PCR 4、PCR 7 勾上（`↓` 移到对应行按 `空格`），凑成与"高安全"预设等价的 `{0,2,4,7}`。界面实时刷新为（光标停在 PCR 7）：

```
  Select PCRs (sm3_256) -- space=tick  up/down=move  enter=confirm:
    [x] 0 firmware / platform firmware code (SRTM)
    [ ] 1 firmware configuration / data
    [x] 2 option ROM code (pluggable)
    [ ] 3 option ROM configuration / data
    [x] 4 boot loader / MBR / IPL code
    [ ] 5 boot loader configuration / GPT
    [ ] 6 platform / resume / state transitions
  > [x] 7 Secure Boot policy
    [ ] 8 boot loader command line (GRUB)
    [ ] 9 kernel / initrd files (GRUB)
  Checked: 0,2,4,7
```

按 `回车`确认，勾中项以升序逗号串写入策略并自动补上 `sm3_256:` bank 前缀，与前两个预设完全同构。成功 log：

```
[INFO/deploy] PCR policy: sm3_256:0,2,4,7
```

> 候选 PCR 列表由 `lib/common.sh` 的 `PCR_CANDIDATES[]` 数组决定；要增减可选项只改这一个数组即可，无需动其它代码。

### 3.7 Step 6/11 — 生成 32 字节随机 keyfile

屏幕输出（无交互）：

```
Step 6/11: Generate a 32-byte random keyfile

[OK/deploy] Keyfile ready: /tmp/luks.key.12345 (32 bytes, 0400)

`/tmp/luks.key.<pid>` 为临时文件，**deploy 完成后将由 step 10 执行 shred**。持久化的 keyfile 由 step 11 通过 TPM 解封生成，落盘至 `/run/<mapper>.key`，权限模式 0400。

### 3.8 Step 7/11 — cryptsetup luksFormat

屏幕输出：

```
Step 7/11: cryptsetup luksFormat on /dev/sdb1

  This step writes a LUKS2 header to /dev/sdb1.
  The first ~16 MiB of the partition will be OVERWRITTEN.
  Existing data on the partition is IRRECOVERABLY destroyed.
  cryptsetup runs in --batch-mode; you will not be prompted for confirmation.

  Note: state.env persists the LUKS UUID written below, NOT the
  /dev/sdb1 path you see here.  After a reboot, the
  kernel may assign a different sdX name to this disk; the
  toolkit will resolve by LUKS UUID.  See README "sdX-safety".

Proceed with luksFormat on /dev/sdb1?
  [y/n/c]? 
```

**该步骤为唯一会对磁盘执行物理擦除的步骤**。确认无误后输入：

```
y
```

后续屏幕输出（cryptsetup 自身输出占满一屏，此处略去；以下为脚本层面的关键日志）：

```
[INFO/deploy] Creating ext4 filesystem on LUKS volume /dev/sdb1 (mapper: _mkfs_tmp)

## 5. 管理维护：manage 子命令

每个子命令一节，结构统一：**用途 → 命令 → 典型输出 → 适用时机**。

### 5.1 `manage status` —— 一眼看出全部加密卷

**用途**：以 dashboard 形式展示本工具集部署过的全部加密卷——逐设备列出 LUKS UUID、mapper 名、TPM 封存对象、PCR 策略、crypttab / fstab 条文、unseal 脚本与 systemd unit 路径，以及当前 mapper 是否 OPEN。属于**只读**操作，可随时执行而不影响运行状态，是日常巡检与故障定位的首选入口。

```bash

**适用时机**：任何时候需确认磁盘在线状态、TPM 对象是否存在、systemd unit 是否已安装。

### 5.3 `manage verify` —— 单盘健康检查

**用途**：对单台加密卷执行 8 项健康检查——设备存在性、LUKS UUID 一致性、LUKS header 完整性、mapper open 状态、TPM 封存对象、PCR 策略可读性、unseal 脚本与 systemd unit 安装情况。适合每次系统重启后、BIOS / bootloader 升级后、或怀疑部署状态被篡改时运行，**只读**不修改任何状态；首次部署后第一次重启可能因 systemd 尚未完成解封而短暂告警，再次 reboot 后即稳定。

```bash

```

成功输出见 §4。失败时将以 `[ERROR/manage]` 标注每行错误并以退出码 30 退出。

**适用时机**：每次系统重启后；BIOS/bootloader 升级后；或怀疑部署状态被篡改时。

[INFO/manage] Removed header backup: /var/backups/hygon_luks_toolkit/<uuid>-20260715190000.header.bak
[OK/manage] Removed 1 header backup(s).

Step 8/8: Clear the state file (/var/lib/hygon_luks_toolkit/state.env)

```

**适用时机**：更换磁盘、推倒加密方案重建、或拆除本机 TPM+LUKS 整套方案时。

> **rollback 不擦除 LUKS 数据**——header 与 payload 均保持不变。rollback 执行完毕后，该磁盘仍处于加密状态，仅无法自动解封。如需彻底擦除数据，请执行 `cryptsetup luksErase`。

### 5.11 `manage state-show` / `manage state-clear` —— 看/清状态文件

**用途**：`state-show` 打印 `/var/lib/hygon_luks_toolkit/state.env` 中的 `key=value` 行（目标设备、LUKS UUID、TPM 封存对象、PCR 策略、部署时间戳等），用于排查"实际部署与 state.env 不一致"的问题；`state-clear` 则按 `--device /dev/DEV`（清除单个设备条目）或 `--all`（清空整个状态文件）两种粒度重置状态。**注意**：state 文件由工具集自动维护，请勿手编——手编后下次 deploy / manage 操作可能误判状态。

```bash
# 看
sudo hygon_luks_toolkit manage state-show

# 清单个设备的 slot
sudo hygon_luks_toolkit manage state-clear --device /dev/sdb1

# 清整个状态文件（所有设备）
sudo hygon_luks_toolkit manage state-clear --all
```

`state-show` 直接打印 `key=value` 行（**不要手编**），例如：

```
TARGET_DEV=/dev/sdb1
TARGET_UUID=<uuid>
TARGET_SAFE_ID=<8hex>
CIPHER_KEYSPEC=capi:gbt17964(xts(sm4))-plain64
KEY_SIZE=256
KDF=argon2id
HASH=sm3
SEAL_SCHEME=nv
PCR_LIST=sm3_256:0,2,4,7
TPM_HANDLE_OR_NVINDEX=0x1500016
MAPPER_NAME=luks_sdb1
MOUNT_POINT=/mnt/luks_sdb1
INSTALLED_AT=2026-07-15T19:00:00+0800
STEP_1_STATUS=DONE
...
STEP_11_STATUS=DONE
```

`state-clear --device` 与 `state-clear --all` 均将请求一次 `[y/n/c]?` 确认。若未携带任何 flag，操作将被拒绝：

```
[ERROR/manage] state-clear requires either --device /dev/DEV (clear one device) or --all (wipe entire state file). Refusing to act.
```

**适用时机**：state 文件与实际部署状态不一致或怀疑存在 stale 项时；多设备场景下需单独移除某个 slot 时。

## 7. 常见错误与对应命令

| 报错 | 原因 | 怎么办 |
|------|------|--------|
| `This script must be run as root.` | 没用 sudo | 加 `sudo` |
| `cryptsetup not found; cannot annotate candidates` / `cannot proceed` | cryptsetup 不在 PATH | 用 `--cryptsetup-path /path/to/dir` 或 `/path/to/cryptsetup` |
| deploy step 2 选 3 后报 `CAPI not available on this cryptsetup` | cryptsetup \< 2.7.3 或内核没注册 `gbt17964(xts(sm4))` | 升级 cryptsetup；或退回到选 2（`sm4-xts-plain64`） |
| `[ERROR/deploy] Precheck did not pass; refusing to deploy.` | 内部 precheck 有 CRITICAL FAIL | 先跑 `sudo hygon_luks_toolkit precheck --verbose`，看 REQUIRED CHECKS 哪行 FAIL |
| `UUID mismatch: /dev/sdb1 has LUKS UUID 'X', but state.env records 'Y'.` | resume 时 sdX 名字漂移——同一个名字被另一块盘占了 | `sudo blkid \| grep Y` 找正确的设备，然后 `sudo hygon_luks_toolkit deploy --device /dev/<correct-dev> [resume]` |
| `[ERROR/manage] Cannot resolve LUKS UUID '…' to any /dev/... block device.` | state 里的 UUID 在系统里找不到了（盘没插 / udev 卡了） | `sudo udevadm settle && sudo hygon_luks_toolkit manage state-show`；还不行就 `manage state-clear` |
| `manage verify` 报 `[WARN/manage] Mapper /dev/mapper/luks_sdb1 not open` | 第一次重启后 systemd 还没解封完 | 再 reboot 一次；或 `manage mount --device /dev/sdb1` 手动挂 |
| `[ERROR/seal] tpm2_nvdefine failed.` / `tpm2_evictcontrol failed.` | TPM 满了 / 权限问题 / 驱动 bug | `dmesg \| grep -i tpm`；`tpm2_getcap handles-nv-index` 看空间 |
