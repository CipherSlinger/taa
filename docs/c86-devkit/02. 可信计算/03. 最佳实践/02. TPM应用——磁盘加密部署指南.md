# 一、简介

磁盘加密工具种类丰富，比如windows下的bitlocker，Linux下的dm-crypt等。本文主要介绍Linux下的加密工具和TPM之间的应用。磁盘加密是TPM应用中比较典型的一类功能，主要是利用TPM来安全的管理磁盘加密的密钥，通过把密钥保存在TPM内并设定授权策略与代表系统一致性信息的PCR值绑定，只有当前PCR符合预期，即系统一致性符合预期时，才能从TPM中将密钥读取出来（关于PCR的作用可参照前述TPM功能测试文档）。当系统遭到篡改，比如操作系统被更改或者BIOS被更改，密钥都将无法读出。密钥读出后通过cryptsetup工具设置到LUKS中，后续磁盘访问时具体的加解密过程完全由dm-crypt提供，与TPM无关。

# 二、基础概念

## 1、LUKS

LUKS（Linux Unified Key Setup），是一种在 Linux 环境下广泛使用的磁盘加密标准（非加密算法），它提供标准化的方式来对磁盘进行加密。LUKS定义了加密设备的元数据格式（加密头），统一了密钥管理流程，并支持多种加密算法，比如AES、Anubis、Blowfish、Twofish等；实际使用时还需选择加密模式（如XTS）以及加密模式的初始化向量模式（如Plain64），最常见的组合是aes-xts-plain64。

LUKS作为dm-crypt的前端管理工具，提供了标准化的加密头和密钥管理接口。用户通过LUKS工具（如 cryptsetup）配置加密参数，LUKS再将配置传递给dm-crypt 执行实际加密。

它允许用户使用多个密钥对同一加密卷进行解密，并且支持密码和密钥文件的组合使用，增加了数据的安全性。此外，LUKS 的另一个优点是它对底层文件系统是透明的，这意味着用户可以在加密的文件系统上使用任何文件系统类型，而无需对文件系统本身进行修改。

### 1.1、加密头（LUKS Header）

位于加密设备的起始位置（通常前 16MB），存储加密元数据，包含：

- 加密算法（如 `aes-xts-plain64`）、密钥大小（如 256/512 位）、扇区大小、哈希算法（如 SHA256）；
- 密钥槽（Key Slot）信息；
- 主密钥加密后的密文；

**注**：加密头是恢复数据的关键，一旦损坏或丢失，数据将永久不可恢复，所以一般情况下建议备份储存。

### 1.2、主密钥（Master Key）

- 用于实际加解密数据的对称密钥（通常 256 位或 512 位），主密钥不直接由用户管理，而是通过**密钥槽**中的密码或密钥加密后存储在加密头中；
- LUKS 初始化时会随机生成一把**主密钥**（真正用于数据面加解密）；
- **主密钥不直接由输入的密码或密钥决定**；密码或密钥只是用来“加密/解密”主密钥；

### 1.3、密钥槽（keyslots）

- LUKS 支持多个 keyslot：即同一把主密钥可以被多种凭据解锁：
  - 口令
  - keyfile（随机二进制数据）
  - TPM2 / FIDO2 / PKCS#11 等 token（比如让 TPM 保护的某个 keyslot中的密钥解封过程）；
- **cryptsetup luksAddKey的本质：再增加一种解锁主密钥的方式**，但不会替换原有口令；
- 存储通过”用户密钥“（密码或密钥文件）加密后的主密钥。每个密钥槽独立存储，支持多组用户密钥（比如 LUKS2 默认支持 8 个密钥槽）。用户通过验证任一密钥槽的密钥，就可以解密出主密钥，进而访问加密数据；

### 1.4、密钥派生（KDF）

用于把输入口令或者密钥变成抗暴力破解的密钥KEK（Key Encryption Key）：

- LUKS1 常见：PBKDF2（CPU 密集）；
- LUKS2 默认：Argon2id（CPU+内存密集，更抗 GPU/ASIC）；
- KDF 只发生在**解锁时刻**，不影响日常 I/O 吞吐；

## 2、dm-crypt

dm-crypt使用内核加密 API 提供块设备的透明加密。可以指定一个对称密码、一个加密模式、一个密钥（任何允许的大小）、一个 iv 生成模式，然后就可以在 /dev 中创建一个新的块设备。写入此设备的数据将被加密，读取数据将被解密。可以将文件系统挂载到此设备上，或者将 dm-crypt 设备与其他设备（例如 RAID 或 LVM 卷）堆叠在一起。

要启用 dm-crypt 支持，需要在内核配置选项中启用**CONFIG\_DM\_CRYPT**。大多数发行版默认都包含 dm-crypt。

dm-crypt内核模块源码位于`drivers/md/dm-crypt.c`。

### 2.1、dm-crypt功能

dm-crypt是Linux 内核里 Device Mapper（DM）的一个 target（target\_type.name="crypt"），负责真正的**扇区级加/解密**。dm-crypt会把一个“后端块设备”包装成一个新的“前端块设备”：

- **后端设备**：真实存放数据的磁盘/分区/逻辑卷（存的是密文）；
- **前端设备**：`/dev/mapper/<name>` 这类映射设备（对上层看起来像普通块设备，读写是明文）；
- **核心功能**：对每一次Block  I/O 做按扇区或块粒度的加/解密，使上层文件系统/应用无需感知加密存在；

可以把dm-crypt理解为：**块设备层的加密适配器**，对上层“透明”，对下层“落盘密文”。

### 2.2、dm-crypt在存储链路中的位置

一个典型的存储层次（从上到下）如下，对上层文件系统来说只是在读写“普通块设备”，并不知道底层被加密，而dm-crypt 则不需要关心文件/目录语义，只处理扇区数据流。

- 应用
- VFS/Page Cache
- 文件系统（ext4/xfs/btrfs…）
- **Device Mapper 虚拟块设备（dm-crypt 生成的 /dev/mapper/xxx）**
- 真实块设备（NVMe/SATA等）
- 驱动与硬件

### 2.3、mapping table

dm-crypt 依赖 DM 的通用机制，即用一份映射表描述“如何把前端设备的逻辑扇区映射到后端设备，并对数据做什么处理”。

crypt映射表定义如下：

```
<start_sector> <size> <target name> <target mapping table>
```

- **start\_sector**为 0（对于仅使用一个映射段的表，即表仅包含一行）；
- **size**是指设备使用的扇区数目；
- **target name**是映射目标的名称，此处为“crypt”，代表 dm-crypt；

这里的扇区单位始终是 512 字节，但加密可以使用不同的扇区大小（参见`sector_size`选项）。

**target mapping table**定义如下：

```
<cipher> <key> <iv_offset> <device path> <offset> [<#opt_params> <opt_params>]
```

- **cipher**是加密分组密码的格式，比如aes-xts-plain64、aes-cbc-essiv:sha256等；
- **key**是用于加密的密钥；
- **iv\_offset**是一个扇区计数，通常为0；
- **device path**是后端实际承载加密数据的设备，比如/dev/xxx 的路径，或设备号（主设备号:次设备号）；
- **offset**是后端设备上密文数据起始扇区；
- **opt\_params**是一些可选参数，比如allow\_discards、same\_cpu\_crypt、integrity、integrity\_key\_size、sector\_size等；

一个完整的crypt映射表示例：

```plaintext
0 417792 crypt aes-xts-plain64 e8cfa3dbfe373b536be43c5637387786c01be00ba5f730aacb039e86f3eb72f3 0 /dev/sdb1 0  
|    |     |    |   |     |                                 |                                   |    |     |   
start|     |    |  mode   IV                                |                                   |    |   offset  
     size  |  cipher                                        |                                   |  device  
         target                                        256bit-key                          IV offset  
```

### 2.4、dmsetup

Dmsetup是一个用户态工具用于创建和删除设备、获取有关设备的信息或重新加载表（这意味着在设备使用过程中可以更改映射）。通常情况下，此工具仅用于对 DM 设备进行底层访问，此处提及示例只是为了说明底层参数的工作原理。当前主流的发型版OS已经优先使用 cryptsetup，cryptsetup在下一章节介绍。

需要创建设备并指定映射表，使用以下命令：

```
dmsetup create <name> --table " ..." 
```

比如：

```
dmsetup create xxx --table "0 $(blockdev --getsz /dev/sdb1) crypt serpent-cbc-essiv:sha256 a7f67...ee 0 /dev/sdb1 0" 
```

新创建的设备随后显示为\*\*/dev/mapper/xxx\*\*。

使用 cryptsetup 的示例：

如果在 /key 文件中有一个密钥文件（二进制格式），则可以按照上面的示例设置映射。

```plaintext
cryptsetup -d /key -s 128 -c serpent-cbc-essiv:sha256 create <name> /dev/sdb1
```

如果要使用默认加密算法的 LUKS 磁盘元数据，使用如下命令：

```plaintext
cryptsetup luksFormat <device>
cryptsetup luksOpen <device> <name>  
```

## 3、cryptsetup（用户态工具）

cryptsetup 是 Linux 上配置磁盘加密的用户态工具，其核心库是 libcryptsetup。它主要负责创建/解析 LUKS 头、管理 LUKS keyslots、派生密钥、解封主密钥以及调用 device-mapper 创建/移除 dm-crypt 映射设备（`/dev/mapper/<name>`）。下面介绍下cryptsetup常见命令用法。

### 3.1 创建与打开加密设备

```bash
# 初始化（注：此操作会清空分区！！），执行后，工具会提示确认（输入 YES，大写），并要求设置初始密码；
# 初始化 LUKS2 设备（采用默认算法：aes-xts-plain64，密钥大小 256 位，哈希算法 sha256），就是将sdb1变成加密设备。
sudo cryptsetup luksFormat --type luks2 /dev/sdb1

# 创建加密设备后，需先解密再映射为虚拟设备
# 打开（创建 /dev/mapper/mydata），输入上一步骤中设置的密码，验证通过后，虚拟设备 /dev/mapper/mydata 即创建成功。
sudo cryptsetup open /dev/sdb1 mydata
```

### 3.2 格式化与挂载加密设备

映射后的虚拟设备可像普通磁盘一样格式化（如 ext4、XFS）并挂载：

```bash
# 格式化（以 ext4 为例）
sudo mkfs.ext4 /dev/mapper/mydata

# 创建挂载点并挂载
sudo mkdir /mnt/mydata
sudo mount /dev/mapper/mydata /mnt/mydata

# 此时，/mnt/mydata即为加密设备的访问目录，所有写入该目录的文件会被自动加密。
```

### 3.3 关闭LUKS设备（close）

使用完毕后，需卸载并关闭加密设备，释放资源：

```bash
# 卸载挂载点
sudo umount /mnt/mydata
 
# 关闭加密设备（删除映射）
sudo cryptsetup close mydata
```

### 3.4 管理 keyslots

LUKS 支持多密钥槽，可添加多个密码/密钥文件，方便密钥轮换或多用户访问。

```bash
# 添加密码
# 首先输入现有密码（验证权限），然后设置新密码，完成后新增一个密钥槽
sudo cryptsetup luksAddKey /dev/sdb1

# 添加密钥文件
# 先输入现有密码，之后添加密钥文件可替代密码，适合自动化场景，添加密钥文件到密钥槽，/path/to/keyfile是密钥文件路径
sudo cryptsetup luksAddKey /dev/sdb1 /path/to/keyfile

# 删除指定密钥槽的密钥
sudo cryptsetup luksRemoveKey /dev/sdb1    # 删除某把口令（匹配输入的那把），需输入待删除的密码
sudo cryptsetup luksRemoveKey /dev/sdb1 /path/to/keyfile   # 删除某个密钥文件，/path/to/keyfile是密钥文件路径

# 查看 keyslot 状态
sudo cryptsetup luksDump /dev/sdb1

# 直接修改某个密钥槽的密钥（等价于先删除旧密钥，再添加新密钥），格式：sudo cryptsetup luksChangeKey <加密设备路径> [密钥文件]
sudo cryptsetup luksChangeKey /dev/sdb1
```

### 3.5 LUKS头部备份

```bash
sudo cryptsetup luksHeaderBackup /dev/sdb1 --header-backup-file /root/sdb1.luks.header
```

LUKS 头损坏通常等同于数据不可恢复（除非有备份）。建议将备份文件（如 `sdb1.luks.header`）存储在**离线、安全的位置**（如加密 U 盘、保险箱），并设置权限 `chmod 400`。

### 3.6 LUKS头部备份恢复

```bash
sudo cryptsetup luksHeaderRestore --header-backup-file /root/sdb1.luks.header /dev/sdb1
```

注：恢复前需确保目标设备与备份时的设备大小一致，否则可能导致数据损坏。

# 三、TPM在磁盘加密中的应用

前面已经介绍了可以将一个密钥文件添加到LUKS密钥槽对磁盘进行加解密操作，而利用TPM来管理磁盘加密的密钥具有极高的安全性，比如把密钥和代表系统一致性信息的PCR值绑定，这样可以确保只有系统启动符合预期时才能从TPM中将密钥读取出来。**下面以ubuntu 18.04系统为例，描述如何实现TPM自动解封密钥并解密加密磁盘/dev/sdb1以及挂载磁盘的过程。**

本次使用的TPM软件栈信息如下：

tpm2-tools-5.7

tpm2-tss-4.0.1

tpm2-abrmd-3.0.0

注：不同版本的tpm2-tools命令格式略有差异，请以实际版本命令格式为准。

## 1、生成随机 key 并加入 LUKS keyslot

```
# 生成 32 字节 key（参考示例，路径和名称根据实际场景更改即可）
tpm2_getrandom -f 32 -o /tmp/luks.key

# 初始化（注：该步骤会清空分区！！），执行后，工具会提示确认（输入 YES，大写），并要求设置初始密码
sudo cryptsetup luksFormat --type luks2 /dev/sdb1

# 把 key 加入 LUKS keyslots（要求输入上述初始密码）
sudo cryptsetup luksAddKey /dev/sdb1 /tmp/luks.key
```

## 2、封存 key

以下两种方式任选其一即可。

### （1）基于封存对象

```
# 基于选定的PCR(0/2)值创建一个Policy:
tpm2_createpolicy --policy-pcr -g sm3_256 -l sm3_256:0,2 -L policy.digest

# 在Storage Hierarchy创建主密钥（Primary Key）并设置访问授权码123456:
tpm2_createprimary -C o -g sm3_256 -G ecc_sm2:null:sm4128cfb -c pctx.out -p 123456

# 在主密钥下为加密密钥/root/luks.key创建一个TPM数据对象，设置Policy策略，创建后数据对象会先保存在本地文件: 
tpm2_create -g sm3_256 -u secret.pub -r secret.priv -C pctx.out -L policy.digest -i /tmp/luks.key -P 123456

# 加载tpm2_create创建的数据对象到TPM内存中:
tpm2_load -C pctx.out -u secret.pub -r secret.priv -c sctx.out -P 123456

# 数据对象保存到flash中成为持久对象，掉电不丢失:  
tpm2_evictcontrol -C o -c sctx.out 0x81010001

#释放内存中对象
tpm2_flushcontext -t

# 封存完成后，删掉明文 key（建议留一份离线备份再删）
sudo shred -u /tmp/luks.key
```

### （2）基于 NV 存储

```
# 基于选定的PCR(0/2)值创建一个Policy:
$ tpm2_createpolicy --policy-pcr -g sm3_256 -l sm3_256:0,2 -L policy.digest

# 定义一个NVRAM区域，绑定上述策略，用来存放加密口令:
$ tpm2_nvdefine 0x01500016 -C o -s 32 -g sm3_256 -a "policyread|policywrite" -L policy.digest

# 将密钥写入NV，PCR值必须和之前定义NV区域时一致才可以写入:
$ tpm2_nvwrite 0x01500016 -C 0x01500016 -i /tmp/luks.key -P pcr:sm3_256:0,2

# 储存完成后，删掉明文 key（建议留一份离线备份再删）
sudo shred -u /tmp/luks.key
```

## 3、开机解锁加密设备

### （1）tpm 密钥释放

在系统组件未发生篡改，即PCR不变的情况下，可利用脚本实现开机自动释放密钥（脚本在步骤（4）中使用），比如tpm2-get-mydata-key.sh，示例内容如下：

根据步骤2中封存key的方式不同，释放key也有两种方式，请选择对应的方式释放密钥。

```
#!/bin/bash

# unseal to OUT
tpm2_startauthsession --policy-session -S /tmp/seal.ctx -g sm3_256
tpm2_policypcr -S /tmp/seal.ctx -l sm3_256:0,2
tpm2_unseal -c 0x81010001 -p session:/tmp/seal.ctx -o /run/mydata.key
tpm2_flushcontext /tmp/seal.ctx
rm -f /tmp/seal.sctx
chmod 0400 /run/mydata.key
```

```
#!/bin/bash

# NV to OUT
tpm2_nvread 0x01500016 -C 0x01500016 -P pcr:sm3_256:0,2 -s 32 -o /run/mydata.key
chmod 0400 /run/mydata.key
```

完成后安装脚本，安装路径可自行指定：

```
sudo install -m 0700 /usr/local/libexec/tpm2-get-mydata-key.sh /usr/local/libexec/
```

### （2）编辑 /etc/crypttab

`/etc/crypttab`是系统启动时自动解密磁盘的配置文件，如果系统没有，可能是之前从未做过 LUKS 分区加密、也没有加密 swap/data 盘，此时可手动创建：

```
sudo sh -c 'install -m 0644 /dev/null /etc/crypttab'
```

配置文件添加以下内容，系统启动时会用 `/run/mydata.key` 自动解锁 `/dev/mapper/mydata` 加密设备：

```
mydata UUID=<设备的UUID> /run/mydata.key luks
```

注：`/run/mydata.key`是步骤（1）中tpm释放出来的key。

### （3）更新 initramfs

`/etc/crypttab` 修改后需要 **更新 initramfs**（否则启动阶段不会生效）

```
sudo update-initramfs -c -k $(uname -r)    #Debian/Ubuntu
sudo dracut -f                             #RHEL/Fedora
```

### （4）生成 systemd 单元

创建一个systemd unit文件，用来完成开机自动释放密钥并解锁加密磁盘。比如`/lib/systemd/system/tpm2-get-mydata-key.service`，示例内容如下：

```
[Unit]
Description=Get LUKS key from TPM2
DefaultDependencies=no
After=dev-tpm0.device
Requires=dev-tpm0.device
Before=systemd-cryptsetup@mydata.service

[Service]
Type=oneshot
ExecStart=/usr/local/libexec/tpm2-get-mydata-key.sh
RemainAfterExit=yes

[Install]
WantedBy=systemd-cryptsetup@mydata.service
```

1）释放密钥的服务`tpm2-get-mydata-key.service`必须在`systemd-cryptsetup@mydata.service`这一解锁加密设备的服务前运行。

2）当在 `/etc/crypttab` 里写了条目（比如 `mydata …`），然后触发 generator（重启或 `daemon-reload`），`/run/systemd/generator/systemd-cryptsetup@mydata.service`服务才会生成；

3）可通过 `systemctl cat systemd-cryptsetup@mydata.service`查看服务状态；

4）`mydata` 是实例名（mapper 名称），对应 `/dev/mapper/mydata`，systemd 用它实例化出：`systemd-cryptsetup@mydata.service`

启动上述服务：

```
sudo systemctl daemon-reload
sudo systemctl enable tpm2-get-mydata-key.service
```

### （5）确认磁盘是否解密完成

按照上述步骤配置完成后，重启系统。假设卷名是 `mydata`：

```
ls -l /dev/mapper/mydata
sudo lsblk -f /dev/mapper/mydata

sudo lsblk -o NAME,TYPE,FSTYPE,MOUNTPOINT /dev/sdb1
```

可以看到：

1）`/dev/mapper/mydata` 这个“解密后的块设备”已存在，但该块设备上是没有一个可识别/可挂载的文件系统，因为LUKS/dm-crypt 只负责“块设备加解密”，**不会自动创建 ext4/xfs**。需要在第一次创建映射成功后对 `/dev/mapper/mydata` 做一次 `mkfs.*`创建一个文件系统后才能 mount；比如创建一个ext4 文件系统，使用如下命令：

```
sudo mkfs.ext4 /dev/mapper/mydata
```

注：这一步骤也可根据需要做成service，系统启动完成自动创建文件系统，但一般不建议这样做，原因是系统可能误判该设备“没文件系统”，会造成**不可逆数据损坏**（重新格式化）。

2）`/dev/sdb1` 设备 type 通常为 `crypt`；

### （6）fstab：挂载 mapper 设备

可根据需要实现开机挂载上述创建的文件系统，比如先创建挂载目录：

```
sudo mkdir -p /mnt/mydata
```

之后修改 `/etc/fstab` 文件，增加如下内容：

```
/dev/mapper/mydata /mnt/mydata ext4 defaults,nofail,x-systemd.device-timeout=10s,x-systemd.automount 0 2
```
