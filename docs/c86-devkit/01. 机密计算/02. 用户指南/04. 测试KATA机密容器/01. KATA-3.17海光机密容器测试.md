### 机密容器与KBS远程认证、获取KBS存储的秘密

> 为了更直观展示KBS是一个独立（位于可信隔离环境）的服务，这里展示在一个独立于运行机密容器的物理机的平台环境，这个平台环境需要提供机密容器物理机可以访问的IP地址，以便机密容器的TEE环境能够与KBS进行通信（通信过程中包括交互远程认证、传输秘密）。

> 下面的示例中用${KBS\_IP\_ADDR}表示KBS服务的IP地址。

#### KBS所属物理平台上编译、安装、运行KBS服务

> KBS服务由 kbs、as、rvps组成。

##### 编译、安装KBS

**打开用于KBS服务的终端1**

```shell
## 如果是openEuler、Anolis的系统，请执行如下语句安装curl
sudo yum makecache
sudo yum install -y curl
## 如果是ubuntu的系统，请执行如下语句安装curl
sudo apt update
sudo apt install -y curl

## 执行脚本`build-kbs-microservices.sh`编译kbs,as,rvps
cp ~/test/deployment/tools/build-and-install/kbs-as-rvps/build-kbs-microservices.sh /dev/shm/build-kbs-microservices.sh
bash /dev/shm/build-kbs-microservices.sh
```

##### 运行KBS服务

**本示例中：**

* RVPS的参考值文件存放在`/opt/confidential-containers/rvps-reference-values.json`（用户可以通过工具`rpvs-tool`查询和更新参考值）
* AS使用的规则配置文件存放在`/opt/confidential-containers/attestation-service/policies/opa/default_cpu.rego` （用户可以尝试调试以便展示RTMR校验功能）
* KBS使用的秘密管理配置文件存放在`/opt/confidential-containers/opa/policy.rego`
* 用户可以把认证报告验证所须的证书链存储到`/opt/hygon/csv/hsk_cek/<海光物理CPU的Chip ID>/hsk_cek.cert`，这样在验证认证报告时就不需要连接公网获取证书链了。

###### 将运行机密容器的裸机的 Hygon 证书链存储到 KBS 中

**该步骤只有机器不能连外网时用到，需要离线部署认证的证书链**

> 您必须在运行机密容器的裸机上执行以下命令

* 获取芯片序列号以及证书链

```shell
## chip_id.txt 文件包含类似 'ABCD6666666666' 的 ASCII 字符串
sudo hag general get_id | grep 'chip id is' | awk '{print $4}' > chip_id.txt
## 以下命令将为 chip_id.txt 对应的芯片序列号保存 hsk_cek.cert 证书链到当前工作目录
curl -s -f -o hsk_cek.cert https://cert.hygon.cn/hsk_cek?snumber=$(cat chip_id.txt)
```

* 将 "chip\_id.txt" 和 "hsk\_cek.cert" 文件传输至运行 KBS/AS/RVPS 微服务的裸机上

```shell
## 假设运行 KBS/AS/RVPS 微服务的裸机用户名为 ${KBS_HOST_USER}，IP 地址为 ${KBS_IP_ADDR}
scp chip_id.txt hsk_cek.cert ${KBS_HOST_USER}@${KBS_IP_ADDR}:~/
```

> 必须在运行 KBS/AS/RVPS 微服务的裸机上执行以下命令。

```shell
sudo mkdir -p /opt/hygon/csv/hsk_cek/$(cat chip_id.txt)/
sudo cp hsk_cek.cert /opt/hygon/csv/hsk_cek/$(cat chip_id.txt)/hsk_cek.cert
```

**在KBS服务的终端1**

```shell
## 这里运行的AS是以前台模式运行，且打开了调试日志，用户可以通过翻滚窗口看到远程认证的细节，包括measurement, rtmr等。
cd ~/test/deployment/tools/build-and-install/kbs-as-rvps && ./run-rvps-as.sh
```

**打开用于KBS服务的终端2**

```shell
cd ~/test/deployment/tools/build-and-install/kbs-as-rvps && ./run-kbs.sh
```

##### 在KBS服务的文件系统中写入要存储的秘密

**打开用于KBS服务的终端3**

> 这里的秘密的存储路径为`/opt/confidential-containers/kbs/repository/default/test-secret/1`，下面测试机密容器获取秘密时，获取的秘密就是这里存储的秘密

```shell
sudo mkdir -p /opt/confidential-containers/kbs/repository/default/test-secret
cat <<EOF | sudo tee /opt/confidential-containers/kbs/repository/default/test-secret/1
This is secret stored in the KBS, you got it :)
EOF
```

> **注意：** KBS 的 CPU 策略文件为 `/opt/confidential-containers/attestation-service/policies/opa/default_cpu.rego`。为测试方便，可以取消度量值验证，将该文件内容修改如下：

    ```rego
    executables := 3 if {
      input.csv.measurement
      #input.csv.measurement in data.reference.measurement
    }
    ```

> 其中 `input.csv.measurement`（不验证度量值）与 `input.csv.measurement in data.reference.measurement`（验证度量值）是互斥的，保留一个即可。

* 在主机界面\> 计算得到CSV3机密容器的启动度量值

```shell

  -o /dev/shm/csv-calc-measurement.sh && \

```

```shell
cat <<EOF > rvps.csv.measurements
{

    ]
}
EOF

provenance=$(cat rvps.csv.measurements | base64 --wrap=0)
cat << EOF > rvps.message
{
    "version" : "0.1.0",
    "type": "sample",
    "payload":"${provenance}"
}
EOF

## 上传数据
```

### 测试基于kbs密钥的pvc卷机密容器

> **说明**：本章节基于 KBS 提供的持久密钥进行加解密，除了提供容器 rootfs 存储空间外，还会额外挂载一个加密卷供容器使用，加密卷中的数据在容器重启后依然存在，具备持久性。

> 我们在这里将存储密钥路径固定为 'default/keys/trusted-storage-key-1'，因为测试脚本 `test-simple-pod-with-trusted-pvc.sh` 将使用此密钥路径。

```shell
sudo mkdir -p /opt/confidential-containers/kbs/repository/default/keys
sudo dd if=/dev/urandom \
  of=/opt/confidential-containers/kbs/repository/default/keys/trusted-storage-key-1 \
  bs=4096 count=1
```

> 脚本 `test-simple-pod-with-trusted-pvc.sh` 将会<br>

1) 创建 `${HOME}/trusted-image-storage.img`、`${HOME}/trusted-container-storage.img`，并将其挂载到 `/dev/loop10`、`/dev/loop11` 设备
2) 创建 StorageClass、PV、PVC、Pod 的 yaml 文件
3) 创建脚本 `pod-apply.sh`、`pod-delete.sh`

> 脚本 `pod-apply.sh` 会创建 StorageClass、PV、PVC，以及名为 `trusted-pvc-busybox` 的 Pod。脚本 `pod-delete.sh` 会删除 StorageClass、PV、PVC，以及名为 `trusted-pvc-busybox` 的 Pod。

```shell
./test-simple-pod-with-trusted-pvc.sh -i ${REGISTRY_IP_ADDR} -p ${REGISTRY_PORT} -r kata-qemu-csv -K ${KBS_IP_ADDR}
```

> 警告：如果裸机重启后要直接运行这里的 `trusted-pvc-busybox` Pod，请先执行 `sudo losetup /dev/loop10 ${HOME}/trusted-image-storage.img`，因为该 PV 依赖 `/dev/loop10` 设备节点，`${HOME}/trusted-container-storage.img` 同样绑定到 `/dev/loop11`。

* 第 1 次运行 Pod `trusted-pvc-busybox`

```shell
./pod-apply.sh
```

* 检查加密设备是否已完成解密并挂载。

```shell
kubectl exec -it trusted-pvc-busybox -- mount |grep data
```
