## BIOS+CSV固件版本要求

> 海光每代CPU都支持对应机密计算能力，但是需要BIOS和固件要求才能支持机密计算功能的使用。

### BIOS版本确认方法

BIOS的版本信息可以通过2种方式获取到：

- BIOS PI版本：将 *机器型号* 告知 *厂商* ，由 *厂商* 反馈您对应的**BIOS PI版本**。
- Bootloader版本：开机，在机器的BIOS设置页面查看Bootloader版本号，Bootloader版本号可以反映出功能支持情况。

### CSV固件版本确认方法

CSV固件的版本信息由**build id**，**api major**，**api minor**表示。

获取**build id**的方法如下：

```
$ sudo hag csv platform_status | grep -i build
build id:           2084
```

获取**api major**和**api minor**的方法如下：

```
$ sudo hag csv platform_status | grep -i api
api_major:          1
api_minor:          3
```

### 更多机密计算特性和优化的BIOS+CSV固件版本要求

> 上表3描述的各代际CPU支持机密计算的BIOS最低版本要求，还有一些诸多的特性和优化是在更高BIOS版本或CSV固件版本中才支持的。

#### ASID划分优化

ASID划分优化：优化前，用于CSV2/3的ASIDs与用于CSV1的ASIDs不能有交集，\[1, MinCsvAsid)范围的ASIDs只能用于CSV2/3，\[MinCsvAisd, MaxAsid\]范围的ASIDs只能用于CSV1；优化后，\[1, MaxAsid\]范围的ASIDs均可用于CSV2/3，\[MinCsvAsid, MaxAsid\]范围的ASIDs可用于CSV1。

> MinCsvAsid可通过CPUID\_Fn8000\_001F\_EDX取得；MaxAsid可通过CPUID\_Fn8000\_001F\_ECX取得。

表 4 ASID划分优化的BIOS+CSV固件版本要求

| CPU | BIOS | CSV固件 |
| --- | --- | --- |
| 海光2号 | 同 **要求1** | build id \>= `1810` |
| 海光C86-3G | 同 **要求2** | build id \>= `1810` |
| 海光C86-4G | 同 **要求4** | build id \>= `1810` |

* 如果主机不支持该优化，且需要支持运行CSV2/CSV3虚拟机，请在主机BIOS中设置`ASID Space Limit`配置项，该配置项的值最终即为MinCsvAsid。

* 如果主机支持该优化，默认主机BIOS中`ASID Space Limit`值为1（即MinCsvAsid=1），如果使用过程中发现MinCsvAsid != 1，请在主机BIOS中设置`ASID Space Limit`配置项为1。

#### SME与CSV解耦支持

* 概念澄清
  - SMEE：硬件使能内存加密功能，SMEE通常在BIOS设置中可以看到，通过在BIOS中设置SMEE为`Enabled`，才能使硬件的内存加密能力可用。主机OS的SME和CSV虚拟机（包括CSV1/2/3）都依赖于硬件的内存加密能力。
  - SME：这个通常是指主机OS应用了内存加密功能，这样主机OS可以对访问的内存进行加密保护，防止外部偷窥物理内存中的明文数据。这属于主机OS管辖域的内存加密保护。
  - CSV虚拟机：CSV虚拟机也是使用的内存加密能力保护虚拟机所属内存的机密性，CSV虚拟机有其独立的内存密钥。这属于CSV虚拟机管辖域的内存加密保护，不隶属于主机OS管辖域。

SME与CSV解耦支持：只要SMEE是打开的，即使支持主机OS不打开SME功能，也可以启动CSV虚拟机。

#### CSV3 ATTESTATION+Kernel启动度量+秘密注入

> CPU代际至少是C86-4G才能支持CSV3。

CSV3 ATTESTATION：提供远程认证的能力，可使认证方确认CSV3虚拟机。在机密容器等主流场景中，起到关键作用。

CSV3 Kernel启动度量：用于确保Qemu kernel direct boot启动方式中，kernel、initrd、cmdline的完整性。在机密容器、密钥封印等主流场景中，起到关键作用。

CSV3 秘密注入：用于支持CSV3虚拟机启动之前，注入秘密消息给虚拟机使用。在机密计算全磁盘加密场景中，起到关键作用。

# Linux内核

## Linux内核编译config配置说明

编译内核时，需要打开相关编译配置，才能让内核支持海光机密计算功能，否则相关支持代码不会包含在编译出来的内核里。

> 以下编译配置中的部分配置项可能依赖于其他内核编译配置项，请用户确保依赖的内核编译配置项被正确设置。

### 配置列表

#### 基础配置

- CONFIG\_AMD\_MEM\_ENCRYPT=y
- CONFIG\_KVM\_AMD\_SEV=y
- CONFIG\_CRYPTO\_DEV\_CCP=y
- CONFIG\_CRYPTO\_DEV\_CCP\_DD=m 或 CONFIG\_CRYPTO\_DEV\_CCP\_DD=y
- CONFIG\_CRYPTO\_DEV\_SP\_CCP=y
- CONFIG\_CRYPTO\_DEV\_SP\_PSP=y
- CONFIG\_HYGON\_CSV=y
- CONFIG\_CSV\_GUEST=m 或 CONFIG\_CSV\_GUEST=y

#### CSV3必须打开的配置

- CONFIG\_CMA=y

#### Reuse ASID（复用ASID）功能

> Linux 6.x版本的内核依赖于以下配置项，Linux \< 6版本的内核不依赖于以下配置项。

- CONFIG\_KVM\_SUPPORTS\_CSV\_REUSE\_ASID=y
