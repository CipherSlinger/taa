# hctconfig

hctconfig是HCT部署必用工具，其参数和含义如下
|参数|含义|说明|
|--- |---|---|
|start| 绑定驱动||
|stop|解绑驱动||
|-m \<driver\>|可选，强行指定驱动模式（否则由脚本自行决定），可选参数hct,vfio-pci,ccp ||
|-n \<ccp\_cnt\>|可选，指定绑定ccp的个数，默认为N-1，N为主机CCP总数，`-n all`绑定全部CCP | |
|-p \<max\_cnt\>|可选，指定主机支持最大的普通进程数，默认为128|仅驱动模式为hct有效|
|-q \<max\_cnt\>|可选，指定主机支持最大的Qemu进程数（即指定拟启动的虚拟机数）|仅驱动模式为hct有效|
|-t \<ccp\_type\>|可选，指定ccp类型，可选参数ntb,psp，默认为both，即两者都选|较少使用，建议默认即可|
|vccp\_create \<cnt\>|可选，指定创建vCCP的group数|HCT3.x有效，group数是指当前主机拟启动虚拟机的个数|

# start\_qemu

start\_qemu.py用于测试HCT虚拟化功能的脚本，他能自动生成**带HCT虚拟化功能**的参数并启动QEMU，用户也可移植脚本代码到其自己的管理平台上，脚本参数含义如下
|参数|含义|说明|
|--- |---|---|
|-q \<qemu\_path\>|指定程序`qemu-system-x86_64`完整路径|例如： -q ./path/bin/qemu-system-x86\_64|
|-n \<cnt\>|指定一次性启动虚拟机的**个数**，默认为1|较少使用|
|-i \<img\>|指定虚拟机镜像的路径|例如：-i ./path/hct.qcow2，更多说明见补充说明（1）|
|--vid \<n\>|指定vTKM密钥空间序列号|可选参数，仅vTKM功能需要|
|-m \<size\>|指定虚拟机启动分配的内存大小|可选，默认自动根据系统环境分配|
|-c \<vm\>|关闭指定的虚拟机|`-c all`关闭全部 或 `-c hct_test_vm_0| |-s|列出已经启动的虚拟机|仅列出由start_qemu.py启动的虚拟机| |--hct_parament \<n\>|列出第n个虚拟机的mdev参数|仅基于hct驱动虚拟化方案使用，更多说明见补充说明| |--update_qemu_conf|更新`/etc/libvirt/qemu.conf\`配置，主要往cgroup\_device\_acl中配置vfio相关节点|仅基于hct驱动模式虚拟化可用|

## 补充说明

（1） 一个虚拟机镜像只能被一台虚拟机使用，因此`-i`指定的镜像个数应该与`-n`所指定的启动虚拟机个数相同，例如`-n 2`，则需要 `-i ./path_0/hct_0.qcow2 -i ./path_1/hct_1/qcow2`

（2）基于hct驱动部署虚拟化，需要使用驱动绑定阶段生成的mdev-id，每一个mdev-id对应唯一的物理CCP设备，多台虚拟机同时使用HCT虚拟化功能，将涉及到mdev-id分配。部分用户使用`libvirt`或自己开发的工具管理虚拟机，需要配置这些参数，`--hct_parament`会帮助用户分配mdev-id的启动参数，例如使用命令`start_qemu.py --hct_parament 3`将为第3台虚拟机分配分配mdev-id参数。需要注意的是

- 该命令仅打印参数，不启动QEMU
- 用户需自行管理已启动的虚拟机序号，即`--hct_parament n`中的n
