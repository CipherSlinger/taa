# cTKM 用户使用指南

本文档说明 cTKM 的部署、配置和日常管理方法。示例默认 HCT 安装在
`/opt/hygon/hct` 目录；安装包文件名和虚拟机镜像路径请以实际交付物为准。

## 1. cTKM 是什么

cTKM 在 CSV 机密虚拟机中提供 TKM 服务，支持客户端通过网络访问。
配置完成后，应用仍使用原有的 SDF、TKM 接口，无需修改接口调用方式。

部署时涉及两类环境：

- **宿主机**：运行 cTKM 虚拟机，通过 `hctconfig ctkm` 命令启动、停止和管理服务。
- **客户端**：运行应用程序，通过宿主机地址和 TCP `6900` 端口访问 cTKM。

管理命令需要在运行 cTKM 虚拟机的宿主机上执行，管理端口为本地 `6901`。
远端客户端只需配置业务端口 `6900`。

```text
Client App
    |
    v
libhct / TKM API
    |
    | TCP host_ip:6900
    v
宿主机端口转发 ----> CSV VM / ctkm_server(TKM)
```

## 2. 快速入门

### 2.1 准备环境

宿主机需要：

- CPU 为 C86-4G 或更新型号
- 内核支持并已启用 CSV3，部署方法参见 [CSV3 环境部署说明](<../../../01. 机密计算/02. 用户指南/01. 环境部署/01. 环境要求.md>)
- 安装 3.0.33 以上版本的 HCT RPM/DEB 安装包
- 宿主机安装 `qemu-kvm` 或 `qemu-system-x86_64` (需支持CSV3)（也可用 `start -qemu <path>` 指定其他 QEMU 二进制）
- 宿主机需要存在以下命令：`ip`、`iptables` 和 `dnsmasq`

### 2.2 启动 cTKM 虚拟机

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm start
```

启动命令返回后，虚拟机仍需要一定时间完成初始化。请按下一节检查服务状态。

查看启动控制台：

```sh
sudo tail -f /var/log/hct/ctkm_console.log
```

该日志记录虚拟机的启动过程，每次执行 `ctkm start` 时会清空。

### 2.3 检查服务

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm status
```

输出形态如下：

```text
CTKM Status: RUNNING
  Business port: 6900
  Client business endpoints:
    localhost:6900
    <host-ip>:6900
  Management endpoint: localhost:6901
```

`RUNNING` 表示服务可用。刚启动时如显示 `STOPPED`，可稍后再次检查；
若持续显示 `STOPPED`，请按第 6.1 节排查。

### 2.4 修改初始管理员口令

内置管理用户为 `admin`，初始口令为 `12345678`。首次部署后建议自行修改：

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm passwd admin
```

命令依次提示输入管理登录口令、admin 旧口令和新口令。首次修改时，前两个
提示均输入 `12345678`。

**请妥善保管 admin 口令。遗忘后恢复系统授权口令会丢失所有应用密钥。**

### 2.5 创建业务用户

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm useradd alice
```

命令会交互式提示输入 admin 口令和新用户口令。用户名长度为 1 到 64 个字符，
只能包含字母、数字、下划线和连字符。

### 2.6 配置客户端

把以下字段合并到客户端现有的 `/etc/hct_config` JSON 对象中：

```json
{
  "ctkm_server_ip": "127.0.0.1",
  "ctkm_server_port": 6900,
  "ctkm_username": "alice",
  "ctkm_password": "StrongPassword",
  "cek_path": "/path/to/hsk_cek.cert"
}
```

| 配置项 | 填写说明 |
| --- | --- |
| `ctkm_server_ip` | 运行 cTKM 服务的宿主机 IP；客户端与服务在同一宿主机时，可填 `127.0.0.1` |
| `ctkm_server_port` | 填写 `6900` |
| `ctkm_username` | 已创建的业务用户名，如 `alice` |
| `ctkm_password` | 该业务用户的口令，请替换示例中的 `StrongPassword` |
| `cek_path` | 与服务端宿主机匹配的 HSK+CEK 二进制证书文件在客户端的路径，文件须对应用可读 |

远端客户端应使用 `hctconfig ctkm status` 显示的可达宿主机地址，
并确保宿主机防火墙允许客户端访问 TCP `6900`。

证书可从 [海光证书下载网站](https://cert.hygon.cn) 获取。
在服务端宿主机上查询芯片序列号，再下载对应证书：

```sh
hag general check | grep "chip id"
```

将下载的 HSK+CEK 二进制证书文件放到客户端，并把 `cek_path` 改为实际路径。

### 2.7 验证 TKM 调用

```sh
hag tkm dev_info_get
```

## 3. 自定义启动参数

### 3.1 `hctconfig ctkm start`

```text
hctconfig ctkm start [-image <path>] [-ovmf <path>] [-qemu <path>] [-smp <count>]
```

| 参数 | 说明 |
| --- | --- |
| `-image <path>` | 指定 cTKM 虚拟机镜像；默认使用安装包中的 `ctkm_server.qcow2`，文件须可读 |
| `-ovmf <path>` | 指定虚拟机启动固件；默认使用安装包中的 `OVMF_CODE.fd`，文件须可读 |
| `-qemu <path>` | 指定 QEMU 路径或命令名；默认依次查找 `qemu-kvm`、`qemu-system-x86_64`，文件须可执行 |
| `-smp <count>` | 指定虚拟机的虚拟 CPU 数量，范围为 1 到 72，默认 8 |

以上参数均为可选项。使用默认参数启动时，直接执行第 2.2 节的启动命令即可。

## 4. 用户和口令管理

本节命令均在宿主机终端执行，并按提示输入 admin 口令。

### 4.1 添加用户

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm useradd <username>
```

依次输入 admin 口令和新用户口令。

### 4.2 删除用户

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm userdel <username>
```

依次输入 admin 口令和该用户当前口令。

### 4.3 查看用户

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm userlist
```

输出为用户名列表；没有用户时输出 `no users`。

### 4.4 修改口令

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm passwd <username>
```

依次输入 admin 口令、用户旧口令和新口令。`username` 可以是普通用户或
内置 `admin`。

## 5. 状态、日志和停止

### 5.1 查看状态和访问地址

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm status
```

该命令无需指定 IP 或端口，会显示服务状态、客户端可使用的业务地址和本地管理地址。
远端客户端请选择自身网络可达的宿主机地址。

### 5.2 导出服务日志

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm log ./ctkm_server.log
```

输入 admin 口令后，服务日志会保存到宿主机的指定文件。
若文件已存在，将覆盖原有内容。

QEMU 控制台日志与服务日志不同：

| 日志 | 位置 | 用途 |
| --- | --- | --- |
| QEMU 控制台 | `/var/log/hct/ctkm_console.log` | 排查虚拟机启动问题 |
| cTKM 服务日志 | 导出时指定的路径，如 `./ctkm_server.log` | 排查服务启动、登录和接口调用问题 |

### 5.3 设置日志级别

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm loglevel debug
```

可选值为 `debug`、`info`、`warning`、`error`。重启 cTKM 虚拟机后生效。

### 5.4 停止虚拟机

```sh
sudo /opt/hygon/hct/hct/script/hctconfig ctkm stop
```

输入 admin 口令后，关闭 cTKM 虚拟机。停止前请先结束正在使用 cTKM 的业务。

## 6. 常见问题

### 6.1 `status` 显示 `STOPPED`

依次检查：

```sh
sudo tail -n 200 /var/log/hct/ctkm_console.log
sudo /opt/hygon/hct/hct/script/hctconfig ctkm log ./ctkm_server.log
```

如果服务尚未就绪，日志导出也可能失败，此时先查看控制台日志。
重点确认 CSV3 环境是否正常、虚拟机是否完成启动，以及业务端口 `6900` 是否可用。
若仍无法定位问题，请保留报错信息和日志，联系技术支持。

### 6.2 启动时报缺少网络工具

安装并确认以下命令可用：

```sh
command -v ip iptables dnsmasq
```

### 6.3 客户端提示缺少 `cek_path`

确认 `/etc/hct_config` 中存在非空 `cek_path`，目标文件对当前进程可读，
并使用第 2.6 节下载的、与服务端宿主机匹配的 HSK+CEK 二进制证书文件。

### 6.4 客户端登录或认证失败

检查：

- 客户端使用的 HSK+CEK 证书文件是否与服务端宿主机匹配；
- cTKM 镜像与客户端 HCT 是否为配套版本；
- 客户端是否能够访问宿主机的 TCP `6900` 端口；
- 用户名和口令是否正确。

### 6.5 管理登录失败

请在运行 cTKM 虚拟机的宿主机上执行管理命令，并输入正确的 admin 口令。
业务用户口令不能用于管理员登录。可先执行 `hctconfig ctkm status` 确认服务状态。
