## 1. 驱动与部署方式

### Q: HCT驱动是什么，它有什么作用？

A: HCT驱动基于内核vfio-mdev模块开发，其设计，一是为了考虑HCT密码库能够运用到虚拟化技术中，二是多进程的支持。HCT驱动内部对CCP资源的共享进行管理，并且驱动内部把多进程使用的IOVA映射到一张iommu页表上，避免了多进程运行中的iommu页表切换，提升多进程应用程序的执行效率。

### Q: HCT驱动和vfio-pci驱动如何选择？

A: CCP可绑定到HCT驱动或者vfio-pci驱动上使用HCT密码库，但需要注意的是vfio-pci驱动不支持多进程，因此用户需要根据使用场景选择：1）如果主机上多进程会同时使用HCT密码库，必须使用HCT驱动。2）如果主机上明确只有单进程-多线程应用，可以将CCP直接绑定到vfio-pci驱动进行使用，从而省去安装HCT驱动的步骤。注意：如果主机内核为4.10以下，无mdev模块，需绑定vfio-pci驱动使用。

### Q: 如何使用vfio-pci驱动？

A: 执行如下命令，其中，`-m`指定驱动类型，默认为hct

```
hctconfig start -m vfio-pci
```

## 2. PSP-CCP 与 CCP 绑定

### Q: 如何使用PSP-CCP？

A: 使用PSP-CCP，需要BIOS中进行设置，将PSP-CCP配置给x86使用，配置方法如下： 开机进入BIOS, `HYGON CBS -> Moksha common option -> Available PSP CCP VQ count` 把该选项设置为`4`。若BIOS中无此选项，请联系供应商进行BIOS升级。

若CPU为海光4G，并且满足BIOS PI版本`4.2.0.7`，固件版本`2155`或更新，即使BIOS中无VQ配置选项，我们可以通过hag工具配置，使用方法详见[PSPCCP配置VQ指导文档](../6-PSPCCP配置VQ指导文档.md)

### Q: PSPCCP配置VQ，所设置的4是什么含义？

每个CCP总共有5个队列通道，用于主控向CCP发送加解密操作的command。默认状态下，对于PSPCCP，5个队列通道均只有PSP安全处理器可以使用。配置4，表示将其中4个队列通道授权给C86使用，预留1个给PSP处理器使用。

理论上用户可以配置1~4，但实际上，我们不建议用户尝试别的参数，其它参数可能影响C86下使用CCP的性能。

### Q: 为何3000系列机器中，只能使用一个CCP？

A: 默认情况下，hctconfig会尽可能多的绑定CCP，但总是会预留一个PSP-CCP给内核驱动，这是因为考虑到TKM等其他安全产品需要。而3000系机器上只有两个CCP(NTB-CCP,PSP-CCP)，除去预留的，故而默认只绑定了一个CCP使用。同样道理，5000系，7000系设备上，默认绑定的CCP总是少1个。若您明确表示没有其他业务的需求，只使用HCT，可以将所有CCP都绑定到HCT驱动/vfio-pci驱动中使用。可使用参数`-n all`强制绑定所有CCP，完整命令如下

```
hctconfig start -n all
```

## 3. 驱动绑定与 IOMMU

### Q: 绑定驱动错误：cannot open /sys/bus/pci/drivers/hct/bind

A: 该问题一般是由于设备iommu未打开导致，可通过内核日志：`dmesg | grep hct` 查看是否有`iommu disable`相关信息，若确认，请开启iommu后重试。iommu需确保BIOS以及内核启动项均开启：

- BIOS设置路径：HYGON CBS → NBIO Common Options → NB Configuration → IOMMU
- 内核启动项：GRUB\_CMDLINE\_LINUX 添加 `amd_iommu=on`设置完成后，请更新grub并重启机器。

### Q: insmod hct或者vfio-pci内核模块失败

A: 在已编译完成HCT或已存在了vfio-pci驱动的情况下，insmod失败或者绑定CCP设备失败最常见的情况是BIOS或者grub未打开IOMMU，可以按照下述方法使能IOMMU：dmesg | grep IOMMU检查IOMMU是否开启cat /proc/cmdline检查是否在grub启动参数添加了iommu=off在BIOS界面检查IOMMU是否为enable状态，设置路径如下：HYGON CBS→NBIO Common Options →NB Configuration→IOMMU

### Q: IOMMU开启后，绑定驱动失败

用户已确认开启IOMMU，但执行`hctconfig start` 依然失败，并提示`Error: bind failed for 0000:ef:00.1 - Cannot bind to driver hct`

A: 请执行`dmesg|grep hct`查看内核日志，若出现类似如下日志，该问题很可能是由于BIOS中关闭了PCIe ACS选项导致的。

```
hct: iommu attach device return
hct: probe of 0000:ef:00.1 failed with error -22
```

ACS选项的关闭，将导致系统启动后，不同的pci设备被添加到同一个group，如下所示（通过`dmesg|grep iommu`查看），进一步导致hct驱动无法绑定。

```
pci 0000:f7:00.0: Adding to group 66
pci 0000:f7:00.1: Adding to group 66
```

解决办法：BIOS中将ACS选项enable。（ACS选项往往和IOMMU选项在同一级路径下，即NBIO Common Options中）

### Q: 执行hctconfig start失败？

hctconfig 脚本执行失败，会有相应的错误日志输出，以下列出了几点常见的排查点：

- 未安装python2，或已安装但python2部分模块缺失
- 未正确安装HCT驱动，例如编译安装驱动过程中，只执行了make，未执行make install。
- 所安装的驱动与内核版本不一致，可通过`modinfo`命令查看`hct.ko`模块信息，对比`vermagic`是否与当前内核一致。

Tips: 驱动安装后可通过执行`sudo modprobe hct`确认HCT是否安装成功。

### Q: 执行hctconfig start未报错误，但无ccp被绑定？

该问题是由于hctconfig工具无法通过关键字检测到ccp设备导致，可通过使用`hct_ccp_bind.py -s`命令查看CCP设备信息来进行确认。

- 通常出现该问题情况下，设备信息显示格式如下：

```
Other Crypto devices
====================
0000:03:00.2 'Device 1456' unused=ccp,vfio-pci,hct
0000:04:00.1 'Device 1468' unused=ccp,vfio-pci,hct
...
```

设备信息中缺失`PSP`或`NTB`关键字，导致hctconfig工具无法解析出CCP. 其根本原因是由于系统裁剪等行为导致`lspci -Dvmmnnk`命令无法查看完整的pci设备的描述信息。

- 正常情况下，设备信息显示格式如下

```
Other Crypto devices
====================
0000:03:00.2 'PSPCCP Command DMA Processor 1456' unused=ccp,vfio-pci,hct
0000:04:00.1 'NTBCCP 1468' unused=ccp,vfio-pci,hct
```

解决办法：

- 更新系统的`hwdb.bin`文件(可以从能正常显示的设备中拷贝)，从而使得`lspci -Dvmmnnk`能够获取到完整的设备信息
- 修改hctconfig脚本，bind\_ccp中，检索CCP的grep条件，如将关键字PSP替换为1456，NTB替换为1468（注：部分机型CCP设备ID还包括1537和1486，需根据实际情况作调整）。

### Q: lack of necessary kernel modules？

该问题出现在执行`hctconfig start`后，其原因是由于模块加载失败导致，可参考2.2节确认HCT驱动环境是否安装成功。

### Q: invalid node id 255？

该问题是由于无法获取CCP设备的numa\_node导致，可通过如下命令进行确认（将命令中pci替换为本机CCP设备）：

```
cat /sys/bus/pci/devices/0000\:03\:00.0/numa_node
或
numactl -H
```

- 请通过`cat /proc/cmdline` 查看本机是否设置了numa=off，若设置了，请配置为numa=on.
- 请查看BIOS(`HYGON CBS → DF Common Options → Numa Mode`)中Numa Mode选项是否被disable（注：部分bios可能没有该选项）.
- 查看BIOS(`HYGON CBS → DF Common Options → Memory Interleaving` 或 `HYGON CBS → DF Common Options → Numa Mode → Memory Interleaving`) 中的Memory Interleaving，将其设置为auto模式.

测试阶段可采用如下命令手动为CCP分配numa\_node，以此workaround

```
echo 0 > /sys/bus/pci/devices/0000\:03\:00.0/numa_node
```

注意：HCT1.0.1版本不支持numa\_node非法的情况下使用；HCT1.1.0版本将支持非法numa\_node（值为-1）情况下使用。

## 4. 编译、证书与初始化

### Q: 证书检查失败 Validation Failed

A: 该信息随后会跟随 `Please download and install the Hygon General Security Certificate.`提示该错误信息是由于主机未安装通用安全证书所致，请参考 [导入通用安全证书](../../1-安全功能环境配置/2-导入通用安全证书.md) 进行安装

若完成上述步骤，通过hag工具查询的证书安装成功，但是错误依然存在，则表明当前的测试环境，缺少海光ccp内核patch（日志会提示/dev/sev找不到），此时我们可以进一步通过升级固件解决，升级方式可参考文档[安全固件动态升级](../../5-海光安全工具手册/1-安全固件动态升级.md)

Tips: 使用安全产品均需要安装通用安全证书。

### Q: HCT驱动编译失败

使用HCT发布包中的Makefile安装HCT驱动失败，可排查以下几点：

- 确保内核版本4.10以上；
- 确认内核中mdev，vfio-mdev模块是否被裁剪，若裁剪将导致驱动链接过程中无法找到对应的依赖。

### Q: Can't open /dev/sev!？

该信息出现在HCT1.0.1及之前的版本，是HCT进行通用安全证书检查过程中所报，其根本原因是由于所使用的内核未添加CSV功能patch所致（HCT1.0.1证书检查依赖于该内核patch），请更新至包含CSV功能的内核，推荐内核: [安全操作系统和内核](<../../01. 机密计算/02. 用户指南/01. 环境部署/02. 安全操作系统.md>)

### Q: hct\_ccp\_init fail -1？

初始化失败常见的原因：

- 证书未安装导致初始化失败。
- 未绑定驱动的情况下使用HCT，可通过`hctconfig status`确认CCP驱动是否已绑定到HCT驱动或vfio-pci驱动。
- 未使用正确版本的驱动，系统中存在老版本驱动，请更新到最新驱动使用。
- 未使用root权限运行。HCT1.0.1及之前的版本要求root权限下使用，HCT1.1.0开始支持user用户权限使用。

## 5. 功能测试与 OpenSSL 兼容

### Q: hct\_test 执行提示 Undefined Symbol EVP\_sm4\_xxx

A: 该问题是由于系统自带的openssl不支持国密导致。部分OS厂商发布的系统中，尽管通过命令`openssl version`所查出的版本是符合的，但其自带的openssl并没有将国密接口编译进去。可通过如下命令查看库中是否有国密符号。`objdump -t ${OPENSSL_INSTALL_PATH}/libcrypto.so |grep sm4 `若符号缺失，请重新下载openssl编译安装。

### Q: hct\_test 部分用例失败？

该情况表现为部分测试用例成功，部分失败。该问题一般出现在麒麟系统上，其原因是由于麒麟系统自带的openssl sm2国密接口与标准版本有差异导致。请下载社区标准版本OpenSSL（1.1.1c或更新）重新编译安装后使用HCT。
