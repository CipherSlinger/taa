# 06-PGO与BOLT用户指南

> 本指南提供 HCC 编译器 PGO 与 BOLT 的详细用法及海光平台参数配置指导方法。PGO(Profile-Guided Optimization)为编译期反馈优化，BOLT(Binary Optimization and Layout Tool)为二进制级布局优化，两者均基于程序运行时的特征数据，可单独或叠加使用。

## 1. 概述

### 1.1. PGO/BOLT概述

PGO 是一种基于程序运行时特征数据进行性能优化的技术。相较于传统的静态编译技术，它能提前获取运行时数据(函数调用频率、代码块执行次数、分支方向偏好等)，让编译器做出更好的优化决策,从而生成执行效率更高的二进制。

BOLT(Binary Optimization and Layout Tool)是基于 LLVM 框架的后链接优化器，在程序编译完成之后,通过运行时采集的性能数据(profile)重新排列函数和基本块,优化指令缓存、分支预测和调用路径,从而提升性能。BOLT 优化效果最明显的应用是有许多指令缓存和 iTLB 未命中的程序，常见于大小超过数百 MB 的大型应用程序；在 FDO 和 LTO 构建的高度优化二进制基础上，BOLT 能进一步提高程序性能,是对传统编译器优化的补充。

### 1.2. 二者的定位与区别

| 维度 | PGO | BOLT |
|---|---|---|
| 作用阶段 | 编译期(需重新编译) | 链接后(直接改写二进制，无需重编译) |
| 优化内容 | 指导编译器内联、布局、分支概率、代码生成等决策 | 函数/基本块布局重排、冷热代码拆分 |
| 数据来源 | 插桩计数器 / 采样(perf) | 插桩计数器 / LBR 采样 |
| 适用程序 | 代码结构复杂、分支多、函数调用密集的程序 | 体积大、指令缓存/iTLB 压力大的程序 |
| 组合使用 | 可先 PGO 再 BOLT，进一步挖掘性能 | 同左 |

## 2. PGO使用指南

### 2.1. PGO方案选择

| 方案 | 数据来源 | 精准度与优化潜力 | 运行时开销 | 使用方式 |
|---|---|---|---|---|
| -fprofile-generate | 中端 IR 插入计数器 | 高 | 中等 | 编译两次(插桩→运行→再编译) |
| -fcs-profile-generate | 中端 IR 计数器 + 函数调用上下文 | 最高(大型项目优势明显) | 中等偏高 | 编译两次 |
| -fprofile-instr-generate | 编译器前端插桩 | 较低(LLVM 已不推荐) | 高 | 编译两次 |
| 采样式 PGO | perf 等采样工具 | 中等(有环境噪声) | 低 | 编译→运行采样→反馈编译(可迭代) |

> 重要限制：采样式 PGO 依赖 LBR(Last Branch Record)信息构建调用链,目前 Hygon 平台暂不支持采集 LBR 信息,采样式 PGO 暂不可用。当前推荐使用插桩式 PGO。

### 2.2. 插桩式PGO全流程

第一步：编译插桩版本。在编译选项中加入：

```
# 标准中端 IR 插桩
-fprofile-generate=<存放插桩信息的目录>
# 上下文相关的中端 IR 插桩(大型项目推荐)
-fcs-profile-generate=<存放插桩信息的目录>
```

第二步：运行程序，收集插桩信息。让程序在接近真实生产环境的负载下运行，收集足够的样本量。

第三步：整理运行信息。使用 `llvm-profdata` 合并原始数据(版本需与编译器 LLVM 版本一致)：

```
llvm-profdata merge -o <dir>/default.profdata <dir>/*.profraw
```

第四步：基于插桩信息重新编译：

```
-fprofile-use=<dir>/default.profdata
```

### 2.3. 多进程程序的profile收集

多进程(如 MPI)场景下，需设置 `LLVM_PROFILE_FILE` 防止各进程相互覆盖：

```
export LLVM_PROFILE_FILE="/PATH/grapes-%m-%p.profraw"
ulimit -s unlimited
mpirun -np 192 --map-by core --bind-to core ./your_app
# 合并多进程 profraw
llvm-profdata merge -output=app.profdata *.profraw
# 验证数据有效性
llvm-profdata show -detailed-summary app.profdata
# 基于 profile 重新编译
-fprofile-use=/PATH/app.profdata -Wno-profile-instr-unprofiled
```

### 2.4. 采样式PGO（平台支持 LBR 后可用,当前仅供了解）

```
# 1. 编译时添加采样所需调试信息
-fdebug-info-for-profiling -funique-internal-linkage-names
# 2. perf 采样(采集分支事件,-b 依赖 LBR)
perf record -b -e cpu/event=0xc4,umask=0x0,name=br_inst_retired_taken/ <运行指令>
# 3. 生成 profile
llvm-profgen --binary=<二进制程序> --output=<目录>/xxx.prof --perfdata=<dir>/perf.data
# 4. 基于采样数据编译
-fprofile-sample-use=<dir>
```

### 2.5. 采集数据的注意事项

PGO 的优化效果很大程度上取决于收集信息时的程序运行特征与实际运行特征是否相似：采集时程序的输入数据应尽可能与真实运行一致(如 SPEC 使用 ref 数据集测试，则采集时也用 ref 数据集)。

适合 PGO 优化的程序特征：

- 有大量多层次循环、循环体巨大、分支多且复杂
- 同一函数多处调用、函数多但无明确热函数、热函数代码量少
- 热区域在多个较大代码块中反复跳转执行

## 3. BOLT使用指南

### 3.1. 前置条件

BOLT 在二进制层面做布局优化，需要重定位信息定位函数。编译/链接时需添加：

```
# 必需:保留输出重定位信息(BOLT 依赖它定位函数、改写二进制)
-Wl,--emit-relocs
# 完整写法(追加 -z now,供 BOLT 的 PLT 调用优化 --plt 使用)
-Wl,-z,now -Wl,--emit-relocs
```

验证重定位信息是否保留成功：

```
readelf -S your_app | grep -E '\.rela?\.text'
```

### 3.2. 收集profile的两种方式

| 方式 | 命令 | Hygon 平台可用性 |
|---|---|---|
| LBR 采样 | perf record -e cycles:u -j any,u -o perf.data -- \<exe\> \<args\> | 不可用：Hygon 硬件仅支持 1 个 LBR，不支持 -j any,u，采集的 perf 数据无 branch records，对 BOLT 无效 |
| 插桩 | 运行 llvm-bolt -instrument 生成的插桩版二进制;采集数据写入插桩时指定的路径(未指定时为默认值 /tmp/prof.fdata),建议用 --instrumentation-file 显式指定到统一目录 | 可用，推荐 |

> 因此，在海光平台上推荐使用插桩方式收集 BOLT profile

### 3.3. 插桩式BOLT全流程说明

采集数据的输出路径由插桩时的 --instrumentation-file 参数决定(写入插桩版二进制,运行程序时按该路径写出);若未指定,则使用 llvm-bolt 的默认值 /tmp/prof.fdata。建议插桩时就显式指定到统一的工作目录(下文统一使用 $HOME/bolt-profile,请替换为实际路径),避免 /tmp 被清理、多用户或多节点写偏等问题。

#### 3.3.1. 单次采集（基础流程）

```
# 0) 约定工作目录与文件名(以下各步骤统一使用)
export BOLT_PROFILE_DIR=$HOME/bolt-profile
mkdir -p "$BOLT_PROFILE_DIR"

# 1) 生成插桩版二进制,并指定采集数据的输出路径与文件名
llvm-bolt your_program -instrument \
    --instrumentation-file="$BOLT_PROFILE_DIR/prof.fdata" \
    -o your_program.instrumented

# 2) 运行插桩版程序(真实负载);程序结束时数据写入指定文件
./your_program.instrumented [程序参数]
ls -l "$BOLT_PROFILE_DIR/prof.fdata"          # 确认采集文件已生成

# 3) 用采集数据生成优化后二进制(引用与第 2 步完全相同的文件)
llvm-bolt your_program \
    -o your_program.bolt \
    -data="$BOLT_PROFILE_DIR/prof.fdata" \
    [优化参数,见 3.5 节]
```

两点说明:

- 若第 1 步省略 --instrumentation-file,数据默认写入 /tmp/prof.fdata;此时第 3 步可直接引用 -data=/tmp/prof.fdata,或先把文件取回工作目录( mv /tmp/prof.fdata "$BOLT\_PROFILE\_DIR/prof.fdata" )再引用——关键是第 3 步引用的文件与第 2 步实际生成的文件保持一致。
- 插桩版程序每次运行都会覆盖写目标文件(截断重写),上一轮数据不会保留;需要多轮/多进程数据时按下节流程处理。

#### 3.3.2. 多次采集与合并(样本更大、统计更稳定)

(1) 多进程(如 MPI):插桩时增加 `--instrumentation-file-append-pid`,BOLT 会在输出的插桩文件名后面自动追加当前进程的 PID(当前 LLVM 工具实际输出形如 `prof.fdata.<PID>.fdata`),避免各进程互相覆盖;运行结束后合并:

```
# 1) 生成插桩版二进制(每个进程写独立文件)
llvm-bolt your_app -instrument \
    --instrumentation-file="$BOLT_PROFILE_DIR/prof.fdata" \
    --instrumentation-file-append-pid \
    -o your_app.instrumented

# 2) 运行(各进程输出 $BOLT_PROFILE_DIR/prof.fdata.<PID>.fdata)
mpirun -np N --map-by core --bind-to core ./your_app.instrumented

# 3) 合并为单一 profile
merge-fdata -o "$BOLT_PROFILE_DIR/prof-merged.fdata" "$BOLT_PROFILE_DIR"/prof.fdata.*

# 4) 生成优化后二进制(引用第 3 步合并得到的文件)
llvm-bolt your_app \
    -o your_app.bolt \
    -data="$BOLT_PROFILE_DIR/prof-merged.fdata" \
    [优化参数,见 3.5 节]
```

(2) 单机多轮运行(未用 append-pid):每轮运行后立即将数据改名保存,避免被下一轮覆盖:

```
./your_program.instrumented ; mv "$BOLT_PROFILE_DIR/prof.fdata" "$BOLT_PROFILE_DIR/run1.fdata"
./your_program.instrumented ; mv "$BOLT_PROFILE_DIR/prof.fdata" "$BOLT_PROFILE_DIR/run2.fdata"
merge-fdata -o "$BOLT_PROFILE_DIR/prof-merged.fdata" \
    "$BOLT_PROFILE_DIR/run1.fdata" "$BOLT_PROFILE_DIR/run2.fdata"
# 之后 llvm-bolt 使用 -data="$BOLT_PROFILE_DIR/prof-merged.fdata"
```

> 合并的前提:所有 fdata 必须来自同一二进制(函数结构、ID、基本块 Hash 一致),合并为计数相加、线性开销;重新编译后的二进制数据不可与旧数据混合合并。

### 3.4. 多进程插桩的文件命名与合并说明

多进程(MPI)运行时,各进程若都写同一个文件会发生写入冲突,采集数据不可用;使用 `--instrumentation-file-append-pid` 后,BOLT 会在输出的插桩文件名后面自动追加当前进程的 PID(当前 LLVM 工具在 PID 后还缀 `.fdata`,即指定 `prof.fdata` → 实际输出 `prof.fdata.<PID>.fdata`),避免不同进程覆盖彼此的插桩文件。

```
merge-fdata -o "$BOLT_PROFILE_DIR/prof-merged.fdata" "$BOLT_PROFILE_DIR"/prof.fdata.*
```

### 3.5. 常用 BOLT 优化参数

| 参数 | 作用 |
|---|---|
| -reorder-functions=hfsort+ | 用 hfsort 算法重排函数,热点函数放连续内存,提升 CPU 缓存命中率 |
| -reorder-blocks=cache+ | 重排函数内基本块,热点块放一起,减少指令缓存(ICache)缺失 |
| -reorder-blocks=ext-tsp | 基于 ext-tsp 算法的基本块重排 |
| -split-functions | 拆分函数为热点部分和冷部分,热点部分优先加载 |
| -split-all-cold | 将所有冷代码拆分到单独内存区域 |
| -split-eh | 拆分异常处理路径 |
| -icf | 开启同一代码折叠,合并相同代码块,减小二进制体积并提升缓存效率 |
| -indirect-call-promotion=all | 间接调用提升(将间接调用转为直接调用) |
| -frame-opt=all / -frame-opt-rm-stores | 栈帧优化/消除冗余栈存储 |
| -peepholes=all | 开启全部窥孔优化 |
| -inline-all | 内联优化 |
| -eliminate-unreachable | 消除不可达代码 |

## 4. 实战案例：GRAPES全流程

### 4.1. PGO 优化(四步)

```
# 第一步:编译选项加入插桩
-fprofile-generate=/home/GRAPES/pgo-profile

# 第二步:设置 LLVM_PROFILE_FILE 并运行(多进程防覆盖)
export LLVM_PROFILE_FILE="/home/GRAPES/pgo-profile/grapes-%m-%p.profraw"
ulimit -s unlimited
export NO_STOP_MESSAGE=1 && time mpirun -np 192 --map-by core --bind-to core ./grapes_global_4.exe

# 第三步:合并 profraw
cd /home/GRAPES/pgo-profile
llvm-profdata merge -output=grapes.profdata *.profraw
llvm-profdata show -detailed-summary grapes.profdata   # 验证数据有效性

# 第四步:基于 profile 重新编译(路径替换为实际路径)
-fprofile-use=/home/GRAPES/pgo-profile/grapes.profdata -Wno-profile-instr-unprofiled
```

### 4.2. BOLT优化(六步)

```
# 第一步:准备工具(llvm-bolt 与 merge-fdata 同目录)

# 第二步:编译带重定位信息的程序
# 编译参数中加入:-Wl,--emit-relocs（或-Wl,-z,now -Wl,--emit-relocs）
readelf -S grapes_global_4.exe | grep -E '\.rela?\.text'   # 验证

# 第三步:生成插桩程序
llvm-bolt grapes_global_4.exe \
    -o grapes_global_4.exe.instrumented \
    --instrument \
    --instrumentation-file="/path/to/bolt-profile/grapes.fdata" \
    --instrumentation-file-append-pid

# 第四步:运行插桩程序
ulimit -s unlimited
export NO_STOP_MESSAGE=1 && time mpirun -np 192 --map-by core --bind-to core ./grapes_global_4.exe.instrumented

# 第五步:合并 bolt 数据(各进程输出 grapes.fdata.<PID>.fdata)
cd /path/to/bolt-profile
merge-fdata -o grapes-merged.fdata grapes.fdata.*
strings grapes-merged.fdata | head -100   # 验证数据有效性

# 第六步:生成 BOLT 优化程序
llvm-bolt grapes_global_4.exe \
    -o grapes_global_4_bolt \
    --data="/path/to/bolt-profile/grapes-merged.fdata" \
    --reorder-blocks=ext-tsp \
    --reorder-functions=cdsort \
    --reorder-functions-use-hot-size \
    --split-functions \
    --split-strategy=profile2 \
    --split-eh \
    --plt=hot \
    --dyno-stats \
    --print-profile-stats
```

## 5. 注意事项与常见问题

| 事项 | 说明 |
|---|---|
| Hygon 平台 LBR 限制 | 采样式 PGO 与 BOLT LBR 采样均依赖 LBR，Hygon 平台暂不支持，请使用插桩方式 |
| llvm-profdata 版本 | 应与编译器 LLVM 版本保持一致 |
| 插桩运行开销 | 标准插桩约 +53% 运行时间，上下文相关约 +32%，采集阶段需预留时间 |
| 采集负载一致性 | 采集时的输入数据应尽可能与真实运行一致，否则可能“优化错方向” |
| PGO/BOLT 非万能 | 部分课题无收益甚至负收益，需实测对比后决定是否采用 |
| 多进程冲突 | MPI 场景务必使用 LLVM\_PROFILE\_FILE (PGO)与 --instrumentation-file-append-pid (BOLT) |
| 编译器自身优化 | 用 PGO/BOLT 优化 clang/flang 编译器二进制本身(缩短编译时间)可借助 CMake cache 自动化流程 |
