# 04-编译选项参考手册

> 本手册分类列出 HygonCC 支持的全部自研编译选项，说明各选项的释义、效果、依赖/互斥关系、用法与典型适用场景，并注明与公版编译器选项的对齐关系。

## 1. 手册说明

### 1.1. 编译器选项驱动机制

HygonCC 的编译选项按作用阶段分为两类：

| 驱动形式 | 作用位置 | 示例 |
|---|---|---|
| -mllvm \[option\] | 编译阶段，作用于 LLVM 中端 Opt 优化器 | -mllvm -enable-gvaa |
| -Wl,-mllvm -Wl,\[option\] | 链接阶段(Link Time Optimize) | -Wl,-mllvm -Wl,-struct-compress |

> 链接阶段选项通常需要配合 `-flto` 使用

### 1.2. 公版选项对齐声明

- 所有公版(上游)编译选项的支持范围、语义与行为，与 LLVM 16.0.4 的 Clang 对齐；
- 此手册列出的通用选项均为公版选项，遵循 Clang 16.0.4 语义；自研选项为 HygonCC 独有，不影响公版选项行为。

## 2. 通用编译选项

### 2.1. 优化级别

| 选项 | 说明 | 备注 |
|---|---|---|
| -O0 | 不做任何优化，保留所有调试信息，编译最快 | 调试建议 |
| -O1 | 轻量优化：死代码删除、常量折叠等 | |
| -O2 | 启用几乎所有安全的优化，推荐的默认级别 | 及以上默认开启循环向量化与 SLP 向量化【官方依据】 |
| -O3 | 在 -O2 基础上增加循环展开、函数特化、向量化等激进优化 | 可能增大代码体积 |
| -Ofast | 启用 -O3 全部优化及可能违反严格语言标准的积极优化 | 谨慎使用 |
| -Os / -Oz | 优化代码体积 | |

### 2.2. 向量化与链接时优化

| 选项 | 说明 |
|---|---|
| -fvectorize | 开启循环向量化 |
| -fslp-vectorize | 开启 SLP 向量化 |
| -flto | 打开链接时优化 |
| -fopenmp | 启用 OpenMP 编译与运行时支持 |

## 4. 典型优化效果

HygonCC编译器在Spec2017、HPC应用中都有显著的性能提升。

核心课题效果总览（部分）：

- 关键改进:AVX-512 相关代码生成与代价模型优化等工作(架构特性类, 含跨 256 半区开销建模、k-mask 降级、gather 拆分等相关方向)
- 选用原因:目标即"修复 AVX2→AVX-512 切换回退,并进一步取得增益"。
- 对比基线:AVX-512 初始版本(即 AVX2 迁移后的初版)。

| 指标 | 效果 |
|---|---|
| fprate · 1 copy | 提升约 30%(AVX512 优化 vs AVX512 初始) |
| fprate · 1 node | 提升约 14%(AVX512 优化 vs AVX512 初始) |

## 5. 典型优化案例

### 5.1. 多级尾部向量化

场景与问题：循环向量化后，仍有较多样本落入尾部处理路径，尾部开销影响整体收益，该场景在spec2017 525/625课题上均有体现。

| 参数 | 说明 |
|---|---|
| -Wl,-mllvm -Wl,-enable-multi-level-epilogue-vectorization | 多级尾部向量化:主循环之后逐级以减半向量宽度处理剩余迭代 |
| -Wl,-mllvm -Wl,-enable-ext-type-widening | 扩展类型范围:将 zext/sext/fpext 结果类型纳入向量元素类型集合 |

- 选用原因:两个方案均针对尾部处理,但该课题实测差异明显——多级尾部向量化平均需经过约 4.5 个 check 基本块(引入更多控制流检查),扩展类型范围平均仅约 2 个;后者开销更小、收益更高。
- 效果:多级尾部向量化约 +7%(625 实测 6.73%~7.45%);扩展类型范围约 +9%(8.8%)。该优化在 525 课题同样验证:1copy 约 +9.1%、1node 约 +8.75%
- 通用性说明:均为通用优化选项

### 5.2. GROMACS 软件预取与 gather 指令拆分

背景与问题:GROMACS在使用 AVX-512 时未充分体现浮点峰值;分析定位两个方面:① 部分访存瓶颈需用软件预取缓解;② AVX-512 版本 gromacs 自带核函数中的 gather intrinsic 在 c86-4g-m7 / c86-4g-m8 上造成较大性能下降,需在后端将 gather 指令拆分。

| 参数 | 作用 |
|---|---|
| -mllvm -x86-enable-loop-random-data-prefetch | 针对循环中随机访存插入软件预取指令,提高 cache 命中率 |
| -mllvm -x86-split-gather-intrinsics | 拆分 gather 指令,优化海光平台上的访存指令 |

- 在gromacs不同算例上有较为明显的性能加速。
- 通用性说明:均为通用优化选项

### 5.3. WRF中端向量化优化

| 参数 | 作用 |
|---|---|
| -mllvm -enable-loop-dependency-split | 剥离原循环中含有循环携带依赖的部分,使剩余部分可以进行向量化 |
| -mllvm -enable-laa-global-object-bounds | 在 LAA 中为 non-AddRec 指针增加 fixed-size GlobalVariable 的保守边界回退机制;解决 fptosi(float) → sext → GEP 查表访问无法推导 bounds 导致向量化失败的问题 |

- 拓展可以做向量化的场景，在WRF应用上获得明显的性能提升。
- 通用性说明:均为通用优化选项
