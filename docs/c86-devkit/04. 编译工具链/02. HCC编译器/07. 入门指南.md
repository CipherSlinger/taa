# 03-入门指南

## 1. 快速上手

### 1.1. 确认安装

```
clang -v
# 预期输出包含海光版本标识,例如:
# clang version 16.0.4 (hcc 2.12.0-260309-4)
```

若提示找不到命令，请先按《安装指南》完成安装并加载环境。

### 1.2. 编译并运行第一个C程序

```
# 编写 hello.c
cat > hello.c << 'EOF'
#include <stdio.h>
int main() {
    printf("Hello, HygonCC!\n");
    return 0;
}
EOF
# 编译
clang hello.c -o hello
# 运行
./hello
# 输出:Hello, HygonCC!
```

C++/Fortran也是同样的流程。

## 2. 基础编译/链接/运行流程

### 2.1. 单文件编译

```
# C 程序
clang [flags] hello.c -o hello

# C++ 程序
clang++ [flags] hello.cpp -o hello

# Fortran 程序
flang [flags] hello.f90 -o hello
```

### 2.2. 分步编译与多文件工程

支持多文件链接：

```
# 只编译不链接,生成目标文件
clang [flags] -c hello.c -o hello.o
# 多文件链接
clang main.o foo.o -L/path/to/lib -lmylib -o app
```

相关选项：

| 选项 | 作用 |
|---|---|
| -I \<路径\> | 指定头文件搜索路径 |
| -L \<路径\> | 指定链接库搜索目录 |
| -l \<库名\> | 链接指定库(如 -lm 为数学库) |

### 2.3. 常用编译选项

| 类别 | 常用选项 | 说明 |
|---|---|---|
| 优化级别 | -O0 / -O1 / -O2 / -O3 | 调试建议 -O0,发布版本常用 -O2 或 -O3 |
| 调试信息 | -g | 生成调试符号,便于 gdb / perf 等工具使用 |
| 头文件/库 | -I / -L / -l | 指定 include 路径、库目录和链接库 |
| 并行 | -fopenmp | 启用 OpenMP 编译与运行时支持 |
| 目标 CPU | -march=native | 在 Hygon 平台自动选择最优目标指令集 |
| 数学优化 | -ffast-math | 放宽 IEEE 严格语义,启用更激进的数学优化 |

> `-ffast-math` 可能降低浮点计算精度，使用前请确认 fast-math 语义是否可接受

| 级别 | 说明 |
|---|---|
| -O0 | 不做任何优化,保留所有调试信息,编译速度最快,执行性能最差 |
| -O1 | 轻量优化,启用基本的、编译快速的优化,如删除死代码、常量折叠 |
| -O2 | 中等优化,启用几乎所有安全的优化,通常是推荐的默认级别,性能提升明显 |
| -O3 | 最高级别优化,在 -O2 基础上增加更激进的优化,如循环展开、函数特化、向量化等可能会增加代码大小 |
| -Os | 优化代码空间,基于 -O2,但优先优化可执行文件体积 |
| -Oz | 极简缩小优化,比 -Os 更激进 |

> `-O2` 及以上默认开启循环向量化与 SLP 向量化优化

### 2.4. 目标微架构选择

\# 自动识别当前海光处理器,选择最优目标指令集(推荐)，另外如显式指定微架构:支持 c86-4g-m4 / c86-4g-m6 / c86-4g-m7 / c86-4g-m8。

```
clang compute.c -O3 -march=native -o compute
```

\# 单独指定支持的指令集

```
clang compute.c -O3 -march=native -mavx2 -o compute        # AVX2
clang compute.c -O3 -march=native -mavx512f -o compute     # AVX-512
```

\# 向量化宽度选择(256/512)

```
clang compute.c -O3 -march=native -mprefer-vector-width=512 -o compute
```

### 2.5. 链接器选择

\# 默认使用系统 ld 链接器

```
clang [flags] hello.c -o hello
```

\# 使用 LLVM lld 链接器

```
clang [flags] -fuse-ld=lld hello.c -o hello
```

\# 打开链接时优化(Link Time Optimization)

```
clang [flags] -flto hello.c -o hello
```

### 2.6. 运行时库配置

```
# 64 位运行时库
export LD_LIBRARY_PATH=<compdir>/lib:$LD_LIBRARY_PATH

# 32 位运行时库
export LD_LIBRARY_PATH=<compdir>/lib32:$LD_LIBRARY_PATH

# 其他 Hygon 优化库
export LD_LIBRARY_PATH=<Path to Hygon optimizing lib>/Hygon-lib:$LD_LIBRARY_PATH
```

### 2.7. 推荐入门首选

\# 入门首选:基础优化 + 自动识别目标架构

```
clang main.c -O2 -march=native -o app
```

\# 追求极致性能:最高优化 + 快速数学(需确认 fast-math 语义可接受)

```
clang main.c -O3 -ffast-math -march=native -o app
```

## 3. 海光加速库的调用方法

### 3.1. 加速库总览

随发布件提供的加速库与运行时库如下(以实际安装包内文件为准)：

| 库文件 | 说明 |
|---|---|
| libhvml.so | 海光向量数学库 HVML,链接参数 -lvml-hg(包内 libhvml.so、libvml-hg.so、libhygonvml.so 为同一库的三个命名) |
| libhlm.so | 海光标量数学库 |
| libhjemalloc.so | 海光内存分配库 |
| libomp.so / libompstub.so | OpenMP 运行时库 |
| libpgmath.so | PG 数学库 |
| libflang.so | Flang 运行时库 |
| libquadmath.so / libstdc++.so / libgcc\_s.so | 四精度数学库 / C++ 标准库 / GCC 运行时 |

> 提示：目录内同时提供部分库的静态版本(.a)与带版本号的动态库(.so.1 等)；链接时使用上面的基础库名即可，由链接器自动选择对应版本。

### 3.2. 向量数学库HVML

作用：在循环内使用数学库函数计算时，做函数级别的向量化，调用向量版本的数学库函数，一次处理多个元素。

调用方式：

\# 编译时：-fveclib=HVML 启用 HVML 向量数学库<br># 链接时：链接 HVML 库 -lvml-hg

```
clang compute.c -O3 -march=native -ffast-math -fveclib=HVML -c -o compute.o
clang compute.o -lvml-hg -L/{Path_To_hvml}/lib -o app
```

> 库路径说明:按《安装指南》加载环境脚本(如 `source <安装目录>/hpc-setenv.sh hcc`)后,编译器的库搜索路径中已包含 HVML 库目录(`$HML_HOME/lib`),可直接使用 `-lvml-hg`;若未加载环境,则需显式指定 HVML 库目录(即实际安装目录下的 `hml/hcc/lib`)。例如安装目录为 `/opt/hygon` 时:clang compute.o -L/opt/hygon/hml/hcc/lib -lvml-hg -Wl,-rpath=/opt/hygon/hml/hcc/lib -o app
> 
> 兼容说明：包内该库同时以 libhvml.so(本体命名)、libhygonvml.so 提供(三个文件名指向同一库)，链接参数 -lhvml 同样可用；本文档统一使用 -lvml-hg。

### 3.3. 标量数学库

如需指定特定版本的标量数学库(如 glibc 2.32)，在链接时通过 -L 和 -Wl,-rpath 指定路径。

```
clang [flags] hello.o \
  -L/path-to-lib/glibc-2.32/lib \
  -Wl,-rpath=/path-to-lib/glibc-2.32/lib \
  -Wl,--dynamic-linker=/path-to-lib/glibc-2.32/lib/ld-linux-x86-64.so.2 \
  -o hello
```

> 注意:GLIBC 2.32 之前版本不识别海光平台，如需使用更早版本的 GLIBC，需要修改 loader 的 `dl_platform_init` 并重新编译 GLIBC 以识别海光平台

## 4. 最小工程示例

### 4.1. 工程结构

```
vector_demo/
├── vector_demo.c      # 主程序:向量数学计算
├── Makefile                # Make 构建脚本
└── CMakeLists.txt       # CMake 构建脚本
```

### 4.2. 源码实例vector\_demo.c

```
#include <stdio.h>
#include <math.h>
#define N 1000000
int main(void) {
    static double angles[N], val[N];
    double s = 0.0;
    /* 初始化 */
    for (int i = 0; i < N; i++)
        angles[i] = (i % 10) + 0.333;
    /* 核心计算:循环内调用数学函数,可被编译器向量化;
       配合 -fveclib=HVML 时可调用海光向量数学库 */
    for (int i = 0; i < N; i++) {
        val[i] = cos(angles[i]);
        s += val[i];
    }
    printf("Sum: %.4f\n", s);
    return 0;
}
```

> 说明：示例调用了数学库函数 cos，因此链接时必须链接数学库(-lm)；这一项已包含在下方的 Makefile 与 CMakeLists 中。

### 4.3. Makefile

```
CC = clang
CFLAGS = -O2
-march=native
LDLIBS = -lm
# 如需使用海光向量数学库 HVML,取消以下注释,并将 HVML_LIB 改为实际库目录:
# HVML_LIB = /path/to/hml/hcc/lib
# CFLAGS += -ffast-math -fveclib=HVML
# LDLIBS += -L$(HVML_LIB) -lvml-hg -Wl,-rpath=$(HVML_LIB)
all: vector_demo
vector_demo: vector_demo.o
    $(CC) $(CFLAGS) -o $@ $^ $(LDLIBS)
vector_demo.o: vector_demo.c
    $(CC) $(CFLAGS) -c $< -o $@
clean:
    rm -f vector_demo vector_demo.o
.PHONY: all clean
```

### 4.4. CMakeLists.txt

```
cmake_minimum_required(VERSION 3.10)
project(vector_demo C)
set(CMAKE_C_COMPILER clang)
set(CMAKE_C_FLAGS "-O2 -march=native")
# 如需使用海光向量数学库 HVML,取消以下注释,并将 HVML_LIB 改为实际库目录:
# set(HVML_LIB /path/to/hml/hcc/lib)
# set(CMAKE_C_FLAGS "${CMAKE_C_FLAGS} -ffast-math -fveclib=HVML")
# link_directories(${HVML_LIB})
add_executable(vector_demo vector_demo.c)
# 链接数学库 -lm
target_link_libraries(vector_demo m)
# 启用 HVML 时,再链接向量数学库(与上方注释对应):
# target_link_libraries(vector_demo vml-hg)
```

### 4.5. 编译、运行与验证

```
# 方式一:Make 构建
cd vector_demo
make
./vector_demo
# 输出:Sum: -24065.5991(示例输出,数值以实际运行环境为准)
# 方式二:CMake 构建
mkdir -p build && cd build
cmake ..
make
./vector_demo
# 输出:Sum: -24065.5991(示例输出,数值以实际运行环境为准)
```
