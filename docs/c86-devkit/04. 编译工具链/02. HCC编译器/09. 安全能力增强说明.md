# 05-安全能力增强说明

> 本文档说明 HygonCC 与公版上游基线(LLVM 16.0.4)相比，在稳定性、正确性与安全防护方面的增强情况、质量保障机制及已知风险。

## 1. 总体说明

HygonCC 的安全能力由四道防线构成:

1. 继承上游安全基线：以 LLVM 16.0.4 为基座，完整继承上游编译器的安全机制(栈保护、地址无关代码、sanitizer 支持等)；
2. 持续同步上游修复：基线之上持续同步上游维护版本的修复；
3. 自研安全护栏：在自研优化 Pass 中内置正确性与内存安全防护，防止优化本身引入风险；
4. 全流程质量保障：评审、门禁、三级测试、全量回归与故障跟踪闭环，保证进入发布版本的代码质量。

## 2. 安全重点工作

### 2.1. 上游对齐与维护修复同步

保持与上游 LLVM 16.0.4 基线的安全机制一致，并及时将上游维护版本的修复同步进 HCC，涵盖链接器参数处理、OpenMP 运行时错误处理、开发工具构建修复等类别。

### 2.2. 内存与精度安全防护

在自研优化 Pass 内部内置安全防护机制，从源头防止优化引入风险，代表机制：

- 内存安全护栏：对优化中追踪的指针进行来源(provenance)校验，来源不合法即放弃该变换，防止无效指针被错误优化导致越界访问；
- 精度安全护栏：近似计算类优化(如快速倒数)在用户未显式声明宽松浮点语义(fast-math)时，自动告警并忽略，防止无意中降低计算精度。

### 2.3. 回归测试用例修复

针对失败用例分类排查与核心修复：zlib/zstd 内核版本兼容、pipeline、SLP、Pointer-compress、前端 metadata、dhyana/dharma/HVML 新特性相关、libomptarget 模块 bug 等。

## 3. 质量保障机制

HygonCC 通过多道质量关卡保障进入发布版本的代码质量：

| 机制 | 说明 |
|---|---|
| Gerrit 代码评审 | 所有代码变更需评审合入，commit message 规范化 |
| DCN 补丁准入门禁 | 补丁合入前的自动门禁检查 |
| 三级测试 | 每个修复/特性均需通过功能测试、性能测试、集成测试后方可合入 |
| 全量回归体系 | 基于 llvm-lit + FileCheck 的 make check-all 全量回归，覆盖中端/后端/前端/sanitizer 等各组件 |
