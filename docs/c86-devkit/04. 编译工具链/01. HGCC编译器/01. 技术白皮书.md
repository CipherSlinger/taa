# hgcc 编译器技术白皮书

---

## 前言

在算力基础设施持续演进的背景下，处理器性能的充分释放不仅取决于硬件能力本身，更高度依赖编译器等基础软件对硬件特性的理解与利用水平。编译器已成为连接应用软件与处理器架构的关键枢纽，其性能与优化能力直接影响系统整体效率、能耗表现与业务稳定性。

hgcc 编译器是一款基于GCC 12.3.0深度演进、面向海光（Hygon）处理器平台优化的高性能编译器产品。hgcc 在保持 GCC 生态高度兼容的前提下，通过微架构感知优化、高性能运行库，帮助用户在无需修改源代码的情况下，充分释放海光平台的计算潜力。

---

## 1. 产品概述

### 1.1 产品定位

hgcc 是一款：

- 面向海光平台深度优化的高性能编译器
- 兼容 GCC 主流生态的企业级基础软件
- 面向服务器、HPC 与国产化应用场景的编译解决方案

hgcc 可作为 GCC 的直接替代工具使用，也可作为性能优化阶段的核心组件，广泛适用于数据库、中间件、科学计算、工业仿真、金融计算及国产化迁移场景。

---

### 1.2 核心优势

**高度兼容，低迁移成本**

- 完整继承 GCC 12.3.0 编译选项与使用习惯
- 支持 C / C++ / Fortran 及 OpenMP
- 无需修改源代码即可平滑迁移

**深度适配海光处理器**

- 微架构感知的指令调度与流水线优化
- 面向缓存层级与内存访问模式的专项优化

**性能可持续演进**

- 支持 LTO、PGO 等先进编译技术

---

### 1.3 组件构成

hgcc 以一套完整的工具链形态交付，各组件及其在交付包中的位置如下：

| 组件 | 内容 | 交付位置 |
|------|------|----------|
| 编译驱动 | `gcc` / `g++` / `gfortran` / `cpp` 及 `x86_64-linux-gnu-*` 别名，负责调度前端、汇编器与链接器 | `<install>/bin/` |
| 编译器前端 | C 前端 `cc1`、C++ 前端 `cc1plus`、Fortran 前端 `f951` | `<install>/libexec/gcc/x86_64-linux-gnu/12.3.0/` |
| 中端 / 后端 | GCC 优化器与海光（C86）微架构后端，负责体系无关优化与目标码生成 | 同上 |
| 二进制优化工具 | LLVM BOLT 工具集（`llvm-bolt` / `perf2bolt` / `merge-fdata`）及 BOLT 插桩运行库，用于链接后二进制重排优化 | `<install>/bin/`、`<install>/lib/libbolt_rt_*.a` |
| 运行时库 | OpenMP 运行时 `libgomp`、Fortran 运行时 `libgfortran`、四精度数学库 `libquadmath`、`libstdc++`、`libatomic`、`libsanitizer` 系列 | `<install>/lib64/` |
| 环境初始化脚本 | `setenv_hgcc.sh`，用于注入 PATH / 编译器变量 / 库与头文件搜索路径 | `<install>/setenv_hgcc.sh` |

---

### 1.4 与上游 GCC 的基线关系

hgcc 以**上游 GCC 12.3.0** 为基线深度演进，源码维护于 `hygon-12.3.0` 分支。

**版本号规则**

版本号遵循《海光二进制包名、版本号、BUILDID 统一规则》：

```
hgcc-<GCC基线版本>-<BUILDID>.<model step>.<架构>.tar.gz
      └ 12.3.0        └ 260901      └ 4      └ x86_64
```

各字段含义如下：

| 字段 | 示例 | 含义 |
|------|------|------|
| GCC 基线版本 | `12.3.0` | 所基于的上游 GCC 版本 |
| BUILDID | `260901` | `26` = 2026 年，`09` = 9 月，`01` = 当月第 1 次合入/构建 |
| model step | `4` | 目标 CPU 型号标识 |
| 架构 | `x86_64` | 目标平台 |

例如 `hgcc-12.3.0-260901.4.x86_64.tar.gz` 表示：基于 GCC 12.3.0 基线，2026 年 9 月第 1 次合入/构建，CPU 型号标识为 4，x86\_64 架构。

**兼容性**

- 编译命令、选项体系与使用习惯完整继承 GCC 12.3.0，可作为其直接替代品（drop-in replacement）
- 生成代码的 ABI 与 GCC 12.3.0 一致，可与 GCC 12.3.0 编译的目标文件、静态库、动态库混合链接
- 已安装的第三方库、构建系统（Make/CMake/Autotools/Meson）无需改造即可切换

**相对上游的差异**

| 差异类别 | 具体内容 |
|----------|----------|
| 新增微架构目标 | `-march=c86-4g-m4`、`-march=c86-4g-m7`，并支持 `-march=native` 自动识别海光平台 |
| 默认优化策略调整 | 部分增强特性仅在 `-O3` 及以上优化级别自动启用，避免影响 `-O2` 的编译时间与代码体积 |
| 上游缺陷修复 | 修复 loop unswitch、循环向量化、自动并行化、循环不变量外提等上游缺陷（详见本文档"公版编译器漏洞修复"章） |
| 二进制优化能力 | 集成 LLVM BOLT，提供链接后二进制布局优化能力，上游 GCC 不包含 |

### 2.1 编程语言与并行模型

hgcc 聚焦企业级与高性能计算主流技术栈：

- C / C++
- Fortran
- OpenMP 并行程序（C/C++/Fortran）

**语言标准支持**

语言标准的支持范围与基线 GCC 12.3.0 保持一致：

| 语言 | 默认标准 | 可选标准 |
|------|----------|----------|
| C | `-std=gnu17` | C89 / C99 / C11 / C17 / C2x（部分特性） |

```bash
gcc   -std=c17      hello.c  -o hello
g++   -std=c++20    hello.cc -o hello
gfortran -std=f2008 hello.f90 -o hello
gcc   -fopenmp      omp_demo.c -o omp_demo
```

适用于以下典型应用类型：

- 高性能计算（HPC）
- 数值仿真与工程计算
- 数据分析与金融计算

## 3. 编译器体系与工作机制

在常规非 LTO 模式下，`gcc` / `g++` / `gfortran` 作为完整的编译驱动程序，按以下流程依次调度各前端、汇编器与链接器：

| 语言 | 前端 | 编译流程 |
|------|------|----------|
| C | `cc1` | 预处理 → 编译优化 → 生成汇编 → 汇编器 `as` → 链接器 `ld` / `collect2` |
| C++ | `cc1plus` | 同上 |
| Fortran | `f951` | 同上 |

启用 LTO 时流程有所不同：前端产出的不再是汇编代码，而是承载 GIMPLE 中间表示的目标文件；链接阶段会读入全部中间表示，执行跨编译单元的全程序分析（WHOPR 模式下进一步拆分为 LGEN / WPA / LTRANS 三阶段并行处理），再分发回各编译单元完成优化与代码生成，最终交由链接器完成常规链接。

该体系在保证稳定性的同时，为性能优化提供了充足空间。

## 4. 性能优化能力

### 4.1 通用优化能力

hgcc 支持 GCC 全部主流优化等级：

- `-O0`：调试友好
- `-O1 / -O2`：通用性能优化
- `-O3 / -Ofast`：面向极致性能的激进优化

可满足从功能验证到性能调优的不同阶段需求。

---

### 4.2 自动向量化与循环优化

hgcc 针对计算密集型程序进行了增强：

- 自动循环向量化与 SLP 向量化
- 软件预取优化，减少内存访问延迟
- 循环结构识别与执行路径优化

在数值计算和矩阵运算场景中效果尤为显著。

---

## 5. 高级优化技术

### 5.1 链接时优化（LTO）

hgcc 支持链接时全程序优化，可在链接阶段获得跨文件调用关系，实现：

- 跨模块内联
- 全局调用图分析
- 更优的代码布局与函数划分

适合大型工程和复杂软件系统。

---

### 5.2 反馈式优化（PGO）

通过真实运行数据引导编译优化决策，hgcc 能够：

- 提升分支预测准确率
- 优化热点代码布局
- 改善内联与寄存器分配策略

在实际业务负载下显著提升性能稳定性。

---

### 5.3 二进制优化（BOLT）

hgcc 集成了 LLVM BOLT（Binary Optimization and Layout Tool），可在链接完成后对最终二进制做进一步的布局优化，这是上游 GCC 所不具备的能力：

- **剖面获取**：既可用 `perf2bolt` 基于 `perf` 采样数据转换，也可用 `llvm-bolt -instrument` 插桩运行获取更精细的执行剖面
- **布局重排**：依据真实执行剖面重新排布函数、基本块与跳转指令，改善 I-cache 与 TLB 局部性
- **配套工具**：`llvm-bolt`、`perf2bolt`、`merge-fdata`，以及插桩运行库 `libbolt_rt_instr.a`、`libbolt_rt_hugify.a`

BOLT 与 PGO 互补：PGO 指导编译器在生成阶段优化，BOLT 则在链接后对既有二进制直接优化，适用于难以重新编译或希望进一步提升性能的场景。

---

## 6. 微架构感知优化

hgcc 支持通过 `-march` 选项指定目标微架构，实现对海光处理器的精细化调优：

| 海光平台 | 编译选项 |
|---------|----------|
| 海光 4G | `-march=c86-4g-m4` |
| 海光 4G 升级版 | `-march=c86-4g-m7` |

编译器将基于目标平台的指令特性和流水线结构生成更高效的代码。

### 7.1 数学库

- 减少内存碎片
- 提升高并发与内存密集型场景性能
