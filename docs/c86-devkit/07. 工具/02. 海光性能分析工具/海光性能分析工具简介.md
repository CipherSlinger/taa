# 简介

HPT(Hygon Performance Tuner)是一款专为Hygon服务器设计的性能分析工具，现阶段仅支持在Linux系统上运行。这款工具集成了多种功能，以便全面而深入地分析服务器的性能状况。

## HPT功能分类

根据分析场景，HPT 的 11 项子功能分为以下四类，用户可按需选择：

### 系统概况

> 全面了解服务器的硬件配置与性能基线。
> 适用场景：**新机器上线验收**、**系统配置审计**、**性能基准评估**。

* [system](#system): 采集系统详细配置信息（BIOS版本、操作系统、CPU型号、内存拓扑、网卡型号、磁盘布局等），同时测试内存带宽/延迟、FLOP、IPC等关键性能指标，为用户提供系统整体性能概览。

### 硬件分析

> 深入分析CPU缓存、DF（Data Fabric）互连等硬件层面的PMU性能指标。
> 适用场景：**硬件性能问题排查**、**CPU/内存性能监控**、**性能基线建立**。

* [collect](#collect): 采集CPU、L3 Cache和DF等组件的PMU性能事件，支持按系统/进程/命令维度、Socket/CCX/CPU粒度灵活采集，帮助用户掌握硬件运行状态与性能瓶颈。

### 软件分析

> 覆盖操作系统、运行时和应用层面的性能分析，包括进程资源、网络、Java、调度、热点、内存访问等维度。
> 适用场景：**应用性能调优**、**资源瓶颈定位**、**代码优化方向指导**。

* [process](#process): 收集各进程对CPU、内存、存储IO等资源的消耗情况，包括使用率、饱和度、错误次数等关键指标，帮助识别资源热点与竞争瓶颈。
* [network](#network): 收集网卡的整体收发包统计、单队列收发包统计以及硬中断/软中断统计，用于分析网络吞吐与延迟瓶颈。
* [java](#java): 收集Java进程的CPU、内存等资源使用率，获取类加载、热点代码编译等信息，助力Java应用性能调优。
* [sched](#sched): 收集进程/线程的调度时延、CPU切换链路以及冷火焰图等数据，帮助识别调度延迟与CPU争抢问题，优化系统调度策略。
* [hotspot](#hotspot): 基于 PMU 采样分析 C/C++ 程序的 on-CPU 热点，并结合调度事件展示 off-CPU 状态、调用链、HTML 时间线和火焰图，帮助定位计算热点与等待/阻塞问题。
* [lock](#lock): 采集用户态/内核锁事件，分析锁等待、持有、调用点和调度关联，帮助定位并发程序中的锁竞争与长尾等待。
* [mem](#mem): 分析程序访存行为，包括进程本DIE访存和跨DIE访存次数、伪共享检测等，帮助开发者优化NUMA架构下的内存访问模式。

### HPC业务分析

> 面向高性能计算场景，结合计算/访存瓶颈诊断与并行通信剖析。
> 适用场景：**HPC应用性能优化**、**计算/访存瓶颈诊断**、**MPI通信剖析**、**多节点负载均衡分析**。

* [roofline](#roofline): 通过Roofline模型可视化分析程序性能瓶颈，将浮点运算能力与DRAM带宽结合，以图形方式判断程序是计算密集还是访存密集，指导优化方向。
* [mpi](#mpi): 无侵入式采集各rank的MPI API（调用次数、通信量、耗时）以及各节点的CPU性能指标（IPC、CPU利用率、Cache Miss率等），生成多维度的文本和HTML报告，帮助开发者快速定位通信热点问题。

通过以上四类功能的组合使用，HPT为Hygon服务器用户提供了覆盖「系统 → 硬件 → 软件」全链路的性能分析能力，助力用户快速定位性能瓶颈、精准优化系统与应用的运行效率。

## 支持的平台

海光1号，海光2号，C86-3G，C86-4G，C86-4H。

## 目录结构

HPT 工具包的目录结构及组成如下，包含 `hpt` 命令行工具和`DF PMU API`开发库：

``````
hpt/
├── hpt                 	# 下发命令的接口
├── bash_completion.sh   	# 配置命令行自动补全的脚本
├── get_all_configs.sh  	# 一键收集系统的详细配置信息的脚本
├── get_all_collect_data.sh	# 一键收集常用的PMU指标脚本
├── get_all_software_data.sh	# 一键收集常用的软件性能数据脚本
├── driver/              	# hygon-uncore驱动
│   ├── hygon_uncore.c
│   └── Makefile
├── configs/             	# 自定义采集规则配置示例目录
│   └── customized.xml   	# 自定义采集事件的输入配置文件模板（XML格式）
├── docs/                	# 文档目录
│   ├── README           	# 工具包使用说明文档
│   └── ChangeLog        	# 版本迭代记录文档（按时间倒序排列更新内容）
└── libs/                	# DF PMU API开发库及示例目录（支持C++集成开发）
    ├── examples/               # 静态库使用示例代码
    ├── include/                # 开发所需头文件
    │   ├── df_api.h            # DF PMU接口头文件
    │   ├── df_data_types.h     # DF 数据结构定义头文件
    │   ├── core_data_types.h   # CORE/L3 数据结构定义头文件
    │   └── core_api.h          # CORE/L3 PMU接口头文件
    ├── lib/                    # 静态链接库文件
    │   └── lipcm.a             # lib API 静态库（Linux静态库格式）
    ├── Makefile                # 示例代码编译脚本（支持make命令构建）
    └── README                  # 开发库API文档
``````

## 版本安装

### 安装命令

 - RPM 包：

 ``````
 sudo rpm -ivh HPT-<version>.x86_64.rpm
 ``````

 - DEB包：

 ``````
 sudo dpkg -i hpt_<version>_amd64.deb
 ``````

默认安装路径为/opt/hygon目录。

## 环境配置

 - 执行source bash\_completion.sh，配置命令自动补全。
 - 执行HPT和一键收集脚本时，需要root权限。
 - 工具存放点目录路径不要有中文字符

## 快速开始

| 功能 | 典型场景 | 示例命令 |
|------|---------|---------|
| **system** | 查看系统配置与性能基线 | `sudo ./get_all_configs.sh` |
| **system** | 采集CPU重负载下全核频率 | `sudo hpt system --freq 0` |
| **system** | 采集CPU轻负载下频率变化 | `sudo hpt system --freq 1` |
| **collect** | 采集CPU缓存PMU指标（按DIE粒度） | `sudo hpt collect -m ipc,l1,l2,l3 -d 3 -A die` |
| **collect** | 监控DIE内存带宽并导出CSV | `sudo hpt collect -m cm -I 1 -d 3 --csv -o output` |
| **process** | 分析进程CPU/内存/IO/系统调用 | `sudo hpt process -c -m -s -S -I 1 -n 2 -p $PID` |
| **network** | 分析网卡收发包与中断统计 | `sudo hpt network -i enp51s0f1` |
| **java** | 分析Java进程资源与热点代码 | `sudo hpt java -p 88805 -c "thread;memory"` |
| **sched** | 分析调度时延与CPU切换 | `sudo hpt sched -d 5 -o "$OUTPUT"` |
| **hotspot** | 定位 C/C++ 的 CPU 热点、等待状态与调用链 | `sudo hpt hotspot -f 500 -g --html -- ./app` |
| **lock** | 定位锁竞争、长时间持锁与调度关联 | `sudo hpt lock --sched-mode 1 -- ./app` |
| **mem** | 检测伪共享与跨DIE访存 | `sudo hpt mem -d 5 -c2c -p $PID` |
| **roofline** | 诊断计算密集 vs 访存密集瓶颈 | `sudo hpt roofline --record survey -o "$OUTPUT" -- $COMMAND` |
| **roofline** | 生成Roofline分析报告 | `sudo hpt roofline --report -i "$OUTPUT"` |
| **mpi** | 采集MPI通信与节点PMU数据 | `sudo mpirun -np 4 hpt mpi --collect-level 1 -I 1 -o output -- $COMMAND` |
| **mpi** | 生成MPI性能分析报告 | `sudo hpt mpi --report -i mpi_<hostname>_<date>` |

> 以上示例均需 root 权限。各功能的详细参数说明见下方[子功能介绍](#子功能介绍)。

#### system 示例

- **采集系统配置**：执行以下命令采集当前平台的系统配置信息，生成二进制原始数据文件，txt 和 html 格式报告。

```bash
sudo hpt system
```

- **对比配置**：对两个已采集的配置进行对比并生成报告。

```bash
sudo hpt system -d null_mercury_20250509_151556,null_jupiter_20250509_152312
```

- **收集访存带宽/延迟、FLOPS、IPC 信息**：
  最好在系统Idle状态下进行测试，否则数据不具有参考性。

```bash
sudo hpt system -p
```

其评估如下指标：

  - 硬件预取关闭下的访存带宽
    - Read-only
    - Read:Write = 1:1
    - Read:Write = 2:1
    - Read:Write = 3:1
  - 硬件预取关闭下的访存延迟
    - idle latency：使用单core访问内存，适于衡量理想状态下的内存访问延迟，反映了L3缓存未命中后，直接访问主内存的基本延迟
  - 浮点运算性能FLOPS：
    - 单core的FLOPS
    - 所有物理core的FLOPS

也支持按需测试特定项，例如仅测试`mem-idle-lat`：

```
sudo hpt system -l
```

- **测试CPU频率（基准测试）**：在轻/重负载下采集CPU频率曲线，在目录benchmark\_report生成HTML报告。

```bash
sudo hpt system --freq 0    # 重负载（默认）：全核满载
sudo hpt system --freq 1    # 轻负载：1→N核递增
sudo hpt system --freq 2    # 双模式：轻+重负载双模式
```

### java

<span id="java"></span>

#### 功能概述

收集 Java 进程的 CPU、内存等资源使用率，获取类加载、热点代码编译等 JVM 内部信息，支持交互式诊断，助力 Java 应用性能调优。

### sched

<span id="sched"></span>

#### 功能概述

适用场景：**调度延迟排查**、**CPU 争抢分析**、**进程/线程调度优化**。

### lock

<span id="lock"></span>

#### 功能概述

采集用户态 mutex、rwlock、spinlock 和 POSIX semaphore 的生命周期事件，也可用 `-k` 分析内核竞争等待和全机 RCU grace period（GP）时延。用户态锁分析报告提供等待/持有、rwlock 读写交叠、spinlock、semaphore 和调度关联分析；内核态锁分析报告提供竞争场景的锁调用、等待时间和 RCU GP 时延。报告格式包括文本和HTML。
适用场景：**锁竞争定位**、**长时间持锁排查**、**线程等待与调度关联分析**、**并发程序性能优化**。

#### 使用约束

- 需要 root 权限。使用 `-k` 时，目标内核必须提供 `lock:contention_begin` 与  `lock:contention_end` tracepoint。
- 采集目标必须是 `-p <PID>` 或 `-- <command>` 之一；两者不能同时使用。
- 默认采样率为 128。采样、事件丢失、文件截断或调度数据缺失会降低报告完整性。
- semaphore 的 wait 区间表示调用时延，不能仅据此认定线程已在内核中阻塞；emaphore 不输出 mutex 式的持锁人关系。
- 使用 `-k` 时不能指定 `--sched-mode`；内核报告不提供 scheduler-to-lock 关联、持有者或持有时长。
- RCU GP 仅在 `-k` 时采集，范围是采集窗口内的全机普通 RCU GP，不归因到 `-p <PID>` 或 `-- <command>` 指定的目标进程。内核没有 `rcu:rcu_grace_period` tracepoint 或 RCU 数据不完整时，RCU 表会标记为不可用或降级，其他内核锁结果仍可使用。
- 内核竞争表按实际锁对象地址聚合 `contention_begin/end` 等待窗口。仅在未显式指定
  `--lock-type`，且四个 lockdep tracepoint 均可用时，报告才额外显示按 lockdep 地址聚合的生命周期表；两张表不关联地址。
- `-k -- <command>` 覆盖命令及其后代进程；`-k -p <PID>` 通过 perf 事件继承覆盖初始线程快照中的目标线程，以及事件安装后由这些线程创建的新线程、子进程及其后代；不包含 attach 前已存在的子进程。从准备开始到所有事件启用之间存在初始安装窗口，该窗口内不保证完整覆盖。
- 内核栈无法采集或解析时，报告仍保留竞争统计，并标记调用点归因不可用。原始数据截断、事件丢失、队列丢弃、解码错误或异常配对时，报告只展示已观察窗口，精确排名和 P90/P99 不可用。

#### 用户参数

| Option | Description |
|---|---|
| `-p, --pid <PID>` | attach已有进程；用户态 auto 模式选择 uprobe。 |
| `-- <command>` | 启动并分析命令；用户态 auto 模式优先选择 USDT，BPF 环境预检查失败时改用 preload。 |
| `-d, --duration <seconds>` | 采集时长；`-p <PID>` 场景默认 15 秒，`-- <command>` 场景未指定时等待目标退出, 显式指定 `-d` 后按该时长终止目标。 |
| `-u, --user` / `-k, --kernel` | 采集用户态/内核锁事件；未指定时默认仅用户态，两者可同时指定。 |
| `--user-mode <auto\|uprobe\|usdt\|preload>` | 选择用户态采集通道。默认 `auto`：PID attach 自动选择 `uprobe`，`-- <command>` 初始选择 `usdt`；命令模式的 BPF 环境预检查失败时改用 `preload`，后续仍须通过 preload 资源及配置检查。collector 的 `Prepare` 阶段失败会终止采集，不触发自动回退。<br><br>`uprobe` 仅用于 PID attach，`usdt`/`preload` 仅用于命令模式，`preload` 不可与 `--kernel` 同用。 |
| `--sched-mode <-1\|0\|1>` | `-1` 关闭调度采集；`0` 仅采集 `sched_switch`；`1` 采集 `sched_switch`、`sched_stat_sleep`、`sched_stat_wait` 和 `sched_stat_blocked`，默认 `0`。不能与 `-k` 同用。 |
| `--sample-rate <N>` | 用户态每 N 次锁操作采样 1 次，默认 128；纯 `-k` 固定全量采集。 |
| `--lock-type <LIST>` | 逗号分隔的 `mutex,rwlock,spin,sem`，默认全部。显式指定时会过滤类型未知或不匹配的内核事件，且不显示 lockdep 生命周期表。 |
| `--wait-threshold <ns>` / `--hold-threshold <ns>` | 过滤适用的通用等待/持有统计；内核竞争表与 lockdep 生命周期表不受这两个阈值筛选。 |
| `--rcu-gp-threshold-us <US>` | Slow RCU GP 阈值，默认 `10000`（10 ms）。只影响 RCU 表的 Slow GP 计数，不筛除 RCU 样本，也不影响锁等待或持有统计；值必须为正整数。 |
| `--max-buffer-size <MiB>` | 原始事件文件上限，默认 256 MiB。 |
| `--bpf-ring-buffer-size <MiB>` | 用户态 BPF/uProbe 事件 ring 容量，范围 1–64，默认 8 MiB；增大可降低突发事件丢失概率。 |
| `--db` | 将二进制锁/调度事件额外导入 `raw_data/lock_events.db`。 |
| `-v, --verbose` | 输出完整 rwlock waiter-holder overlap 明细及完整内核竞争调用栈。 |
| `-o, --output <dir>` | 指定结果会话目录的父路径。 |
| `--report -i <session_dir>` | 跳过采集，从已有会话的原始事件离线重建报告。 |

#### 输出说明

每次采集会创建 `lock_<hostname>_<YYYYMMDD_HHMMSS>/` 结果目录：

```
lock_<hostname>_<timestamp>/
├── raw_data/lock_events.bin       # 用户态锁事件（启用时）
├── raw_data/kernel_events.bin     # 内核锁事件（启用时）
├── raw_data/rcu_gp_events.bin     # RCU GP 边界事件（-k 且 RCU 采集可用时）
├── raw_data/kernel_stacks.bin     # 内核调用栈（成功导出时）
├── raw_data/kernel_lockdep_names.bin # lockdep 名称（D 地址表可用时）
├── raw_data/sched_events.bin      # 调度事件（可用时）
├── raw_data/session_metadata.json # 后端、采样、丢失与截断元数据
├── raw_data/lock_events.db        # 指定 --db 时生成
└── report/
    ├── lock_report.txt
    ├── lock_report.html
    └── timeline/                   # HTML 时间线：manifest.js 与 chunk_*.js
```

#### 报告内容简介

两种报告基于同一批原始事件生成；没有采集到的锁类型、调度事件或可解析调用点，对应表格会为空或不显示。

文本报告（`report/lock_report.txt`）适合在终端、CI 日志或工单中快速阅读，按以下顺序输出：

| 表/章节 | 主要字段和用途 |
|---|---|
| 采集概览与数据质量 | 实际用户态/内核后端、采样率、原始/接受事件数、drop、截断、调用点解析和调度覆盖状态；先判断后续统计是否完整。 |
| 锁竞争热点 | 锁类型、地址、事件数、等待/持有次数、总时长、平均值、P50/P90/P99/最大值及直方图；用于按影响排序锁实例。 |
| 线程等待/持有统计 | 每个 PID/TID 的等待或持有总量、分位数、最大值和被其它线程抢先获取的次数；用于定位受影响线程和长时间 holder。 |
| CPU 等待统计 | CPU 上观察到的等待次数、总时长、分位数、最大值和抢占次数；用于发现 CPU 维度的不均衡。 |
| 调用点热点 | 锁地址、锁类型、调用点符号/地址、等待次数、累计/平均/最大等待；用于回到业务代码。 |
| waiter-holder 关系 | waiter、holder、锁、等待窗口、时长、调用点及是否完整；仅呈现观测到的配对，不把缺失关系推断为事实。 |
| 锁类型专项 | mutex 公平性与阻塞关系；rwlock 读/写统计、R\<-W/W\<-R/W\<-W 交叠和 reader phase；spinlock spinner/holder 关系与公平性；semaphore 操作、许可等待和失败分类。 |
| 调度与锁关联 | holder/waiter 的 off-CPU、sleep/wait/blocked 窗口与锁等待的重叠、风险级别和证据明细；仅在 scheduler 数据可用时输出。 |
| RCU Grace-Period Latency | 全机普通 RCU GP 按 flavor 的完整 GP 数、总/平均/P50/P90/P99/最大时延、Slow GP、未配对边界和数据状态；用于识别采集期间的 RCU GP 长尾，不用于定位某个目标进程。 |

HTML 报告（`report/lock_report.html`）保留上述统计，并以可筛选的表格和时间线呈现：

| 页面区块 | 输出内容 |
|---|---|
| Overview | 会话、采集后端、数据质量、总体事件数、锁/线程数及等待/持有汇总。 |
| Contention Hotspots | 锁实例热点表；可按锁类型、地址、调用点、等待/持有指标筛选和排序。 |
| Thread Hold Statistics / Thread Wait Fairness / CPU Wait Fairness | 分别展示线程持有、线程等待公平性和 CPU 等待公平性的明细表。 |
| 锁类型专项区块 | mutex、rwlock、spinlock、semaphore 的专项统计和可展开的关系明细；只在相应事件存在时显示。 |
| 调度与锁关联分析 | 判定汇总表及 holder/waiter off-CPU、阻塞锁和内核 spin 数据质量等证据明细；只在可用 scheduler 数据支持时显示。 |
| RCU Grace-Period Latency | 与文本报告相同的全机 RCU GP 时延表；显示状态、阈值和按 flavor 汇总的时延指标。 |
| Lock Timeline | 以线程/锁/调度 lane 展示 wait、hold、semaphore 调用和 off-CPU 窗口；支持锁类型、线程、CPU 过滤，缩放、拖动、悬停和点击查看单条记录详情。明细从 `report/timeline/` 按需加载。 |

#### lock 示例

- 附着进程并采集 30 秒用户态锁竞争：

```bash
sudo hpt lock -p $PID -d 30
```

- 启动业务命令，采集用户态锁与调度关联：

```bash
sudo hpt lock --sched-mode 1 -- ./server --workers 8
```

- 针对 mutex/rwlock 做全量采样：

```bash
sudo hpt lock -p $PID --sample-rate 1 --lock-type mutex,rwlock
```

- 采集已有进程的内核竞争锁：

```bash
sudo hpt lock -k -p $PID
```

- 采集内核锁并统计时延达到 20 ms 的全机 RCU GP：

```bash
sudo hpt lock -k --rcu-gp-threshold-us 20000 -p $PID
```

- 从已有会话离线重建报告：

```bash
sudo hpt lock --report -i lock_<hostname>_<timestamp>
```

### roofline

<span id="roofline"></span>

#### 功能概述

通过 Roofline 模型可视化分析程序性能瓶颈，将浮点运算能力与 DRAM 带宽结合，以图形方式判断程序是计算密集还是访存密集。
适用场景：**HPC 应用性能优化**、**计算/访存瓶颈诊断**、**优化方向指导**。
支持 Fortran、C、C++、OpenMP 场景。

#### 使用约束

- 需要 root 权限。
- 需按顺序执行：survey 分析 → tripcounts 分析 → 绘制 roofline 图。

#### 输出说明

Roofline 图是一个以对数坐标系绘制的二维图，通常包括以下部分：

- X 轴：计算强度（Arithmetic Intensity）单位为 FLOP/Byte，表示每访问1字节DRAM数据，对应进行的浮点计算次数。
- Y 轴：性能（Performance）单位为 GFLOPs，表示程序的实际浮点运算速率。
- 斜线（带宽上限）：斜率为系统DRAM 带宽，。
- 水平线（计算能力上限）：表示系统的峰值计算能力（理论最大GFLOPs），是系统每秒钟所最多能完成的浮点运算数。
- 数据点：表示函数在实际运行时的性能表现。鼠标悬停在数据点上方可以看到函数的详细信息。详细信息如下：
    - DRAM Arithmetic Intensity: 平均DRAM计算强度。每访问1字节DRAM数据，对应进行的浮点计算次数。
    - Performance: 函数的实际浮点运算速率。
    - Function Time: 函数的实际执行时间。
    - Time Ratio: 函数占总执行时间的比例。
    - SSE Ratio: 函数中SSE指令占函数中所有指令的比例。
    - AVX2 Ratio: 函数中AVX2指令占函数中所有指令的比例。
    - AVX512 Ratio: 函数中AVX512指令占函数中所有指令的比例。

### mpi

<span id="mpi"></span>

#### 功能概述

通过 LD\_PRELOAD 注入 MPI 代理库（libhpt\_mpi.so），无侵入式采集各 rank 的 MPI API 调用统计及各节点的 CPU PMU 性能指标，生成多维度的文本和 HTML 报告。
适用场景：**MPI 应用性能剖析**、**通信瓶颈定位**、**多节点负载均衡分析**。
支持 OpenMPI、Intel MPI 等主流 MPI 实现。

#### 使用约束

- 需通过 `mpirun`/`mpiexec` 启动，不支持直接运行。
- 依赖 `libhpt_mpi.so` 代理库，默认搜索路径为 `/opt/hygon/hpt/mpi_libs/libhpt_mpi.so`，也可通过环境变量 `HPT_MPI_AGENT_LIB` 指定。
- 需要root权限。

``````

|       +---Microcode: 由Microcode生成的uops数量的占比。（这里比较特殊，Microcode/Non-Microcode，FP/Non-FP是对retire bound第二级的两种不同看法，并不是划分）
|       +---Non-Microcode: 正常的uops数量的占比。
|       |       +---Conditional Branch: 条件跳转指令数量的占比。

|       |       +---x87: 部分x87指令集的uops数量的占比。
|       |       +---SSE/AVX: 部分SSE/AVX指令集的uops数量的占比。
|       |       |        +---Packed: 常用的SSE非标量uops数量的占比。
|       |       |        +---Scalar: 常用的SSE标量uops数量的占比。
|       |       +---other: 其他指令集的数量的占比。
``````

    - processor：DF频率、cpu scalling/idle governors。
    - 网络：包含了中断聚合设置、offload（网络卸载）功能配置、网卡队列数量。
    - operating sytem：支持检测是否包含 hygon patch（海光补丁），以及获取大页、虚拟内存参数、透明页、debug tracer（调试跟踪器）、KSM（内核同页合并）、硬件预取、Hz/nohz（系统时钟频率相关）、JDK 版本等配置信息。
    - storage：磁盘调度策略、磁盘类型、文件系统类型、挂载参数等。
    - config：sysctl（内核配置参数）、kernel config（内核 config）、lsmod（已加载模块）。
    - 系统拓扑结构展示：能够显示系统硬件拓扑结构，包括 CPU 核心分布、内存节点信息、NUMA 拓扑结构以及 I/O 设备（如 PCI 设备和网卡）等详细信息。
    - ptest：通过测试对内存带宽 / 延时、FLOP（每秒浮点运算次数）、IPC（每周期指令数）进行评估分析，为性能优化提供数据支持
- 新增了3个一键收集脚本，其中get\_all\_configs.sh用于收集系统的详细配置信息，get\_all\_collect\_data.sh用于收集常用的PMU指标，get\_all\_software\_data.sh用于收集常用的软件性能数据

## hygon\_tuner\_v2.0.0 (2024-06)
