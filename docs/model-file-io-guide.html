模型提供方文件读写约定

搬进 TEE 内部执行的训练与推理代码，应该从哪里读文件、往哪里写文件，以及写的时候要遵守什么格式。 按本手册改造后的代码不调用任何网络接口，也不需要引入专有依赖，在普通环境下同样能跑。

输入只读 产物集中在一处 原子写入 日志与进度是旁路

01目录布局

TEE 内固定提供以下目录，训练代码只与它们打交道。

TEE 文件系统角色
/opt/taa/input/只读

输入目录下的内容按模型所需的数据而定，此处不列举。

/opt/taa/output/可写
  ├── result/交付 · 唯一会被导出
  │    ├── weights/
  │    ├── training_result.json
  │    └── test_result.xlsx
  ├── log/旁路 · 不导出
  └── progress/旁路 · 不导出
/opt/taa/models/你的源码 · 进程工作目录

三条硬性规则：

  1. 输入目录只读。不得在 /opt/taa/input 下创建、修改或删除任何文件，包括缓存与临时文件。
  2. 产物集中在 result/。log/ 与 progress/ 只是旁路通道；需要交付的文件一律放 result/。
  3. 不要写相对路径。进程的工作目录是你的源码目录，相对路径会落到代码目录而不是产物目录。

02写日志

位置：$TAA_LOG_DIR（默认 /opt/taa/output/log/）。目录下所有 *.jsonl 与 *.log 文件都会被读取。

格式：每行一个 JSON 对象，追加写入。

{"timestamp": "2026-10-12T07:15:32Z", "message": "[Train] Epoch 3/150 finished - loss: 0.3821"}
  • 消息字段取 message，也接受 msg；时间字段取 timestamp，也接受 time、ts。
  • 时间戳可选；写了会显示为日志前缀。
  • 也接受不含 JSON 的纯文本行；未识别的字段会被忽略，可以按需增加。

必须遵守：

  • 01每行以换行符结尾。没有换行的尾部（包括正在写入的半行）不会被读取，直到换行符落盘为止。
  • 02只追加，不覆盖、不回退。文件如果变小（被截断重写），会被当作新文件从头读取，导致日志重复。
  • 03及时 flush，否则滞留在进程缓冲区的日志看不到。

参考实现

import json
from datetime import datetime, timezone

class ModelLogger:
    def __init__(self, log_dir, filename="train.log"):
        self.path = Path(log_dir) / filename
        self.path.parent.mkdir(parents=True, exist_ok=True)
        self._file = open(self.path, "a", encoding="utf-8")

    def log(self, message: str) -> None:
        ts = datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
        self._file.write(json.dumps({"timestamp": ts, "message": str(message)},
                                    ensure_ascii=False) + "\n")
        self._file.flush()          # 不 flush，日志会滞留在缓冲区
        print(message)              # 同时输出到控制台，便于本地调试

    def close(self) -> None:
        if self._file and not self._file.closed:
            self._file.flush()
            self._file.close()

每次任务开始前 log/ 目录会被清空。不要依赖上一次运行留下的文件，每次运行重新创建。

03写进度

位置：$TAA_PROGRESS_DIR，默认 /opt/taa/output/progress/progress.json。注意默认值是一个文件路径，不是目录。

{
  "percent": 34.6525,
  "timestamp": "2026-10-12T07:15:32.123456Z",
  "stage": "train",
  "message": "Epoch 3/150 (Midpoint) [Batch 20/40, 50.0%] - loss: 0.3821, acc: 85.00%",
  "epoch": 3, "total_epochs": 150,
  "batch": 20, "total_batches": 40,
  "loss": 0.3821, "acc": 85.0
}
字段必填说明
percent是0.0 – 100.0，也接受 percentage。越界或非数字会被忽略，进度将停在原处
timestamp否RFC3339 / RFC3339Nano UTC，建议带微秒。缺失或格式非法时使用文件修改时间
stage · message
epoch · total_epochs
batch · total_batches
loss · acc		否用于平台展示；其余自定义字段同样不会报错

必须遵守：

  • 01原子写入。先写同目录下的临时文件，fsync，再 os.replace 覆盖。直接覆盖写会让读取方读到半截 JSON。
  • 02只在有变化时写。只有 (percent, timestamp) 这一对与上次不同时才会被采用，重复写同样的值没有意义。
  • 03建议节流。每个 batch 都落盘会拖慢训练；典型策略是距上次写入超过 0.2 秒、或进度变化超过 0.0001% 才写，关键里程碑强制写一次。
  • 04建议单调不回退。进度回退会让进度条来回跳。

参考实现

import json, os, time
from datetime import datetime, timezone

class ProgressTracker:
    def __init__(self, progress_path, min_interval_seconds=0.2, min_percent_delta=0.0001):
        self.path = Path(progress_path)
        self.tmp_path = self.path.with_suffix(self.path.suffix + ".tmp")
        self.path.parent.mkdir(parents=True, exist_ok=True)
        self.min_interval_seconds = min_interval_seconds
        self.min_percent_delta = min_percent_delta
        self._last_percent = -1.0
        self._last_write_time = 0.0

    def update(self, percent, stage=None, message=None, force=False, **extra) -> bool:
        percent = max(0.0, min(100.0, round(float(percent), 4)))
        if self._last_percent >= 0.0:
            percent = max(percent, self._last_percent)          # 单调不回退
        if not force and self._last_percent >= 0.0:
            elapsed = time.time() - self._last_write_time
            if elapsed < self.min_interval_seconds and abs(percent - self._last_percent) < self.min_percent_delta:
                return False

        payload = {
            "percent": percent,
            "timestamp": datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%S.%fZ"),
        }
        if stage:   payload["stage"] = stage
        if message: payload["message"] = message
        payload.update({k: v for k, v in extra.items() if v is not None})

        with open(self.tmp_path, "w", encoding="utf-8") as f:
            f.write(json.dumps(payload, ensure_ascii=False, indent=2) + "\n")
            f.flush()
            os.fsync(f.fileno())
        os.replace(self.tmp_path, self.path)                    # 原子替换

        self._last_percent = percent
        self._last_write_time = time.time()
        return True

建议的进度预算

可按任务调整，原则是初始化与收尾都要覆盖，长循环中间要有细粒度变化。

区间内容
0% – 2%参数解析、模型构建、损失与优化器、DataLoader 就绪
2% – 96%按 epoch 均分；epoch 内按 batch 平滑插值；每 epoch 开始、25%、50%、75%、收尾各强制写一次
96% – 100%指标汇总、写 training_result.json、完成

每次任务开始前进度文件会被删除。若进度长时间不动，平台侧看到的进度条也会停住。

04写结果汇总

位置：产物目录根部，即 <output>/training_result.json。

进程以退出码 0 结束后，该文件会被读取并与审计信息、数据校验和合并成最终报告。只有 result/ 里的产物会被导出；进程非 0 退出时产物不会被收集。

{
  "training_task": {
    "metrics": {
      "final_accuracy": 0.9425,
      "final_loss": 0.1352,
      "final_auc": 0.9810,
      "final_f1": 0.9380,
      "epochs": [
        {"epoch": 1, "accuracy": 0.6500, "loss": 0.8500},
        {"epoch": 2, "accuracy": 0.8100, "loss": 0.4200},
        {"epoch": 3, "accuracy": 0.9425, "loss": 0.1352}
      ]
    }
  },
  "dataset": {
    "total_samples": 12500,
    "splits": {"train": 10000, "test": 2500}
  }
}
  • training_task.metrics 与 dataset 是实际被采集的两块内容，指标键名自定。
  • 无需填写 task_id、started_at、finished_at、duration_seconds、status、exit_code、failure_reason：这些由运行侧统一填写，你写了也会被覆盖。
  • dataset 中不要使用 data_structure 字段。
  • 文件缺失不会导致任务失败，但报告里就没有你的指标。无论成功失败都应尽量写出该文件。
result_path = OUTPUT_DIR / "training_result.json"
with open(result_path, "w", encoding="utf-8") as f:
    json.dump(training_result, f, indent=2, ensure_ascii=False)
    f.write("\n")

阶段 2（测试）另需在 result/ 下产出评测明细表，按约定命名 test_result.xlsx；文件名与列结构由模型方与平台约定。

05禁止事项

行为后果
在 /opt/taa/input 下创建、修改、删除文件违反 TEE 内只读约束
把输入数据原样拷进 result/（原始图片、CSV、标注文件）导出前的反泄露检查会比对数据特征，命中即拒绝导出
在产物中写入明文 PEM 私钥、SECRET_KEY= / API_KEY= 等环境变量转储同上，命中明文特征即拒绝导出
任何网络外联（socket / requests / urllib / httpx / aiohttp）代码审计红线，导入阶段即被阻断
反弹 Shell、提权、危险系统调用同上
单次产物超过大小上限（默认 3 GB）导出被拒绝

06上线前检查清单

  • 输入目录只读，代码中没有任何指向 /opt/taa/input 的写操作
  • 所有需要交付的文件都写在产物目录（<output> / TAA_OUTPUT_DIR）下，没有散落在别处
  • 路径从环境变量或宏获取，没有硬编码相对路径
  • 日志写在 $TAA_LOG_DIR，每行以换行符结尾，只追加不重写
  • 进度原子写入 $TAA_PROGRESS_DIR，percent 在 0–100 之间且单调不回退
  • 结束前写出 <output>/training_result.json，含 training_task.metrics 与 dataset
  • 失败路径同样写出 training_result.json，或至少保证日志与进度可用
  • 产物中没有原始数据副本、密钥、环境变量转储
  • 代码中不存在任何网络调用
本手册只覆盖文件读写约定。审计红线、阶段划分与导出口径见《模型提供方开发与接口对接规范》（docs/model-provider-integration-guide.md）。
