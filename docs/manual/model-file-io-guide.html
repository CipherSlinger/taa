1概述

1.1编写目的

本手册面向接入 TAA 机密计算平台的模型提供方，说明模型代码在 TEE（可信执行环境）内应如何读取输入、写出日志、上报训练进度并生成结果汇总文件。按本手册改造后的代码不调用任何网络接口，也不需要引入专有依赖，在普通环境下同样可以运行。

1.2适用范围

本手册适用于在 TAA 内执行的训练任务；推理任务沿用同一套目录与文件约定。手册只覆盖文件读写约定；代码审计红线、任务阶段划分与产物导出口径不在本手册范围内。

1.3读者对象

负责模型训练或推理代码开发、需要将代码接入 TAA 的工程人员。读者应熟悉 Linux 文件操作与 JSON 格式，并具备一定编程能力。

1.4术语与缩略语

表 1-1 术语说明

术语说明
TAATrusted Application Agent，可信应用代理；模型训练与推理的机密计算平台，模型代码在其中的 TEE 内执行

2运行环境与目录布局

2.1TEE 内目录结构

TEE 内固定提供以下目录，模型代码只与它们打交道。输入目录的内容按模型实际需要而定，由平台在任务开始时准备。

表 2-1 目录结构

路径角色
/opt/taa/input/只读
/opt/taa/output/可写
    ├── result/交付 · 唯一会被导出
    │   ├── weights/模型权重（示例）
    │   ├── training_result.json结果汇总文件，见第 6 章
    │   ├── test_result.xlsx测试结果（示例）
    │   └── …按实际交付内容增删
    ├── log/旁路 · 不导出 · 平台据此展示训练过程
    │   └── train.jsonl每行一条 JSON 日志，可拆成多个文件
    └── progress/旁路 · 不导出 · 平台据此显示进度条
        └── progress.json文件名固定，进度写在其中
/opt/taa/models/你的源码 · 进程工作目录

2.2目录职责与生命周期

表 2-2 目录职责与生命周期

目录用途是否导出生命周期
/opt/taa/input/模型只读的输入数据否任务开始时由 TAA 将所需数据集拷贝到该目录
/opt/taa/output/result/交付产物是（唯一）任务开始时创建；进程正常结束后移出并落盘
/opt/taa/output/log/运行日志否任务结束后清空；执行期间逐行追加，可拆成多个 *.jsonl / *.log
/opt/taa/output/progress/进度文件所在目录否任务结束后清空；执行期间反复覆盖写入 progress.json
/opt/taa/models/模型源码，进程工作目录否任务开始时提供

2.3基本约定

接入前请先确认以下三条约定，它们贯穿全文：

  1. 输入目录只读。不得在 /opt/taa/input 下创建、修改或删除任何文件，包括缓存与临时文件。
  2. 产物集中在 result/。log/ 与 progress/ 只是旁路通道；需要交付的文件一律放 result/。
  3. 不要写相对路径。进程的工作目录是源码目录，相对路径会落到代码目录而不是产物目录。

3接入流程

3.1接入步骤总览

把一份已有代码接入 TAA，通常按以下五步完成：

表 3-1 接入步骤

步骤内容参见
1确认输入与输出目录2.1、2.2
2参数化目录配置3.3
3实现日志与进度输出第 4 章、第 5 章
4写出结果汇总文件第 6 章
5本地自检并上传3.5、第 9 章

3.2步骤一：确认输入与输出目录

先确认代码读取什么、产出什么。所有读取只应发生在 /opt/taa/input 下；所有需要交付的文件只应写到 /opt/taa/output/result 下。

3.3步骤二：参数化目录配置

建议把三个目录写成模块级常量，并允许用环境变量覆盖，这样同一份代码在本地调试与 TEE 内运行可以使用不同路径：

3.4步骤三：实现三类输出

日志、进度与结果汇总文件的作用不同，实现方式也不同：日志用于展示运行过程，按行追加；进度用于驱动平台上的进度条，需要原子写入且单调不回退；结果汇总文件在任务结束时写出，被合并进最终报告。三类输出的格式分别见第 4、5、6 章。

3.5步骤四：本地自检并上传

改造完成后，先在普通环境用临时目录完整跑一遍，确认三个文件都按预期生成、内容可以正常解析；随后按第 9 章的检查清单逐项确认，再提交上传。

4写日志

4.1文件位置与命名

日志写在 /opt/taa/output/log/ 下。文件名不限，后缀为 *.jsonl 或 *.log 就会被读取（后缀不区分大小写），可以按阶段拆成多个文件。子目录不会被扫描，日志请直接放在该目录下。多个文件按文件名排序后读取，平台上的展示先后顺序与文件名一致。

4.2格式与字段

每行一个 JSON 对象，追加写入：

json
{"timestamp": "2026-10-12T07:15:32Z", "message": "loss 0.3821"}

表 4-1 日志字段

字段必填说明
message是日志正文，也接受 msg
timestamp否RFC3339 时间戳，也接受 time、ts；写入后显示为日志前缀

未识别的字段会被忽略，可以按需增加。也接受不含 JSON 的纯文本行。

4.3编写要求

  1. 每行以换行符结尾。没有换行的尾部（包括正在写入的半行）不会被读取，直到换行符落盘为止。
  2. 只追加，不覆盖、不回退。文件如果变小（被截断重写），会被当作新文件从头读取，导致日志重复。

5上报训练进度

5.1文件位置

进度写在 /opt/taa/output/progress/progress.json。注意这是一个文件路径，不是目录，文件名固定为 progress.json。

5.2格式与字段

json
{
  "percent": 34.6525,
  "timestamp": "2026-10-12T07:15:32.123456Z"
}

表 5-1 进度字段

字段必填说明
percent是0.0 – 100.0，也接受 percentage。越界、非数字或整个文件不是 JSON 对象都会被忽略，进度停在原处
timestamp否RFC3339 / RFC3339Nano UTC，建议带微秒。缺失或格式非法时使用文件修改时间

整个文件只会被读取这两个字段，其余字段一律忽略：写了不报错，但不会展示、也不会被使用。进度之外的信息请写进日志。

5.3写入要求

进度文件会被频繁读取，必须保证任何时刻读到的都是完整内容：

  1. 原子写入。先写临时文件，fsync 后再 os.replace 覆盖目标文件。
  2. 单调不回退。新值不得小于已写入的值，避免进度条跳回。
  3. 限频写入。建议最小间隔 0.2 秒，且百分比变化小于 0.0001 时跳过。

5.4参考实现

5.5进度预算建议

可按任务调整，原则是初始化与收尾都要覆盖，长循环中间要有细粒度变化。

表 5-2 建议的进度预算

区间内容
0% – 2%参数解析、模型构建、损失与优化器、DataLoader 就绪
2% – 96%按 epoch 均分；epoch 内按 batch 平滑插值；每 epoch 开始、25%、50%、75%、收尾各强制写一次
96% – 100%数据集统计、写 training_result.json、完成
注意

任务结束后进度文件会被清空。若进度长时间不动，平台侧看到的进度条也会停住。

6生成结果汇总文件

6.1文件位置与生效条件

结果汇总文件位于产物目录根部，即 /opt/taa/output/result/training_result.json。进程以退出码 0 结束后，该文件会被读取，并与审计信息、数据校验和合并成最终报告。只有 result/ 里的产物会被导出；进程非 0 退出时产物不会被收集。

6.2文件格式

json
{
  "dataset": {
    "total_samples": 12500,
    "splits": {"train": 10000, "test": 2500}
  }
}

6.5失败路径

文件缺失不会导致任务失败，但报告里会缺少数据集规模等信息，事后核对样本量、划分比例只能翻日志，平台也难以按统一口径统计。该文件被采集的内容只有 dataset。

字段缺失时报告只是留空，不会报错，因此容易到验收阶段才发现漏写。建议在 finally 中写出该文件，使异常退出时也能留下可用的信息；进程非 0 退出时 result/ 不会被导出，此时以日志与进度为准。

7禁止事项

以下行为会导致导出被拒绝或审计结论不通过，接入前请逐项核对：

表 7-1 禁止事项与后果

行为后果
在 /opt/taa/input 下创建、修改、删除文件违反 TEE 内只读约束
把输入数据原样拷进 result/（原始图片、CSV、标注文件）导出前的反泄露检查会比对数据特征，命中即拒绝导出
在产物中写入明文 PEM 私钥、SECRET_KEY= / API_KEY= 等环境变量转储同上，命中明文特征即拒绝导出
任何网络外联（socket / requests / urllib / httpx / aiohttp）代码审计红线，审计结论将判为未通过并上报平台（结论仅供参考，由平台侧处置）
反弹 Shell、提权、危险系统调用同上

8常见问题

8.1代码在普通环境调试时也要写这些文件吗？

建议保持一致。用 3.3 节的环境变量把目录指向本地临时目录即可，读写方式与 TEE 内完全相同，便于提前发现格式问题。

8.2日志可以直接打印到标准输出吗？

可以用于本地调试，但平台只读取 log/ 目录下的文件。正式运行必须把日志落到文件，同时打印到控制台不影响使用。

8.3一次运行写了多个日志文件会怎样？

目录下所有 *.jsonl 与 *.log 都会被读取，可以按阶段拆分文件。但不要重写或截断已经写过的内容，否则会被当作新文件重新读取。

8.4进度长时间不动会怎样？

平台显示的进度会停在最后一次成功读取的值。进度文件被删除、内容非法或 percent 越界时，同样停留在原处。

8.5训练中途失败，还要写 training_result.json 吗？

应在退出前尽量写出。进程非 0 退出时 result/ 不会被导出，但保留该文件便于排查；失败信息同时写进日志与进度，平台侧才能看到。

8.6可以把中间 checkpoint 写在 result/ 下吗？

可以，但 result/ 下的文件都会被导出，体积越大导出耗时越长。只放需要交付的文件，中间产物写到别处或不保留。

9上传前检查清单

上传前，请逐项确认以下内容：

  • 输入目录只读，代码中没有任何指向 /opt/taa/input 的写操作
  • 所有需要交付导出的文件都写在 /opt/taa/output/result/ 下，没有散落在别处
  • 路径按绝对路径书写，没有写成相对路径
  • 日志写在 /opt/taa/output/log/，每行以换行符结尾，只追加不重写
  • 进度原子写入 /opt/taa/output/progress/progress.json，percent 在 0–100 之间且单调不回退
  • 结束前写出 /opt/taa/output/result/training_result.json，含 dataset
  • 失败路径同样写出 training_result.json，或至少保证日志与进度可用
  • 产物中没有原始数据副本、密钥、环境变量转储
  • 代码中不存在任何网络调用
