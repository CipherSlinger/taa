Engineering Roadmap2026-10-30

TAA 工程优化路线图

在不改变生产行为的前提下，梳理项目组织与实现，分四批完成可验证、可回滚的工程优化。

硬约束（已确认）

严格行为不变。配置结构、HTTP 接口与返回体、日志语义、审计判定、结果报告字段、initrd/镜像内容、部署 CLI 行为均保持现状。

第 06 节的四个新增需求不属于这条约束：它们会改变运行时行为，需独立 spec 与验收，不与前四批混合提交。

每批在独立 worktree 中完成，避免与并发会话共享检出；不要并行运行测试。每批独立提交，验收不过即整批回退。

0.1 构建与测试基线

  • CGO_ENABLED=0 GOOS=linux go build -o bin/taa ./cmd/taa 通过。
  • go vet ./internal/... 通过；go test ./internal/... ./pkg/... ./tools/... -run '^$' 可编译。
文档命令 go test ./... 在当前工作区不可用。本地未跟踪的 models/audit/holdout-sources/semgrep-rules-develop 位于主模块内，包含大量不可编译的审计语料 .go 文件，go list ./... / go test ./... 直接报错退出（实测 10 类错误，exit 1）。干净检出中该目录不存在，因此这是本地语料污染，不是 CI 问题，但会误导日常验证。
  • 全量测试较慢，且部分用例真实调用 semgrep/python3；本次未在隔离环境中跑完基线（共享检出中有另一会话在并行跑测试），批次一必须补做并记录。

01 — 策略

总体策略

1.1 “行为不变”的定义

以下任一项发生变化即视为行为改变，批次验收直接失败：

  • HTTP 请求字段、响应 JSON、状态码、CORS/响应头；
  • 日志级别与日志正文（允许新增仅测试/基准使用的输出）；
  • 配置键、默认值、别名、校验错误文案；
  • 审计 finding、风险分级、通过/拒绝结论、报告字段（ReportID / AuditTime / ScanDurationMs 等易变字段除外）；
  • 部署脚本的帮助文本、非 TTY 输出、预检行为、生成的文件/容器；
  • initrd 内容与镜像内容（本路线图不重建二者）。

1.2 每批通用门禁

1CGO_ENABLED=0 GOOS=linux go build -o bin/taa ./cmd/taa
2go vet ./internal/... ./pkg/... ./tools/...
3go test ./internal/... ./pkg/... ./tools/... -count=1
4gofmt -l internal pkg cmd tools
5bash -n deploy.sh deploy-llm.sh deploy-fhe.sh deploy-taa-vm.sh deploy/taa-supervisor.sh deploy/guest-build/*.sh
6configs/*  ·  api/openapi.yaml  ·  api/proto/**   哈希与批次开始前一致

1.3 批次顺序与依赖

批次内容风险依赖
一工程卫生与可信基线 最低无
二代码结构与可维护性 中批次一的可信构建/测试命令
三部署与构建工程 中批次一；与批次二独立，可交换顺序
四审计/推理链路 最高批次一、二；必须先测量后改动
五运行时可靠性、兼容性与鉴权（新增需求，行为变更） 最高独立立项；每项单独 spec，不并入前四批

05 — 批次四

审计 / 推理链路

最高风险 0 / 5

依赖：批次一、二；必须先测量后改动

目标：先建立可复现的性能与内存基线，再只做不改变判定结果的优化。本批不以“更快”为唯一成功标准；没有安全收益时，交付基准与证据即可关闭。

    • 调整 bufio.Scanner 缓冲区，避免超长行截断；调整前后必须验证相同文件输出一致。
    • 消除 CPG/二进制通道中的重复遍历或重复解析。
    • 所有改动必须满足：固定输入下 audit_report.json 除易变字段外逐字节一致；通过/拒绝结论、finding 列表、风险分级完全一致。
    • 记录已知非确定性（同输入不同判定）及其证据，不把“temperature 0 已配置”误当作“已修复”。
    • 核对超时/熔断/降级路径的实际生效点，标注无效或未读取的配置项，但本批不修改这些配置语义。
    • 在 README 或 .claude/specs/ 记录审计链路的测量方法与基线数字。

验收

  • 基准可重复运行，数字稳定（至少 3 次取中位数）。
  • 固定输入的审计报告与基线逐字节一致（排除易变字段）。

06 — 新增需求

可靠性、兼容性与访问控制

行为变更 0 / 4

依赖：独立立项；不受“行为不变”约束，每项需单独 spec 与验收

目标：解决三个已在真实环境暴露的问题——链路存活靠超时判断、macOS 打包导致 semgrep 扫描不通过、训练/推理失败拿不到具体原因，并补上 TAA 接口鉴权这一基础能力。四项都会改变现有行为，不得混入前四批的等价重构提交。

任务

    • 现状：链路存活靠固定超时（请求 read deadline、探针时限）判断；实测 CPU 争用会让 llama-server 慢 36 倍，超时无法区分“很慢”和“已死”，单纯加大超时只会拖住主流程。
    • 目标：用“有进展”作为存活证据——以流式分块/心跳的到达间隔判定，把总时长 deadline 换成 idle deadline（多久没有任何进展才判失败），慢但持续输出的请求不被打断。
    • 核对 /healthz 语义：它会做真实推理探针，冷加载本身就要 120s；需要区分“模型未驻留”“进程存活但无响应”“进程已退出”三种状态，而不是都归为超时。
    • 失败要么有明确证据（连接断开、进程退出、心跳停止），要么显式标注“无法判定”，不得靠调大超时掩盖。
    • 先测量再改：记录当前超时在实际负载下的命中率与误判率；不改审计判定结论与提示词。
    • 问题：macOS 压缩包会带 __MACOSX/、._* AppleDouble 与 .DS_Store，解包后混进文件树，semgrep 扫到这些元数据会报错/非零退出，审计因此不通过。
    • 在解包阶段统一过滤这些条目（不落盘），并处理“压缩包内再套一层同名目录”的常见结构，按包内真实源码根计算扫描路径，而不是外层目录名。
    • 不改文件内容与相对路径，不影响 Linux/Windows 包；顶层目录归一化必须证明等价（同一逻辑包解出的源码集合一致）。
    • 把 macOS 实际产出的 zip 作为回归夹具，断言 semgrep 的目标集合不含任何元数据文件；同时保留现有压缩包用例。
    • 对损坏包是清洗还是拒绝，由 spec 决定，默认清洗并在日志中记录被剔除的条目。
    • 现状：进程非 0 退出时宿主侧只看到退出码，具体原因留在 guest 内的 stdout/stderr，排障只能靠猜。
    • 采集：退出码与信号、失败阶段（下载 / 解包 / 审计 / 训练 / 推理 / 上报）、stdout/stderr 尾部（有界，例如各 64 KiB）、可用的 /opt/taa/output/log 路径。
    • 回传：新增结构化失败原因字段写进任务状态与报告，已有字段保持不变；文案里不得出现宿主路径、密钥或环境变量转储，需先脱敏。
    • 区分用户代码失败与平台失败（OOM、超时、沙箱重建、模型未驻留），对前者给出可直接修正的原因（异常类型、缺失文件、字段错误）。
    • 失败写盘尽力而为，不改变原始退出码与成功路径的响应；新增字段需在 API 文档中标注为可选。
    • 现状：TAA 的 HTTP 接口只靠网络隔离，任何能连到端口的一方都能触发导入、训练、审计与产物导出，调用方身份不可验证。
    • 目标：为控制面接口增加可验证的调用方身份。候选方案：mTLS（平台侧客户端证书）、请求签名（HMAC + 时间戳 + nonce 防重放）、平台签发的短期 bearer token；具体选型由 spec 决定。
    • 密钥与证书不得写进镜像或仓库：通过 Kubernetes Secret 或 CoCo initdata 注入，读取后不出现在日志、错误信息与报告中。
    • 鉴权失败统一返回 401/403，文案不泄露内部路径与实现细节；/healthz 保持免鉴权，但只返回存活状态，不返回任务与配置信息。
    • 至少区分“平台控制面”与“模型提供方上传”两类调用方；是否按任务或租户细分权限由 spec 决定。
    • 迁移路径：先观察模式（只记录不拒绝）→ 灰度强制 → 默认强制，旧客户端有明确窗口；tools/platform-mock 与现有测试同步适配。

验收

  • 每项都有独立 spec；实施前记录现状证据（超时误判率、mac zip 的失败复现、失败原因缺失的样例）。
  • 6.1 用固定负载证明：慢而持续的请求不被误杀，真正失联的请求能被及时判定。
  • 6.2 用 macOS 实测产物跑通导入 → 审计，扫描目标集合干净且源码集合与手工解包一致。
  • 6.3 构造典型失败（缺文件、字段非法、OOM、非 0 退出），报告与日志都能给出具体原因且无敏感信息。
  • 6.4 未携带凭证、凭证错误、凭证过期、重放请求分别被拒绝；合法调用与现有流程一致；观察模式下旧客户端不受影响。
  • 成功路径的响应体、日志正文与现有测试保持通过。

风险与回滚

  • 四项都改变运行时行为，风险最高；不得与批次一至四的提交混在一起。
  • 6.1 触碰超时与探针语义，可能影响审计可用性，必须先测量；6.2 改变导入接受的包形态，需保留旧用例；6.3 新增对外字段，需评估接口兼容性；6.4 改变调用方接入方式，需保留观察模式与回退开关。
  • 每项单独提交、单独回滚；回滚后仍应保留测量数据与夹具。
